## Specification
Dans `ppu/mod.rs` (garde les `pub mod` existants; n'ecris pas encore le rendu):
```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug, Default)] pub struct DotEvents(pub u8);
impl DotEvents { pub const LINE_START: u8 = 1; pub const HBLANK_START: u8 = 2; pub const HBLANK_END: u8 = 4;
                 pub const VBLANK_START: u8 = 8; pub const VBLANK_END: u8 = 16;
                 pub fn has(self, m: u8) -> bool { self.0 & m != 0 } }
pub struct Ppu { region: Region, v: u16, dot: u16, field: bool, interlace: bool, overscan: bool, forced_blank: bool }
impl Ppu {
    pub fn new(region: Region) -> Ppu;     // v=0, dot=0, field=false, interlace=false, overscan=false, forced_blank=true
    pub fn reset(&mut self);               // meme etat que new (region conservee)
    pub fn v(&self) -> u16;  pub fn dot(&self) -> u16;  pub fn field(&self) -> bool;
    pub fn line_dots(&self) -> u16;        // dot::line_dots(type de la ligne courante)
    pub fn dot_clocks(&self) -> u32;       // duree du dot COURANT (avant step_dot)
    pub fn last_line(&self) -> u16;        // (Pal 311 / Ntsc 261) + (1 si interlace && !field)
    pub fn vblank_start(&self) -> u16;     // 240 si overscan sinon 225
    pub fn in_vblank(&self) -> bool;       // v >= vblank_start()
    pub fn in_hblank(&self) -> bool;       // dot >= 274 || dot < 1
    pub fn step_dot(&mut self) -> DotEvents;
}
```
`step_dot` (evenements calcules sur la position COURANTE, avant d'avancer):
1. `dot == 0`: si `v == 0` -> VBLANK_END ; si `v == vblank_start()` -> VBLANK_START ; toujours LINE_START.
2. `dot == 274` -> HBLANK_START ; `dot == 1` -> HBLANK_END.
3. Avancer: `dot += 1` ; si `dot == line_dots()` (calcule AVANT d'incrementer, avec la ligne courante): `dot = 0; v += 1;` et si `v > last_line()` : `v = 0; field = !field`.
Ordre important: `last_line()` est evalue avec le `field` de la frame qui se termine.

### 5.2 Frame
```
last_line = (if PAL {311} else {261}) + (if interlace && !field {1} else {0})   // UNKNOWN - to confirm quel field
```
A la fin de la derniere ligne: `v = 0`, **`field ^= 1` a chaque frame, interlace ou non** (le vrai materiel bascule toujours; STAT78 bit7 expose cette valeur).
`vis_last = if overscan {239} else {224}`. Lignes visibles: `v in 1..=vis_last`; ligne de sortie `r = v - 1`. V=0 est cachee (noire).

### 5.3 Evenements par (v, dot), dans CET ordre dans `step_dot`
1. `dot == 0`:
   - `v == 0`: debut de frame: `time_over = range_over = false`; evenement VBLANK_END.
   - `1 <= v <= vis_last`: **evaluation des sprites** pour la ligne (05b section 6) -> remplit `line_obj[256]`.
   - `v == vblank_start`: evenement VBLANK_START; rechargement OAM (2.1) si `!forced_blank`.
   - evenement LINE_START (toujours).
2. `dot == 274`: evenement HBLANK_START. `dot == 1`: HBLANK_END. (bornes `UNKNOWN - to confirm`, spec 02 3.1: 1096 clocks / 4.)
3. Si `1 <= v <= vis_last` et `22 <= dot <= 277`: `x = dot - 22`; **composer le pixel x** (05b section 11) et l'ecrire dans le framebuffer (section 6).
4. Avancer `dot += 1`; si `dot == line_dots(v)`: `dot = 0; v += 1; si v > last_line {v = 0; field ^= 1; FRAME_START}`.

`step_dot` retourne un petit ensemble de drapeaux (`DotEvents`: LINE_START, HBLANK_START, HBLANK_END, VBLANK_START, VBLANK_END) et `scheduler` gere NMI/IRQ/HDMA/auto-joypad a partir de la position (spec 02/03). Le PPU ne connait ni DMA ni NMI.

## Tests
Tous les tests sont prefixes par `e03_08_`.

- `e03_08_power_on` : `Ppu::new(Ntsc)`: v()==0, dot()==0, field()==false, dot_clocks()==4, line_dots()==340, last_line()==261, vblank_start()==225, in_vblank()==false, in_hblank()==true (dot 0 < 1). `Ppu::new(Pal).last_line()==311`.
- `e03_08_dot_clocks_walk` : apres 323 `step_dot`: dot()==323 et dot_clocks()==5 ; apres 324: dot_clocks()==5 ; apres 325: 4 ; apres 327: 5 ; apres 329: 4.
- `e03_08_line_sum` : somme des `dot_clocks()` relevee AVANT chaque `step_dot` sur 340 steps == 1364 ; ensuite v()==1 et dot()==0.
- `e03_08_events_line0` : Ppu::new: 1er `step_dot()` renvoie `DotEvents(17)` (LINE_START|VBLANK_END) ; 2eme (dot 1) renvoie `DotEvents(4)` ; les steps des dots 2..=273 renvoient `DotEvents(0)` ; le step du dot 274 renvoie `DotEvents(2)`.
- `e03_08_vblank_event` : apres exactement 225*340 steps: v()==225, dot()==0, in_vblank()==true ; le step suivant renvoie `DotEvents(9)` (LINE_START|VBLANK_START). Aucun step avant n'a renvoye VBLANK_START (bit 8).
- `e03_08_frame_ntsc_field0` : NTSC: somme des `dot_clocks()` sur exactement 262*340 steps == 357368 ; apres: v()==0, dot()==0, field()==true.
- `e03_08_frame_ntsc_field1_short` : enchainement: apres la frame 0, les 262*340 steps suivants somment 357364 (ligne 240 courte de 1360 clocks) ; apres: v()==0, field()==false.
- `e03_08_frame_pal` : PAL: frame 0 (field false): somme sur 312*340 steps == 425568 ; la frame 1 (field true, interlace off) somme aussi 425568 (pas de ligne longue sans interlace).
- `e03_08_vblank_end_event` : a la fin de la frame NTSC (apres 262*340 steps), le step suivant renvoie `DotEvents(17)` (v==0 de nouveau).
