Epopee: E08 | Type: code | Dependances: E08-18 | Taille estimee: ~140 lignes

## Contexte
Le thread d'emulation envoie l'audio de chaque frame dans l'anneau et se synchronise dessus (horloge principale). Sans audio: minuteur monotone a la cadence de la console. Avance rapide: aucune attente, audio jete. Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Dans `emu_thread.rs` (comportement existant conserve):
```rust
pub fn frame_period_ns(region: puce16_core::Region) -> u64;      // Ntsc 16_639_267 (1e9 / 60.0988) ; Pal 19_997_200 (1e9 / 50.0070)
pub fn spawn_with_audio(region: puce16_core::Region, start_paused: bool, ring: Option<crate::audio::SharedRing>) -> EmuHandle;
```
`spawn_test_pattern(region, paused)` devient `spawn_with_audio(region, paused, None)`.
Boucle (pas en pause): `run_frame()` ; `snes.take_audio(&mut v)` ; si `ring` est `Some` et PAS d'avance rapide : pousser `v` dans l'anneau (verrou court; trames refusees = perdues) puis ATTENDRE tant que `ring.len() > RING_WAIT_ABOVE` : dormir 1 ms, traiter les commandes pendant l'attente (`Quit`, `Pause`, ...), au plus 100 ms par frame. Si `ring` est `None` et pas d'avance rapide : cadence par echeance `next += frame_period_ns` (`Instant`), dormir jusqu'a `next` ; si le retard depasse 100 ms, `next = maintenant`. Avance rapide (`SetFastForward(true)`) : ni attente ni audio (`v` jete, anneau vide). Le motif de test ne produit pas d'audio. Region: celle de la ROM chargee (`cart_info().region`) apres `LoadRom` ; sinon celle donnee au `spawn`. En pause, ne rien pousser. ROM minimale pour les tests (LoROM, 32 Kio, boucle infinie): `fn tiny_rom() -> Vec<u8> { let mut r = vec![0u8; 0x8000]; r[0] = 0x80; r[1] = 0xFE; r[0x7FFC] = 0x00; r[0x7FFD] = 0x80; r }` (BRA -2 a 0x8000, vecteur RESET 0x8000; l'unique candidat d'en-tete est LoROM). Elle reste en mode emulation.

## 5. Audio (`cpal`)

- Le core produit des echantillons stereo `[i16; 2]` a ~32 040 Hz (`Snes::take_audio`). Le thread audio consomme un anneau (`Vec<[i16;2]>` circulaire, capacite 8192 trames).
- Re-echantillonnage vers la frequence du peripherique par interpolation sinc fenetree (Hann), 16 points, en `f32` (autorise ici). Volume 0..100 % applique en sortie. Muet = silence.
- Latence cible 60 ms (anneau ~ 2000 trames pleines). Sous-alimentation: repeter le dernier echantillon ; sur-alimentation (anneau > `RING_WAIT_ABOVE` = 3072 trames, ~96 ms; constante reglable): le thread d'emulation attend par pas de 1 ms, au plus 100 ms par frame (c'est l'horloge de synchronisation).
- Pas de peripherique audio: l'emulation continue avec le minuteur (message dans la barre d'etat).

## 4. Fenetre, video, filtres, plein ecran

- Fenetre egui (`eframe`), titre `Puce16 - <nom de la ROM>`. Zone de jeu = `FrameView` (256x224 .. 512x478, spec 05 section 6) affichee dans une texture RGBA (conversion XRGB8888 -> `Color32`).
- Echelle: entier `1..=8` (defaut 3) ou "ajuster a la fenetre" ; ratio: pixels carres (defaut) ou 8:7 (largeur multipliee par 8/7).
- Filtres (option `filter`): `nearest` (defaut, `TextureOptions::NEAREST`), `linear` (`TextureOptions::LINEAR`), `scanlines` (nearest + une ligne sur deux assombrie a 75 % par pre-traitement CPU, uniquement en echelle >= 2).
- Plein ecran: `ViewportCommand::Fullscreen(true)` (sans bordure), memes regles d'echelle, curseur masque apres 2 s.
- Cadence: PAL 50.0070 Hz, NTSC 60.0988 Hz (valeurs de reference, flottants autorises ici). Synchronisation principale = audio (section 5) ; sans audio: minuteur monotone. Pause automatique quand la fenetre perd le focus (option, defaut: non).
- Menu minimal (barre egui): Fichier (Ouvrir, ROM recentes, Quitter), Emulation (Pause, Reset, Save/Load state, slot), Video (echelle, ratio, filtre, plein ecran), Audio (volume 0-100, muet), Entrees (liste des touches, lecture seule en v1), Debug (ouvrir le debugger).

## 7. Architecture desktop

- Thread d'emulation (`emu_thread.rs`) possede `Snes` ; thread UI (egui) envoie des `Command` (`std::sync::mpsc`): `LoadRom(Vec<u8>, path)`, `Reset`, `Pause(bool)`, `FrameAdvance`, `SetJoypad(port, u16)`, `SaveState(slot)`, `LoadState(slot)`, `SetFastForward(bool)`, `RequestDebug(bool)`, `Quit`.
- Le thread d'emulation publie `Event` : `Frame(Arc<FrameData>)` (largeur, hauteur, pixels), `Status(String)`, `Debug(Box<DebugData>)` (seulement si demande), `SramDirty`, `Error(String)`.
- Boucle: tant que non en pause: `run_frame()` ; pousser l'audio ; publier la frame ; attendre selon la synchro. Une frame est publiee par frame emulee (la UI affiche la plus recente).
- Aucun etat d'emulation n'est partage par verrou avec la UI: tout passe par canaux.

## Tests
Tous les tests sont prefixes par `e08_19_`.

- `e08_19_frame_period` : `frame_period_ns(Ntsc)==16_639_267` ; `frame_period_ns(Pal)==19_997_200`.
- `e08_19_audio_flows_into_ring` : ring = `new_shared_ring()` ; `spawn_with_audio(Ntsc,false,Some(ring.clone()))` ; `LoadRom(tiny_rom(), "t")` ; attendre 300 ms : `ring.lock().len() > 500`.
- `e08_19_back_pressure` : meme montage, aucun consommateur, attendre 600 ms : `len() <= RING_WAIT_ABOVE + 600` (l'emulation s'est mise en attente) et `len() >= RING_WAIT_ABOVE - 600`.
- `e08_19_consumer_unblocks` : meme montage ; un thread consomme (`pop` de 256 toutes les 5 ms) : au moins 20 `Event::Frame` recus en 2 s.
- `e08_19_fast_forward_ignores_ring` : meme montage sans consommateur, `SetFastForward(true)` : au moins 30 `Event::Frame` en 1 s ; apres `SetFastForward(false)` le debit retombe (le nombre de frames des 300 ms suivantes est < 30).
- `e08_19_timer_pacing_without_ring` : `spawn_with_audio(Ntsc,false,None)` + `LoadRom(tiny_rom())` : 12 `Event::Frame` successives arrivent en plus de 150 ms et en moins de 1000 ms (cadence ~60 Hz).
- `e08_19_pause_pushes_nothing` : meme montage avec ring, `Pause(true)` puis vider l'anneau et attendre 200 ms : `len()==0`.
