## Specification
0. REGLE DE SORTIE: ne jamais afficher la sortie complete de l'oracle (elle peut faire des milliers de lignes). Toujours rediriger vers un fichier, puis lire seulement le debut:
   `cargo run -q -p puce16-cli -- cpu-test tests/oracle/65816 --filter E1,E3,E5,E7,E9,ED,EF,F1,F2,F3,F5,F7,F9,FD,FF > target/oracle_out.txt 2>&1` puis lire les 40 premieres lignes de `target/oracle_out.txt` (outil de lecture de fichier avec limite, ou `python -c "print(''.join(open('target/oracle_out.txt').readlines()[:40]))"`).
   La derniere ligne du fichier est `files: N ok: K failed: F`.
1. SBC seul: lancer (avec redirection, regle 0) `cargo run -q -p puce16-cli -- cpu-test tests/oracle/65816 --filter E1,E3,E5,E7,E9,ED,EF,F1,F2,F3,F5,F7,F9,FD,FF`. Corriger UN OPCODE A LA FOIS (relancer seulement l'opcode fautif, sortie redirigee). Maximum 6 opcodes corriges, puis question `bug` et blocage.
2. Cas decimaux: si l'oracle contredit l'algorithme de la spec, question `spec` avec le premier test en echec (A, m, C, D attendus/obtenus) AVANT de changer l'algorithme.
3. Quand SBC est a `failed: 0`: lancer toute la famille ALU (regle 0): `cargo run -q -p puce16-cli -- cpu-test tests/oracle/65816 --filter 01,03,04,05,06,07,09,0A,0C,0D,0E,0F,11,12,13,14,15,16,17,19,1A,1C,1D,1E,1F,21,23,24,25,26,27,29,2A,2C,2D,2E,2F,31,32,33,34,35,36,37,39,3A,3C,3D,3E,3F,41,43,45,46,47,49,4A,4D,4E,4F,51,52,53,55,56,57,59,5D,5E,5F,61,63,65,66,67,69,6A,6D,6E,6F,71,72,73,75,76,77,79,7D,7E,7F,88,89,C0,C1,C3,C4,C5,C6,C7,C8,C9,CA,CC,CD,CE,CF,D1,D2,D3,D5,D6,D7,D9,DD,DE,DF,E0,E1,E3,E4,E5,E6,E7,E8,E9,EC,ED,EE,EF,F1,F2,F3,F5,F6,F7,F9,FD,FE,FF`. Les fichiers `alu/*.rs` des etapes E02-26a..d sont deja valides; si une regression apparait, corriger seulement ce qui a ete casse.
4. Le fichier `tests/e02_27_oracle_regressions.rs` contient TOUJOURS la fonction de test `e02_27_oracle_clean_or_regressions` (elle verifie `Cpu::new().p == 0x34`), plus un test par bug corrige (nom `e02_27_<instruction>_<cas>`).
