# E02-27 - VERIF oracle: toutes les instructions ALU
Epopee: E02 | Type: code | Dependances: E02-26, E02-14 | Taille estimee: ~60 lignes

## Contexte
Passage a l'oracle de toutes les instructions de la famille ALU (ADC SBC AND ORA EOR BIT CMP CPX CPY INC DEC INX INY DEX DEY ASL LSR ROL ROR TSB TRB), y compris les cas decimaux.

- specs/01_CPU_65816.md sections 5 et 6
- specs/data/ssjson_format.md
- `docs/qa/DECISIONS.md` et `docs/qa/FAQ_SNES.md` (a consulter avant toute question)

## Write only in
- `crates/puce16-core/src/cpu/alu/*.rs`
- `crates/puce16-core/tests/e02_27_oracle_regressions.rs`
- `docs/qa/inbox/**` (questions uniquement)

1. Lancer: `cargo run -q -p puce16-cli -- cpu-test tests/oracle/65816 --filter 01,03,04,05,06,07,09,0A,0C,0D,0E,0F,11,12,13,14,15,16,17,19,1A,1C,1D,1E,1F,21,23,24,25,26,27,29,2A,2C,2D,2E,2F,31,32,33,34,35,36,37,39,3A,3C,3D,3E,3F,41,43,45,46,47,49,4A,4D,4E,4F,51,52,53,55,56,57,59,5D,5E,5F,61,63,65,66,67,69,6A,6D,6E,6F,71,72,73,75,76,77,79,7D,7E,7F,88,89,C0,C1,C3,C4,C5,C6,C7,C8,C9,CA,CC,CD,CE,CF,D1,D2,D3,D5,D6,D7,D9,DD,DE,DF,E0,E1,E3,E4,E5,E6,E7,E8,E9,EC,ED,EE,EF,F1,F2,F3,F5,F6,F7,F9,FD,FE,FF`
2. Corriger chaque echec dans `cpu/alu/*.rs` uniquement (diff = champ ou cycle fautif). Les modes d'adressage sont valides (E02-17): si un echec vient clairement d'un mode, poser une question `spec`/`bug` au lieu de modifier addr/.
3. Pour les cas decimaux: l'algorithme de la spec est un point de depart; si l'oracle le contredit, poser une question `spec` avec le premier test en echec (valeurs A, m, C, D attendues/obtenues) AVANT de changer l'algorithme.
4. Un test de regression par bug dans `tests/e02_27_oracle_regressions.rs` (nom `e02_27_<instruction>_<cas>`), ou le test `e02_27_oracle_clean` si rien a corriger (verifie `Cpu::new().p == 0x34`).
5. Fin: `failed: 0`.
