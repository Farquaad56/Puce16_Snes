# E10-03 - Triches: application sur la console (Snes::set_cheats, ecriture silencieuse a chaque image)
Epopee: E10 | Type: code | Dependances: E10-02 | Taille estimee: ~110 lignes

## Contexte
La console garde une liste de `ParCode` et les ecrit une fois par image, a la fin de `run_frame` (debut du VBlank). Ecriture routee comme dans la table de la spec: WRAM, SRAM par la cartouche, le reste ignore. Rien n'entre dans l'etat sauvegarde ni dans le hash. Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
1. `route.rs`: ajouter a `impl SysBus` la methode `pub fn cheat_write(&mut self, addr: u32, v: u8)` qui decode `bank = (addr >> 16) as u8`, `a = (addr & 0xFFFF) as u16` selon la table de la spec section 4: banques `0x00..=0x3F` et `0x80..=0xBF` avec `a < 0x2000` -> `self.wram.write(a as u32, v)`; banque `0x7E` -> `self.wram.write(a as u32, v)`; banque `0x7F` -> `self.wram.write(0x10000 + a as u32, v)`; banques `0x00..=0x3F`/`0x80..=0xBF` avec `a >= 0x6000`, banques `0x40..=0x7D` et `0xC0..=0xFF` -> `let _ = self.cart.write(bank, a, v);`; tout le reste est ignore. Aucun effet sur `master`, `mdr` ni les registres.
2. `snes.rs`: nouveau champ `cheats: Vec<ParCode>` dans `Snes` (initialise vide dans les trois constructeurs: `new_test_pattern`, `new_with`, et tout autre endroit qui construit `Snes {..}`); `pub fn set_cheats(&mut self, codes: &[ParCode])` (remplace la liste) et `pub fn cheats(&self) -> &[ParCode]`. Le champ n'est PAS dans `save_state`, `load_state` ni `state_hash`; `reset()` et `load_state()` ne le vident pas.
3. `run_frame`, variante `Inner::Real`: apres la boucle (et apres `self.frame = sys.vblank_count();`), `for c in &self.cheats { sys.cheat_write(c.addr, c.value); }`. Attention a l'emprunt: la boucle `match &mut self.inner` emprunte `self.inner` et `self.cheats` est un autre champ, mais ecrire `let cheats = &self.cheats;` avant le `match`, ou restructurer legerement si le compilateur refuse. La variante `Pattern` n'applique rien.
4. Tests (integration, fichier `e10_03_*.rs`): ROM LoRom construite par `build_rom_with` avec le programme `E6 00 80 FC` en tete (`INC $00` puis `BRA -4`, vecteur reset `0x8000`), 2 images au minimum. Pour la SRAM: ROM avec SRAM de 8 Kio (voir `build_rom_with`: parametres SRAM et chipset; chipset `0x02` = ROM + RAM + batterie) et `Snes::sram()` pour relire.

## 4. Application sur la console

- Les codes actifs sont appliques **une fois par image**, a la fin de `Snes::run_frame`, juste apres la detection du debut du VBlank (ils sont donc visibles par les lectures de l'image suivante).
- Une application est une ecriture silencieuse: zero cycle, aucune modification du temps, du `mdr` ni d'un registre. Ordre d'application = ordre de la liste (le dernier gagne).
- Routage de l'adresse `AAAAAA` = `bank:addr` (`bank = A >> 16`, `addr = A & 0xFFFF`):

| Cible | Condition | Effet |
|---|---|---|
| WRAM | `bank` 00-3F ou 80-BF, `addr` < 0x2000 | WRAM[addr] |
| WRAM | `bank` = 7E | WRAM[addr] |
| WRAM | `bank` = 7F | WRAM[0x10000 + addr] |
| Cartouche (SRAM) | `bank` 00-3F ou 80-BF avec `addr` >= 0x6000, ou `bank` 40-7D, ou `bank` C0-FF | `cart.write(bank, addr, v)` (la cartouche decide: SRAM ecrite, ROM ignoree) |
| Rien | tout le reste (registres PPU/APU/DMA/MMIO $2000-$5FFF, etc.) | ignore |

- Les triches ne font PAS partie de l'etat sauvegarde: ni dans `save_state`/`load_state`, ni dans `state_hash`. Sans triche, le comportement et tous les hashs existants sont inchanges.
- La liste de triches de `Snes` survit a `reset()` et a `load_state()`.

## Tests
Tous les tests sont prefixes par `e10_03_`.

- `e10_03_wram_bank7e_written_each_frame` : programme INC $00 en boucle; set_cheats([7E0000/0x42]); apres chaque run_frame (3 images de suite) peek_wram(0) = 0x42 (la console incremente puis la triche reecrit)
- `e10_03_wram_low_mirror_and_bank7f` : set_cheats([000100/0x11, 7F0010/0x22, 7E0200/0x33]) puis 1 image: peek_wram(0x100) = 0x11, peek_wram(0x10010) = 0x22, peek_wram(0x200) = 0x33
- `e10_03_sram_written_through_cart` : ROM avec SRAM 8 Kio: set_cheats([700001/0x5A]) puis 1 image: sram().unwrap()[1] = 0x5A
- `e10_03_rom_and_io_ignored` : set_cheats([008000/0xEE, 002100/0x0F, 004200/0x81, 7E0300/0x01]): apres 1 image peek_wram(0x300) = 0x01 et le programme tourne toujours (la ROM n'est pas modifiee: relire par Snes ne plante pas, state_hash calcule sans panique)
- `e10_03_order_last_wins` : set_cheats([7E0400/0x01, 7E0400/0x02]) puis 1 image: peek_wram(0x400) = 0x02
- `e10_03_no_cheat_hash_unchanged` : deux Snes identiques: l'un fait set_cheats(&[]) avant 2 images, l'autre non: state_hash egaux; cheats() = [] ; save_state de chacun identique
- `e10_03_cheats_survive_reset_and_load_state` : set_cheats([7E0500/0x07]); reset(); cheats().len() = 1; save_state; load_state: cheats().len() = 1 et l'effet est applique a l'image suivante
