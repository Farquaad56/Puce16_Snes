# E07-11c - TUNE: Mode 7, bruit blanc dans le haut de l'image (PeterLemon StarWars)
Epopee: E07 | Type: code | Dependances: E07-11b | Taille estimee: ~120 lignes

## Contexte
Tache de reglage creee a l'etape E07-12. La ROM `tests/roms/homebrew/peterlemon/PPU/Mode7/StarWars/StarWars.sfc` (manifeste: `peterlemon_ppu_mode7_starwars_starwars`, epopee E05, portee de 120 a 600 frames) affiche dans la moitie haute de l'image des traits et blocs blancs, restes de texte repetes. Constate par l'utilisateur dans le desktop et reproduit en CLI a 600, 1200 et 1800 frames (pas a 120: le defilement n'a pas commence). La reference (Snes9x) montre le haut de l'image noir avec les etoiles. `ppu/mode7.rs` traite deja le hors-carte (boucle, transparent, tuile 0): la cause est donc plutot dans l'echantillonnage affine des lignes lointaines (grands facteurs d'echelle, arrondis, bits 13 signes) ou dans la prise en compte par ligne de la matrice M7A-M7D mise a jour par HDMA.

## Specification
1. Reproduire: `cargo build --release -p puce16-cli` puis `target/release/puce16-cli run tests/roms/homebrew/peterlemon/PPU/Mode7/StarWars/StarWars.sfc --frames 600 --dump-ppm tests/out/e07_11c_starwars.ppm` et regarder le haut de l'image.
2. Isoler la ligne la plus haute fautive: ecrire un test qui regle la matrice et le centre d'une ligne lointaine (valeurs reprises de la ROM, lues via `--debug` ou un test) et compare le pixel obtenu a la formule de la spec. Verifier aussi que la matrice utilisee pour la ligne N est celle ecrite par HDMA avant cette ligne.
3. Regle de tuning: UNE seule modification a la fois (arrondi, largeur de bits, ordre, moment de latch), puis relancer l'etape 1 et noter l'effet.
4. Test de non-regression avec valeurs concretes (matrice, centre, scroll, pixel attendu), echoue avant la correction, passe apres.
5. Valeur ou comportement non specifie: `UNKNOWN - to confirm` + question bloquante, jamais de supposition.
