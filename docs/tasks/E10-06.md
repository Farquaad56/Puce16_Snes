## Specification
1. `cheat_panel.rs` (module declare dans `lib.rs`): `pub struct CheatPanel { pub open: bool, entries: Vec<CheatEntry>, pub name_input: String, pub codes_input: String, pub error: Option<String> }` avec: `new(entries: Vec<CheatEntry>) -> CheatPanel`; `entries(&self) -> &[CheatEntry]`; `add(&mut self, name: &str, codes_text: &str) -> Result<(), String>` (nom trim non vide et sans `=` ni retour a la ligne, sinon `Err("nom invalide")`; codes_text decoupe sur espaces et virgules, au moins un code, chacun valide par `parse_par`, sinon `Err` avec le texte du code fautif; en cas de succes l'entree est ajoutee ACTIVE a la fin); `toggle(&mut self, i: usize)`; `remove(&mut self, i: usize)` (indices hors limites: aucun effet, pas de panique); `active_codes(&self) -> Vec<ParCode>` (entrees actives, dans l'ordre, tous leurs codes).
2. Dans le meme fichier, `pub fn show(&mut self, ctx: &egui::Context) -> bool` qui dessine la fenetre `Triches` si `open` (liste: case a cocher + nom + codes en texte + bouton `Supprimer`; deux champs de saisie `Nom` et `Codes`; bouton `Ajouter` qui appelle `add` et vide les champs, ou renseigne `error`) et renvoie `true` si la liste a change ce frame. Suivre le style de `debugger.rs`.
3. `app.rs`: ajouter un champ `cheats: CheatPanel` a `App`; dans `open_path`, apres une lecture de ROM reussie: `cheat_path`, `load_cheat_entries` (en cas d'erreur: message dans la barre d'etat et liste vide), `self.cheats = CheatPanel::new(entries)`, puis envoyer `Command::SetCheats(self.cheats.active_codes())`. Dans `menu_bar`: menu `Triches` avec l'entree `Gerer les triches...` qui met `open = true`. Dans la mise a jour de l'interface: `if self.cheats.show(ctx) { envoyer SetCheats(active_codes); save_cheat_entries(cheat_path(rom_path), entries) }` en signalant une erreur d'ecriture dans la barre d'etat. Si aucune ROM n'est chargee, l'entree de menu est grisee.
4. Les noms de test du modele n'utilisent pas egui (le dessin n'est pas teste, seulement compile).

## 7. Desktop

- Fichier de triches d'une ROM: meme dossier et meme nom que la ROM avec l'extension `.cht` (comme `.srm`).
- Au chargement d'une ROM: lecture du `.cht` (absent = liste vide), envoi des codes actifs a la console par `Command::SetCheats(Vec<ParCode>)`. La console garde la liste apres un `Reset` et un rechargement de la console.
- Menu `Triches` > `Gerer les triches...`: fenetre avec la liste (case a cocher, nom, codes, bouton supprimer), un champ nom, un champ codes, un bouton Ajouter. Chaque modification renvoie les codes actifs et reecrit le `.cht` (ecriture atomique).
