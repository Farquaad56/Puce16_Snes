## Specification
Dans `emu_thread.rs`:
- `Command` gagne `SaveState(u8)` et `LoadState(u8)`. Le thread garde `rom_path: Option<PathBuf>` (E08-21) et `rom_hash` (calcule au `LoadRom` avec `files::rom_hash(&bytes)`).
- `SaveState(slot)`: sans ROM chargee (motif de test) ou sans `rom_path` : `Event::Error("no ROM loaded")`. Sinon `blob = snes.save_state()`, `data = encode_state(rom_hash, region_u8, &blob)` (Ntsc 0, Pal 1), `write_atomic(state_path(rom_path, slot), &data)` ; `Event::Status(format!("State saved to slot {}", slot))` ; erreur d'ecriture -> `Event::Error`.
- `LoadState(slot)`: lire le fichier (absent -> `Event::Error("no state in slot <n>")`), `decode_state(&data, rom_hash)` (erreur -> `Event::Error(<message>)`), region differente de celle de la console -> `Event::Error("state has another region")`, puis `snes.load_state(blob)` : `Err(e)` -> `Event::Error(format!("cannot load state: {}", e))` ET rechargement propre de la console (`Snes::new` sur les memes octets de ROM + SRAM rechargee) car son etat peut etre incoherent ; `Ok` -> `Event::Status(format!("State loaded from slot {}", slot))`, puis publier immediatement une `Event::Frame` de la frame courante (meme en pause).
- Ne pas modifier les autres comportements. Aide de test (a recopier): `fn sram_rom(code: &[u8]) -> Vec<u8> { let mut r = vec![0u8; 0x8000]; r[..code.len()].copy_from_slice(code); r[0x7FC0..0x7FC0 + 21].copy_from_slice(b"PUCE16 TEST          "); r[0x7FD5] = 0x20; r[0x7FD6] = 0x02; r[0x7FD7] = 0x05; r[0x7FD8] = 0x03; r[0x7FD9] = 0x01; r[0x7FDA] = 0x33; r[0x7FFC] = 0x00; r[0x7FFD] = 0x80; r[0x7FDC] = 0xFF; r[0x7FDD] = 0xFF; r[0x7FDE] = 0x00; r[0x7FDF] = 0x00; let sum: u32 = r.iter().map(|&b| b as u32).sum(); let c = (sum & 0xFFFF) as u16; r[0x7FDE] = c as u8; r[0x7FDF] = (c >> 8) as u8; let n = !c; r[0x7FDC] = n as u8; r[0x7FDD] = (n >> 8) as u8; r }` (LoROM 32 Kio avec 8 Kio de SRAM, chipset 0x02, vecteur RESET 0x8000; si `Snes::new` la refuse, corrige l'en-tete d'apres spec 04). Programmes (code a 0x8000): `PROG_W` = `78 18 FB A9 5A 8F 00 00 70 80 FE` (SEI CLC XCE LDA #$5A STA $700000 BRA -2) ; `PROG_R` = `78 18 FB AF 00 00 70 1A 8F 01 00 70 80 FE` (LDA $700000 ; INC A ; STA $700001 ; BRA -2). Dossier temporaire de test: `let dir = std::env::temp_dir().join(format!("puce16_<id>_{}", std::process::id()))` cree puis supprime a la fin du test.

## 6. Fichiers

- Ouverture: `rfd` (filtres `.sfc`, `.smc`, `.swc`, `.fig`, `.zip`). Un `.zip` (crate `zip`) : prendre la premiere entree dont l'extension est une des quatre precedentes.
- **SRAM**: `<dossier de la ROM>/<nom sans extension>.srm`, octets bruts de `Snes::sram()`. Chargee a l'ouverture de la ROM (`load_sram`) ; sauvee toutes les 5 s si le contenu a change, a la fermeture de la ROM et a la sortie ; ecriture atomique (ecrire `.srm.tmp` puis renommer). Pas de SRAM (`None`) -> aucun fichier.
- **Save states**: `<dossier de la ROM>/<nom>.<slot>.p16s`, slot 0..9. Contenu: en-tete `b"P16S"` + `u16` version du conteneur (1) + `u64` hash FNV-64 des octets de la ROM tels que charges (apres extraction d'un `.zip`, avant toute normalisation du core) + `u8` region, puis le blob `Snes::save_state()`. Au chargement: refuser (message) si magie, version ou hash ROM different.
- **Config**: `config.json` dans `%APPDATA%\Puce16\` (Windows) ; a defaut `$HOME/.config/puce16/`. JSON: `scale, ratio, filter, volume, muted, fullscreen, keymap, pad_map, recent_roms (max 8), last_dir, block_opposite_dirs`. Fichier absent ou invalide -> valeurs par defaut (jamais de plantage).
- Capture d'ecran F2: `<nom>_<n>.ppm` dans le dossier de la ROM (n = premier numero libre).

## 7. Architecture desktop

- Thread d'emulation (`emu_thread.rs`) possede `Snes` ; thread UI (egui) envoie des `Command` (`std::sync::mpsc`): `LoadRom(Vec<u8>, path)`, `Reset`, `Pause(bool)`, `FrameAdvance`, `SetJoypad(port, u16)`, `SaveState(slot)`, `LoadState(slot)`, `SetFastForward(bool)`, `RequestDebug(bool)`, `Quit`.
- Le thread d'emulation publie `Event` : `Frame(Arc<FrameData>)` (largeur, hauteur, pixels), `Status(String)`, `Debug(Box<DebugData>)` (seulement si demande), `SramDirty`, `Error(String)`.
- Boucle: tant que non en pause: `run_frame()` ; pousser l'audio ; publier la frame ; attendre selon la synchro. Une frame est publiee par frame emulee (la UI affiche la plus recente).
- Aucun etat d'emulation n'est partage par verrou avec la UI: tout passe par canaux.

## Tests
Tous les tests sont prefixes par `e08_22_`.

- `e08_22_save_without_rom` : `spawn_with_audio(Ntsc,true,None)` (motif de test) + `SaveState(0)` -> `Event::Error` contenant `no ROM loaded`.
- `e08_22_save_creates_file` : dossier temporaire, `sram_rom(PROG_W)` dans `dir/game.sfc`, `SetRomPath`, `LoadRom` ; `FrameAdvance` x2 ; `SaveState(3)` -> `Event::Status` contenant `State saved to slot 3` ; `dir/game.3.p16s` existe, commence par `P16S`, taille > 1_000_000.
- `e08_22_load_restores_frame_counter` : meme montage : `FrameAdvance` x2 (frame_no 1, 2), `SaveState(0)`, `FrameAdvance` x3 (frame_no 5), `LoadState(0)` : `Event::Status` contenant `State loaded from slot 0` puis une `Event::Frame` avec `frame_no==2` ; un `FrameAdvance` de plus -> `frame_no==3`.
- `e08_22_load_missing_slot` : `LoadState(7)` sans fichier -> `Event::Error` contenant `no state in slot 7`.
- `e08_22_load_foreign_rom` : ecrire un etat avec la ROM A (`PROG_W`), puis charger la ROM B (`PROG_R`, MEME chemin `game.sfc` pour retrouver le fichier d'etat) : `LoadState(0)` -> `Event::Error` contenant `another ROM`.
- `e08_22_load_corrupt_blob` : ecrire `encode_state(rom_hash, 0, &[1,2,3])` dans `game.1.p16s` : `LoadState(1)` -> `Event::Error` contenant `cannot load state` ; ensuite `FrameAdvance` fonctionne encore (console rechargee).
- `e08_22_load_works_while_running` : sans pause : `SaveState(0)`, attendre 200 ms, `LoadState(0)` : `Event::Status` de chargement recu et les frames continuent d'arriver.
- `e08_22_pal_region_byte` : `encode_state` utilise l'octet 1 pour une ROM PAL : ROM `sram_rom` avec `r[0x7FD9] = 0x02` (pays Europe) rechargee : le fichier d'etat a l'octet de region (indice 14) egal a 1.
