# E06-36 - Tests d'integration IPL: handshake et envoi d'un programme par les ports
Epopee: E06 | Type: code | Dependances: E06-35 | Taille estimee: ~110 lignes

## Contexte
Preuve que l'Apu complet execute la vraie ROM IPL: le S-CPU (ici simule par des appels `port_write`/`port_read`) envoie un petit programme par le protocole IPL et le lance.
Protocole (reference: l'IPL desassemblee) : (1) attendre `$AA` en port 0 et `$BB` en port 1 ; (2) ecrire l'adresse destination en ports 2 (bas) et 3 (haut), un octet NON NUL en port 1, puis `$CC` en port 0 ; attendre l'ecoute `$CC` en port 0 ; (3) pour chaque octet i (i = 0, 1, 2...) : ecrire l'octet en port 1, puis i (u8) en port 0, attendre que port 0 relu vaille i ; (4) pour lancer : ecrire l'adresse d'entree en ports 2/3, `0` en port 1, puis `(n + 1) as u8` en port 0 (n = nombre d'octets envoyes). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Ecris `tests/e06_36_ipl_upload.rs` (API publique seulement: `Apu::new`, `port_write`, `port_read`, `step_to`, `debug_peek`).
Aides: `fn run(apu: &mut Apu, master: &mut u64, clocks: u64) { *master += clocks; apu.step_to(*master); }` et `fn wait_port(apu: &mut Apu, master: &mut u64, port: usize, val: u8) -> bool` qui avance par pas de 2000 clocks, au plus 200 fois, jusqu'a `port_read(port) == val`.
Programme de test (6 octets) a l'adresse 0x0200: `E8 42  C4 F4  2F FE` = `MOV A,#$42 ; MOV $F4,A ; BRA -2` (met `$42` dans le port 0 cote CPU puis boucle).


### Notes
Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.
Si le programme n'est pas lance, ne change PAS l'Apu au hasard: le protocole ci-dessus est la reference; ecris une question `spec` avec les valeurs de ports observees.

## Tests
Tous les tests sont prefixes par `e06_36_`.

- `e06_36_handshake` : `Apu::new()` ; `run(100_000)` : `port_read(0)==0xAA` et `port_read(1)==0xBB`.
- `e06_36_upload_and_run` : handshake, puis les etapes (2) a (4) du protocole avec le programme de 6 octets a 0x0200 et l'entree 0x0200 : `wait_port(0, 0xCC)` vrai a l'etape 2 ; chaque echo d'octet attendu vrai ; apres le lancement `wait_port(0, 0x42)` vrai ; `debug_peek(0x0200)==0xE8`, `debug_peek(0x0205)==0xFE`.
- `e06_36_upload_two_blocks` : (a) handshake puis premier transfert: le programme de 6 octets a 0x0200 (etapes 2 et 3, SANS lancer); (b) commande du second transfert: ports 2/3 = 0x0300, port 1 = 1, port 0 = 7 (= n + 1, n = 6) ; attendre `port_read(0)==7` ; (c) envoyer les 3 octets `[0xAA,0xBB,0xCC]` avec les compteurs 0, 1, 2 (attendre l'echo de chaque compteur) ; (d) lancer: ports 2/3 = 0x0200, port 1 = 0, port 0 = 4 (= 3 + 1) ; attendre `port_read(0)==0x42` ; verifier `debug_peek(0x0300)==0xAA`, `debug_peek(0x0301)==0xBB`, `debug_peek(0x0302)==0xCC` et `debug_peek(0x0200)==0xE8`.
- `e06_36_ipl_does_not_start_before_cc` : apres le handshake, sans ecrire `$CC` : `step_to` de 100 000 clocks supplementaires : `port_read(0)` vaut toujours 0xAA et `debug_peek(0x0200)==0`.
