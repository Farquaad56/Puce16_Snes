pub const RING_CAPACITY: usize = 8192;        // trames
pub const RING_TARGET: usize = 2048;          // remplissage vise (~64 ms)
pub const RING_WAIT_ABOVE: usize = 3072;      // l'emulation attend au-dela (~96 ms)
pub struct AudioRing { buf: Vec<[i16; 2]>, head: usize, len: usize }
impl AudioRing {
    pub fn new() -> AudioRing;                              // capacite RING_CAPACITY, vide
    pub fn len(&self) -> usize;  pub fn capacity(&self) -> usize;  pub fn free(&self) -> usize;

}
pub type SharedRing = std::sync::Arc<std::sync::Mutex<AudioRing>>;
pub fn new_shared_ring() -> SharedRing;

## 5. Audio (`cpal`)

- Le core produit des echantillons stereo `[i16; 2]` a ~32 040 Hz (`Snes::take_audio`). Le thread audio consomme un anneau (`Vec<[i16;2]>` circulaire, capacite 8192 trames).
- Re-echantillonnage vers la frequence du peripherique par interpolation sinc fenetree (Hann), 16 points, en `f32` (autorise ici). Volume 0..100 % applique en sortie. Muet = silence.
- Latence cible 60 ms (anneau ~ 2000 trames pleines). Sous-alimentation: repeter le dernier echantillon ; sur-alimentation (anneau > `RING_WAIT_ABOVE` = 3072 trames, ~96 ms; constante reglable): le thread d'emulation attend par pas de 1 ms, au plus 100 ms par frame (c'est l'horloge de synchronisation).
- Pas de peripherique audio: l'emulation continue avec le minuteur (message dans la barre d'etat).

## Tests
Tous les tests sont prefixes par `e08_15_`.

- `e08_15_new_is_empty` : `AudioRing::new()`: `len()==0`, `capacity()==8192`, `free()==8192`.
- `e08_15_push_pop_order` : push de `[[1,1],[2,2],[3,3]]` puis `pop` de 2 -> `[[1,1],[2,2]]`, `len()==1` ; `pop` de 5 -> 1 trame `[3,3]`.
- `e08_15_push_full` : push de 8192 trames -> 8192 ; push de 10 de plus -> 0 ; `len()==8192` ; apres `pop` de 4 : push de 10 -> 4.
- `e08_15_wraparound` : push 6000, pop 6000, push 6000 (franchit la fin du tampon), pop : les 6000 valeurs relues sont dans l'ordre (valeurs `[i as i16, -(i as i16)]`).
- `e08_15_pop_empty` : `pop` sur anneau vide -> 0 et le tampon de sortie n'est pas modifie.
- `e08_15_clear` : apres `clear()`: `len()==0` ; push/pop refonctionnent.
- `e08_15_shared_ring_threads` : `new_shared_ring()` ; un thread ecrit 10 x 500 trames (par blocs, en reessayant tant que `push` renvoie moins que demande, avec `sleep(1ms)`), le thread de test lit jusqu'a 5000 trames : valeurs recues = suite croissante complete, aucune perte.
- `e08_15_constants` : `RING_TARGET < RING_WAIT_ABOVE` et `RING_WAIT_ABOVE < RING_CAPACITY`.
