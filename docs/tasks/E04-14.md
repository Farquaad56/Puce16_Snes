# E04-14 - ppu/mod.rs: framebuffer, pixel de fond (backdrop) et FrameView
Epopee: E04 | Type: code | Dependances: E04-13 | Taille estimee: ~140 lignes

## Contexte
Le PPU ecrit maintenant une image. Sans rendu des fonds (E05), chaque pixel visible vaut la couleur du backdrop (CGRAM mot 0) a la luminosite courante, ou noir en forced blank.
Le point d'extension du rendu est la fonction privee `pixel_bgr555(&self, x: usize) -> u16` (renvoie ici `cgram.word(0)`): E05 la remplacera par la composition complete. Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'. Dans les tests, utilise l'aide locale `fn at(p: &mut Ppu, v: u32, dot: u32) { for _ in 0..(v * 340 + dot) { p.step_dot(); } }` (valide pour NTSC, frame 0, sans entrelace; position atteinte = (v, dot) apres ces steps) et `fn set_backdrop(p: &mut Ppu, w: u16) { p.write(0x21, 0); p.write(0x22, (w & 0xFF) as u8); p.write(0x22, (w >> 8) as u8); }`.

## Specification
Dans `ppu/mod.rs`: ajoute au `Ppu` les champs `fb: FrameBuf`, `view: Vec<u32>` (copie compacte de la derniere frame complete), `view_w: usize`, `view_h: usize` (initialement 256x224, noir `0xFF000000`).
```rust
pub fn frame(&self) -> FrameView<'_>;     // output::make_view(view_w, view_h, &view)
fn pixel_bgr555(&self, x: usize) -> u16;  // E04: self.cgram.word(0)   (E05: composition)
```
`step_dot` (sur la position COURANTE, dans l'ordre de la section 5.3), apres les evenements du point 2:
- point 3: si `1 <= v <= vis_last` et `22 <= dot <= 277` (`vis_last = vblank_start() - 1`): `x = (dot - 22) as usize` ; `row = output_row((v - 1) as usize, field, interlace)` ; `argb = if forced_blank { 0xFF000000 } else { bgr555_to_xrgb(pixel_bgr555(x), brightness) }` ; `fb.set(x, row, argb)`. (Colonne `x` seulement: le mode hi-res vient en E05.)
- a `dot == 0` et `v == vblank_start()` (APRES le rechargement OAM): capture de la frame: `w = 256` ; `h = vis_last * (if interlace {2} else {1})` ; `fb.set_view(w, h)` ; `view = fb.compact()` ; `view_w = w` ; `view_h = h`.
`Ppu::reset()` remet aussi `fb = FrameBuf::new()` et `view` a 256x224 noir. Le framebuffer et `view` ne font PAS partie de `hash_into` (etat derive; ne les ajoute pas).

### 5.3 Evenements par (v, dot), dans CET ordre dans `step_dot`
1. `dot == 0`:
   - `v == 0`: debut de frame: `time_over = range_over = false`; evenement VBLANK_END.
   - `1 <= v <= vis_last`: **evaluation des sprites** pour la ligne (05b section 6) -> remplit `line_obj[256]`.
   - `v == vblank_start`: evenement VBLANK_START; rechargement OAM (2.1) si `!forced_blank`.
   - evenement LINE_START (toujours).
2. `dot == 274`: evenement HBLANK_START. `dot == 1`: HBLANK_END. (bornes `UNKNOWN - to confirm`, spec 02 3.1: 1096 clocks / 4.)
3. Si `1 <= v <= vis_last` et `22 <= dot <= 277`: `x = dot - 22`; **composer le pixel x** (05b section 11) et l'ecrire dans le framebuffer (section 6).
4. Avancer `dot += 1`; si `dot == line_dots(v)`: `dot = 0; v += 1; si v > last_line {v = 0; field ^= 1; FRAME_START}`.

`step_dot` retourne un petit ensemble de drapeaux (`DotEvents`: LINE_START, HBLANK_START, HBLANK_END, VBLANK_START, VBLANK_END) et `scheduler` gere NMI/IRQ/HDMA/auto-joypad a partir de la position (spec 02/03). Le PPU ne connait ni DMA ni NMI.

## 6. Sortie: framebuffer

- Tampon interne fixe: `[u32; 512 * 478]`, pixel XRGB8888 avec octet haut `0xFF`: `0xFF000000 | r8 << 16 | g8 << 8 | b8`.
- Conversion finale d'un canal 5 bits `c5` (apres math et luminosite): `c5b = c5 * brightness / 15` (division entiere; brightness 0..15), puis `c8 = (c5b << 3) | (c5b >> 2)` (D-010). `forced_blank` -> `0xFF000000` (noir).
- Rangee de sortie: `row = if frame_interlaced { 2 * r + field_as_u8 } else { r }`. Les rangees de l'autre field gardent leur contenu precedent (image entrelacee complete = 448 ou 478 lignes).
- Colonne: mode 256: `x` (largeur utile 256). Mode hi-res (SETINI.3 ou BG mode 5/6, voir 05b section 12): colonnes `2x` (sous-ecran) et `2x+1` (ecran principal) dans le tampon 512.
- Si la ligne n'est pas hi-res mais que la frame l'est (`frame_hires` = au moins une ligne hi-res dans la frame courante), chaque pixel est duplique sur `2x`, `2x+1` a l'export.
- `FrameView` (spec 01_ARCHITECTURE section 5) est calcule au debut de VBlank (`v == vblank_start`): `width = if frame_hires {512} else {256}`, `height = (vis_last) * (if frame_interlaced {2} else {1})`, avec `frame_interlaced = interlace` lu a ce moment. `pixels` = copie compacte de la zone utile (stride = width). `Ppu::frame()` retourne la derniere frame complete.
- Les lignes non visibles ou ligne 0: non ecrites.

## Tests
Tous les tests sont prefixes par `e04_14_`.

- `e04_14_initial_frame` : `Ppu::new(Ntsc).frame()`: width==256, height==224, pixels.len()==57344, tous egaux a 0xFF000000.
- `e04_14_forced_blank_black` : CGRAM mot 0 = 0x001F (`set_backdrop`), forced blank (defaut) ; `at(p,225,1)` : `frame()` 256x224, tous les pixels 0xFF000000.
- `e04_14_backdrop_red` : `set_backdrop(&mut p,0x001F)` ; `write(0x00,0x0F)` ; `at(p,225,1)` : `frame()` 256x224 et tous les 57344 pixels == 0xFFFF0000.
- `e04_14_frame_not_captured_early` : meme preparation ; `at(p,225,0)` (le step du dot 0 de la ligne 225 n'est pas encore execute) : `frame()` est encore l'image initiale noire (tous 0xFF000000) ; un `step_dot` de plus -> tous 0xFFFF0000.
- `e04_14_brightness_second_frame` : apres la preparation rouge et `at(p,225,1)`, `write(0x00,0x08)` ; 262*340 steps supplementaires : tous les pixels == 0xFF840000.
- `e04_14_overscan_height` : `write(0x33,0x04)`, backdrop rouge, display on ; `at(p,240,1)` : `frame().height==239`, `pixels.len()==256*239`, tous 0xFFFF0000.
- `e04_14_interlace_fields` : `write(0x33,0x01)`, backdrop rouge, display on ; `at(p,225,1)` (frame 0, field faux) : `frame().height==448` ; pixel (0,0) rouge, pixel (0,1) 0xFF000000, pixel (255,446) rouge, pixel (255,447) 0xFF000000, nombre de pixels rouges == 224*256. Frame suivante (field vrai, 263 lignes a la frame 0 en entrelace NTSC): apres 263*340 steps supplementaires, tous les 448*256 pixels sont rouges.
- `e04_14_line_change_vertical` : backdrop rouge, display on ; `at(p,100,0)` puis `set_backdrop(&mut p,0x7C00)` (bleu) ; continuer jusqu'a (225,1) (125*340+1 steps) : les rangees 0..=98 sont rouges, les rangees 99..=223 sont bleues (0xFF0000FF) (la ligne v=100 donne la rangee 99).
- `e04_14_mid_line_change` : backdrop rouge, display on ; `at(p,10,150)` puis `set_backdrop` bleu ; continuer jusqu'a (225,1) : dans la rangee 9 les colonnes 0..=127 sont rouges et 128..=255 sont bleues (le dot 150 dessine la colonne 128 et vient APRES l'ecriture) ; la rangee 8 est entierement rouge ; la rangee 10 est entierement bleue.
- `e04_14_reset_clears_image` : apres une frame rouge, `reset()` : `frame()` est a nouveau 256x224 noir.
- `e04_14_hash_ignores_framebuffer` : A: `set_backdrop(rouge 0x001F)`, `write(0x00,0x0F)`, `at(p,225,1)`, puis `set_backdrop(&mut p,0)`. B: `set_backdrop(&mut p,0)`, `write(0x00,0x0F)`, `at(p,225,1)`. Les registres, memoires et compteurs sont identiques: `hash(A)==hash(B)` alors que `A.frame()` est rouge et `B.frame()` noir (le framebuffer n'est pas dans le hash).
