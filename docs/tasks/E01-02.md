## Specification
1. `Cargo.toml` racine: `members = ["crates/*"]` (ou liste explicite des trois crates).
2. `crates/puce16-cli`: package `puce16-cli`, binaire `puce16-cli`, dependances: `puce16-core` (path), `clap` (feature `derive`), `serde` (derive), `serde_json`, `toml`. `src/main.rs`: struct clap `Cli` avec `#[command(version)]` et sous-commande vide; sans argument, affiche l'aide; `--version` affiche `puce16-cli <version>`.
3. `crates/puce16-desktop`: package `puce16-desktop`, binaire `puce16-desktop`, dependances: `puce16-core` (path), `eframe` (egui), `cpal`, `rfd`, `zip`, `gilrs`, `serde` (derive), `serde_json`. `src/lib.rs` declare `pub mod app; pub mod audio; pub mod config; pub mod debugger; pub mod emu_thread; pub mod files; pub mod input; pub mod video;` et chacun de ces fichiers existe avec la seule ligne `// stub: filled by a later task` (les taches suivantes ne modifient plus lib.rs). `src/main.rs`: `fn main() { println!("puce16-desktop {}", puce16_core::VERSION); }` (la fenetre vient en E01-11). Dans ce projet, egui s'utilise via `eframe::egui` (pas de dependance `egui` separee).
4. Versions: laisse Cargo choisir les dernieres versions compatibles puis ECRIS les versions resolues dans les `Cargo.toml`. Si une crate ne se telecharge pas (reseau): question `tooling`, ne pas la retirer.
5. Ne pas lancer `cargo update` sur les dependances deja resolues apres cette tache sans demande de Claude.

## 2. Workspace Cargo

```
Cargo.toml                       [workspace] members = crates/*
crates/puce16-core/              lib, aucune dependance runtime (sauf serde optionnel feature "serde")
crates/puce16-cli/               binaire `puce16-cli` (clap), depend de core
crates/puce16-desktop/           binaire `puce16-desktop` (egui/eframe, cpal, rfd, zip), depend de core
tests/                           baseline.json, manifest.toml, roms/README.md (pas de ROM commitee)
docs/                            toute la documentation (ce dossier)
```

Dependances autorisees:
- core: aucune en v1 (`std` seulement). Feature optionnelle `serde` interdite en v1.
- cli: `clap` (derive), `serde`, `serde_json`, `toml`.
- desktop: `eframe`/`egui`, `cpal`, `rfd`, `zip`, `gilrs` (D-019), `serde`, `serde_json`.
- Dev-deps de core: `serde`, `serde_json` (chargement des tests JSON SingleStepTests).

Toute nouvelle dependance = question Q&R (QA) avant ajout.

## 7. Architecture desktop

- Thread d'emulation (`emu_thread.rs`) possede `Snes` ; thread UI (egui) envoie des `Command` (`std::sync::mpsc`): `LoadRom(Vec<u8>, path)`, `Reset`, `Pause(bool)`, `FrameAdvance`, `SetJoypad(port, u16)`, `SaveState(slot)`, `LoadState(slot)`, `SetFastForward(bool)`, `RequestDebug(bool)`, `Quit`.
- Le thread d'emulation publie `Event` : `Frame(Arc<FrameData>)` (largeur, hauteur, pixels), `Status(String)`, `Debug(Box<DebugData>)` (seulement si demande), `SramDirty`, `Error(String)`.
- Boucle: tant que non en pause: `run_frame()` ; pousser l'audio ; publier la frame ; attendre selon la synchro. Une frame est publiee par frame emulee (la UI affiche la plus recente).
- Aucun etat d'emulation n'est partage par verrou avec la UI: tout passe par canaux.
