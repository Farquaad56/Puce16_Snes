## Specification
Dans `cpu_test/oracle.rs` (`puce16-cli` est un binaire: les tests sont des tests unitaires `#[cfg(test)] mod tests` DANS `oracle.rs`, fonctions nommees `e02_12_...`; l'exemple JSON est lu avec `include_str!("../../tests/data/e02_12_sample.json")`) :
```rust
pub struct CpuState { pub pc: u16, pub s: u16, pub p: u8, pub a: u16, pub x: u16, pub y: u16, pub dbr: u8, pub d: u16, pub pbr: u8, pub e: bool, pub ram: Vec<(u32, u8)> }
pub struct CycleRec { pub addr: Option<u32>, pub val: Option<u8>, pub kind: String }   // champs = ceux du document de format
pub struct Case { pub name: String, pub initial: CpuState, pub fin: CpuState, pub cycles: Vec<CycleRec> }
pub fn load_file(path: &std::path::Path) -> Result<Vec<Case>, String>;
pub fn list_files(dir: &std::path::Path, filter: Option<&str>) -> Result<Vec<std::path::PathBuf>, String>;
pub fn opcode_of_file(name: &str) -> Option<u8>;
```
Les noms de champs/cles JSON sont ceux du document de format (si une cle differe de ce qui est ecrit ci-dessus, le document gagne et la struct s'adapte, en gardant les memes noms Rust).
- `list_files`: tous les `.json` (recursif), tries par nom; `filter` = liste d'opcodes en hexa separes par des virgules (`61,63,E9`); un fichier est garde si `opcode_of_file(nom)` est dans la liste (ou si `filter` est None). Erreur `String` si le dossier ne se lit pas.
- `opcode_of_file`: convention du document section 7: les deux premiers caracteres du nom (hexa, insensible a la casse) si le nom a la forme `HH.e.json` ou `HH.n.json`, sinon `None` (les vrais noms sont en MINUSCULES: `4c.e.json`). Le `filter` est lui aussi insensible a la casse, espaces tolerees.
- Dans `CycleRec`, `addr` et `val` sont `Option` car le JSON contient des `null` (cycles internes: `val` null; cycle mort final de WAI/STP: `addr` et `val` null). `kind` = la chaine de 8 caracteres telle quelle.
- `load_file`: erreurs en `Err(String)` avec le nom du fichier; aucun `unwrap` sur des donnees externes.
- Utiliser `serde` + `serde_json` (deja dans le Cargo.toml).

## Tests
Tous les tests sont prefixes par `e02_12_`.

- `e02_12_load_sample` : Le fichier `tests/data/e02_12_sample.json` est un TABLEAU JSON `[ ... ]` contenant UNIQUEMENT le test de la section 5 du document de format (copie tel quel, le bloc ```json```). `load_file` renvoie 1 cas ; verifier: name == "db n 1", initial.pc == 34298, initial.s == 753, final.ram == [(3180026, 219)], 4 cycles, cycles[1] == (Some(3180027), None, "---r-m--"), cycles[3] == (None, None, "--------").
- `e02_12_load_bad_json` : un fichier contenant `not json` -> Err(message contenant le nom du fichier).
- `e02_12_opcode_of_file` : `4c.e.json` -> Some(0x4C) ; `0a.n.json` -> Some(0x0A) ; `a9.n.json` -> Some(0xA9) ; `FF.e.json` -> Some(0xFF) ; `readme.md` -> None ; `4c.x.json` -> None.
- `e02_12_list_files_filter` : dossier temporaire avec 3 faux fichiers nommes selon la convention (opcodes 61, 69, e9, noms en minuscules): `filter=Some("61,E9")` (insensible a la casse) -> 2 fichiers tries ; `filter=None` -> 3 ; dossier absent -> Err.
