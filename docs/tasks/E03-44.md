```rust
pub fn describe_load_error(e: &puce16_core::snes::LoadError) -> String;   // TooSmall -> "ROM too small" ; NoHeader -> "no valid ROM header found" ; UnsupportedCoprocessor(n) -> "unsupported coprocessor: <n>"

```
`format_debug` produit exactement: `debug: pc=<pb:02X>:<pc:04X> a=<:04X> x=<:04X> y=<:04X> s=<:04X> d=<:04X> db=<:02X> p=<:02X> e=<0|1> v=<decimal> dot=<decimal> master=<decimal> frame=<decimal>`.
2. `main.rs`, sous-commande `run`: argument positionnel OPTIONNEL `[ROM]` ; options en plus de l'existant: `--state-hash` (imprime `state_hash=0x<16 hex minuscules>` = `Snes::state_hash()`), `--mapper lorom|hirom|exhirom` (force le mapper), `--debug` (imprime `format_debug(&snes.debug())` sur stdout, apres les autres sorties). Reste: `--frames N` (defaut 1), `--hash`, `--region ntsc|pal` (force la region; sinon deduite de l'en-tete pour une ROM, ntsc pour le motif), `--dump-ppm FICHIER`, `--test-pattern`.
3. Logique: ni `ROM` ni `--test-pattern` -> erreur d'usage (stderr `rom path or --test-pattern required`, code 2). `ROM` fourni: `std::fs::read` (erreur -> stderr `cannot read <chemin>: <erreur>`, code 2) ; `Snes::new_with(&bytes, region, mapper)` (erreur -> stderr `cannot load ROM: <describe_load_error>`, code 2). Executer `--frames` fois `run_frame()` dans `std::panic::catch_unwind(AssertUnwindSafe(..))` ; si panique: stderr `emulator panic` + `format_debug(...)` et code 1. Ordre des sorties stdout: `frame_hash=...` (si --hash), `state_hash=...` (si --state-hash), ligne `debug: ...` (si --debug).
4. Codes de sortie: 0 OK, 1 panique/echec d'emulation, 2 erreur d'usage ou de fichier.
ROM minimale pour les tests (LoROM, 32 Kio, boucle infinie): `fn tiny_rom() -> Vec<u8> { let mut r = vec![0u8; 0x8000]; r[0] = 0x80; r[1] = 0xFE; r[0x7FFC] = 0x00; r[0x7FFD] = 0x80; r }` (BRA -2 a 0x8000, vecteur RESET 0x8000; l'unique candidat d'en-tete est LoROM). Elle reste en mode emulation.

## 6. Commande `puce16-cli suite <manifest.toml>`

- Pour chaque `[[rom]]` dont `epic <= --max-epic` (option, defaut: toutes): charge, execute `frames` frames, calcule `frame_hash` (FNV-1a 64 de `width` puis `height` (chacun `u32` little-endian) puis des pixels `u32` little-endian du `FrameView`, ligne par ligne -- identique a `puce16-cli run --hash`), `state_hash` (`Snes::state_hash`) et `audio_hash` (voir section 5).
- Compare a `baseline.json` selon `check`. Rapport `PASS`/`FAIL`/`SKIP` (optional absente) / `NEW` (pas de baseline).
- `--update-baseline <name>` : reecrit l'entree (uniquement demande par l'utilisateur apres validation visuelle, jamais par Hermes).
- `--dump-ppm DIR` : ecrit `<name>.ppm` (P6, 8 bits, largeur/hauteur du `FrameView`, pixels RGB) pour la revue visuelle.
- Echec = toujours `DebugSnapshot` (PC, A, X, Y, S, D, DB, PB, P, e, H/V, master, frame) ; jamais un `TIMEOUT` nu.
- Code de sortie: 0 = aucun FAIL, 1 = au moins un FAIL, 2 = erreur d'usage.

FNV-1a 64: `h = 0xcbf29ce484222325 ; pour chaque octet b: h ^= b ; h = h.wrapping_mul(0x100000001b3)`. Implementation unique dans `hash.rs` (`Fnv64::new() / write(&[u8]) / write_u64(u64) (little-endian) / finish()`).

## 6. CLI (`puce16-cli`)

```
puce16-cli run <rom> [--frames N] [--region ntsc|pal] [--hash] [--trace FILE]
                     [--dump-ppm FILE] [--save-state FILE] [--load-state FILE]
puce16-cli suite <manifest.toml> [--update-baseline]
puce16-cli cpu-test <dossier_json_65816> [--filter NN]     # SingleStepTests
puce16-cli spc-test <dossier_json_spc700> [--filter NN]
```

Codes de sortie: 0 = OK, 1 = echec de test, 2 = erreur d'usage/fichier.
Tout echec imprime `DebugSnapshot` (PC/A/X/Y/S/D/DB/P, H/V, master).

## Tests
Tous les tests sont prefixes par `e03_44_`.

- `e03_44_format_debug` : test unitaire dans `run_cmd.rs`: `DebugSnapshot{pc:0x8000,pb:0,a:0x1234,x:0xABCD,y:0,s:0x01FF,d:0,db:0x7E,p:0x34,e:true,v:225,dot:3,master:306905,frame:1}` -> `"debug: pc=00:8000 a=1234 x=ABCD y=0000 s=01FF d=0000 db=7E p=34 e=1 v=225 dot=3 master=306905 frame=1"`. Avec pb=0x12, pc=0x0ABC, e=false -> `pc=12:0ABC` et `e=0`.
- `e03_44_describe_errors` : test unitaire: `describe_load_error(&LoadError::Cart(CartError::TooSmall))=="ROM too small"` ; NoHeader -> `"no valid ROM header found"` ; `UnsupportedCoprocessor("GSU")` -> `"unsupported coprocessor: GSU"`.
- `e03_44_run_rom_state_hash` : ecris `tiny_rom()` dans un fichier temporaire; `run <f> --frames 3 --state-hash`: code 0 et stdout contient une ligne `state_hash=0x` suivie de 16 chiffres hexa minuscules.
- `e03_44_run_rom_deterministic` : deux executions identiques -> sorties identiques ; `--frames 3` et `--frames 4` donnent des `state_hash` differents.
- `e03_44_run_rom_hash_line` : `--hash` imprime `frame_hash=0x` + 16 hexa (le cadre d'un Snes reel est noir pour l'instant).
- `e03_44_run_rom_debug` : `run <f> --frames 1 --debug`: stdout contient `debug: pc=00:8000 ` et ` e=1 ` et ` v=225 ` et ` frame=1`.
- `e03_44_run_rom_region` : `--region pal` et `--region ntsc` sur la meme ROM (--frames 3 --state-hash) donnent des hash differents ; `--region xyz` -> code 2 (erreur clap).
- `e03_44_run_missing_file` : `run /nonexistent/x.sfc` -> code 2 et stderr contient `cannot read`.
- `e03_44_run_too_small` : fichier de 100 octets -> code 2 et stderr contient `too small`.
- `e03_44_run_bad_mapper` : `--mapper hirom` sur `tiny_rom()` (32 Kio, en-tete HiRom absent) -> code 2 et stderr contient `no valid ROM header`.
- `e03_44_run_dump_ppm` : `--dump-ppm <tmp>` avec une ROM: fichier de taille 15 + 256*224*3 octets commencant par `P6\n256 224\n255\n`.
- `e03_44_legacy_pattern_still_works` : `run --test-pattern --frames 5 --hash` code 0 ; `run` sans argument -> code 2 et stderr contient `rom path or --test-pattern required`.
