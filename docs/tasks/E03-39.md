# E03-39 - Integration: DMA general ROM -> WRAM par $2180 et relecture
Epopee: E03 | Type: code | Dependances: E03-38 | Taille estimee: ~110 lignes

## Contexte
Le DMA demarre apres l'instruction suivant l'ecriture de $420B, copie la ROM vers la WRAM via le port $2180, puis le CPU reprend. Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Donnees ROM: bloc `(0x200, &[0x11,0x22,0x33,0x44,0x55,0x66,0x77,0x88])` (adresse CPU 0x8200). Programme `PROG_DMA` (offset 0):
```

A9 00 8D 81 21           WMADDL = 0
A9 02 8D 82 21           WMADDM = 2     (WMADD = 0x200)
9C 83 21                 STZ $2183
9C 00 43                 DMAP0 = 0      (A->B, pattern 0, A++)
A9 80 8D 01 43           BBAD0 = $80    ($2180)
9C 02 43                 A1T0L = 0
A9 82 8D 03 43           A1T0H = $82    (A = 00:8200)
9C 04 43                 A1B0 = 0
A9 08 8D 05 43           DAS0L = 8
9C 06 43                 DAS0H = 0
A9 01 8D 0B 42           MDMAEN = 1

A9 7B 8D 10 01           marqueur: $0110 = $7B
A9 00 8D 81 21           WMADDL = 0

## 3. DMA general (MDMAEN $420B)

Ecriture non nulle: les canaux dont le bit est a 1 s'executent dans l'ordre 0..7. Le CPU est arrete pendant toute la duree.

Pour chaque canal actif, tant que le compteur n'est pas 0:
1. Lire un octet (source selon direction), ecrire a destination.
   - Direction A->B: lire A-bus `(A1Bn:A1Tn)`, ecrire B-bus `$2100 + ...`.
   - Direction B->A: lire B-bus, ecrire A-bus.
2. Passer a l'octet suivant du pattern (offset B suivant, cyclique sur la longueur du pattern).
3. Ajuster A1Tn (16 bits, la banque ne change jamais): mode 0: +1; mode 2: -1; modes 1 et 3: inchange.
4. Decrementer DASn (16 bits). A 0 -> fin du canal. Le transfert s'arrete meme au milieu d'un pattern.

Apres le canal: DASn = 0, A1Tn = adresse apres l'avance (wrap 16 bits dans la banque). Compteur initial 0 = 65536 octets.

Restrictions:
- L'adresse A-bus ne peut pas viser $2100-$21FF, $4000-$41FF, $4200-$421F, $4300-$437F (banques 00-3F/80-BF): ces acces sont ignores (lecture = open bus; ecriture = rien). `UNKNOWN - to confirm` le detail: defaut = lecture open bus (`mdr`), ecriture ignoree.
- DMA WRAM->$2180 : la lecture A-bus en WRAM n'a pas d'effet utile (rien n'est ecrit, adresse WMADD non incrementee). DMA $2180->WRAM: ecrit open bus; WMADD non incremente. (wiki)
- BBADn = $00 sur certaines revisions de CPU: ne pas emuler la panne; documenter seulement.
- DMA ne peut pas copier WRAM -> WRAM.

### 3.1 Timing DMA (cycle-accurate, valeurs par defaut)
- L'ecriture de MDMAEN fixe un drapeau "DMA en attente". Le DMA demarre **apres la lecture de l'opcode de l'instruction suivante** (le CPU ne se fait pas interrompre au milieu d'un cycle).
- Au demarrage: temps maitre aligne sur le multiple de 8 clocks suivant (`master_phase`; `UNKNOWN - to confirm` l'origine: defaut = origine de la ligne 0 de la frame), puis **8 clocks de surcout**.
- Par canal actif: **8 clocks** de surcout de canal.
- Par octet transfere: **8 clocks**.
- A la fin: **le CPU reprend apres un alignement sur son prochain cycle** (6/8/12 clocks selon l'adresse du cycle suivant): `UNKNOWN - to confirm`; defaut: pas de realignement supplementaire.
- HDMA peut interrompre un DMA general: le DMA est mis en pause pendant l'execution de HDMA (voir 4).
- Les composants PPU/APU/timers avancent normalement pendant le DMA (via `catch_up`). Le CPU ne s'execute pas.

## Tests
Tous les tests sont prefixes par `e03_39_`.

- `e03_39_data_copied` : apres `run_frame()`: `peek_wram(0x200+i)==[0x11,0x22,0x33,0x44,0x55,0x66,0x77,0x88][i]` pour i in 0..8 ; `peek_wram(0x208)==0x55` (intact).
- `e03_39_cpu_resumes` : apres `run_frame()`: `peek_wram(0x110)==0x7B` (le CPU a repris apres le DMA).
- `e03_39_wmdata_readback` : apres `run_frame()`: `peek_wram(0x111)==0x11` et `peek_wram(0x112)==0x22` (relecture par $2180 avec WMADD ramene a 0x200).
- `e03_39_dma_takes_time` : deux `Snes`: l'un avec PROG_DMA, l'autre avec PROG_DMA dont l'octet de valeur de `A9 01 8D 0B 42` est remplace par 0x00 (offset 0x2C : MDMAEN = 0, meme duree d'instruction). Dans chacun, executer exactement 22 `step_instruction()` (jusqu'au NOP inclus). `master_dma - master_nodma` est compris entre 80 et 130 inclus (8 depart + 8 canal + 8*8 octets = 80, + alignement 0..7, + eventuellement un rafraichissement DRAM de 40 clocks decale par le DMA).
- `e03_39_dma_data_not_before_trigger` : `step_instruction()` pas a pas depuis `new` jusqu'a ce que `debug().pc == 0x8030` (STA $420B vient d'etre executee ; le NOP est la prochaine instruction): `peek_wram(0x200)==0x55` (rien copie) ; apres UN `step_instruction()` de plus (le NOP), `peek_wram(0x200)==0x11` et `peek_wram(0x207)==0x88`.
- `e03_39_deterministic` : deux `Snes` identiques: meme `state_hash` apres `run_frame()` x2.
- `e03_39_mdmaen_zero_no_dma` : variante avec `A9 00 8D 0B 42` (MDMAEN=0): `peek_wram(0x200)==0x55` apres une frame.
