# E03-29 - bus/cycle.rs: avance du temps, catch_up et impl cpu::Bus
Epopee: E03 | Type: code | Dependances: E03-28 | Taille estimee: ~140 lignes

## Contexte
Flux de temps (spec 09 section 2): chaque acces CPU fait avancer `master` puis rattrape le PPU dot par dot (`catch_up`); `Timing::on_dot` produit les evenements.
Cette tache ne gere NI le rafraichissement, NI DMA, NI HDMA (E03-30..33): `begin_cycle`/`end_cycle` sont des fonctions vides a remplir. Ajoute `mod cycle;` a `bus/mod.rs`. Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Dans `bus/cycle.rs`:
```rust
impl SysBus {
    pub fn advance(&mut self, clocks: u32) { self.master += clocks as u64; self.catch_up(); }
    pub fn catch_up(&mut self) {
        while self.ppu_t < self.master {
            let c = self.ppu.dot_clocks() as u64;
            self.ppu.step_dot();
            self.ppu_t += c;
            let out = self.timing.on_dot(&mut self.mmio, &mut self.joy, &self.ppu, self.ppu_t);
            if out.hdma_init { self.pending_hdma_init = true; }
            if out.hdma_run { self.pending_hdma_run = true; }
            if out.vblank_start { self.vblank_flag = true; self.vblank_count += 1; }
        }
        self.apu.step_to(self.master);
    }
    fn begin_cycle(&mut self) {}      // E03-30, E03-33
    fn end_cycle(&mut self) {}        // E03-32
}
impl crate::cpu::Bus for SysBus {
    fn read(&mut self, addr: u32) -> u8 { let addr = addr & 0xFF_FFFF; self.begin_cycle(); self.advance(access_clocks(addr, self.memsel)); let v = self.read_inner(addr); self.mdr = v; self.end_cycle(); v }
    fn write(&mut self, addr: u32, v: u8) { let addr = addr & 0xFF_FFFF; self.begin_cycle(); self.advance(access_clocks(addr, self.memsel)); self.mdr = v; self.write_inner(addr, v); self.end_cycle(); }
    fn idle(&mut self) { self.begin_cycle(); self.advance(6); self.end_cycle(); }
    fn nmi_pending(&mut self) -> bool { self.timing.take_nmi_edge() }
    fn irq_asserted(&mut self) -> bool { self.mmio.irq_line }
}
```
Les tests importent le trait: `use puce16_core::cpu::Bus;`. Rappel de la regle d'ordonnancement: un dot s'execute quand `master > debut du dot` (STRICT). Dans les tests: `mod common; use common::*;` puis `fn mk(code: &[u8]) -> SysBus { SysBus::new(Cart::from_bytes(&make_rom(code, Map::LoRom)).unwrap(), Region::Ntsc) }` (imports: `puce16_core::bus::SysBus`, `puce16_core::cart::Cart`, `puce16_core::Region`).

## 2. Flux de temps

```rust
impl SysBus {
    fn advance(&mut self, clocks: u32) { self.master += clocks as u64; self.catch_up(); }
    fn catch_up(&mut self) {
        while self.ppu_t < self.master {                 // le dot s'execute quand master > debut du dot (strict)
            let c = self.ppu.dot_clocks() as u64;        // duree du dot courant
            let _ev = self.ppu.step_dot();
            self.ppu_t += c;
            // la position (ppu.v(), ppu.dot()) est maintenant celle du dot qui COMMENCE a ppu_t
            self.timing.on_dot(&mut self.mmio, &mut self.joy, &self.ppu, self.ppu_t);   // renvoie TimingOut
            ... stocker les drapeaux pending_hdma_init / pending_hdma_run
        }
        self.apu.step_to(self.master);                   // E06 (squelette avant)
    }
}
```
`Timing::on_dot` est une fonction position-dependante; elle ne fait aucun acces bus. `TimingOut { hdma_init: bool, hdma_run: bool, vblank_start: bool, frame_end: bool }`.

### 2.1 Cycle CPU (impl Bus pour SysBus)
```
fn read(addr):   begin_cycle(); advance(access_clocks(addr, memsel)); v = read_inner(addr); mdr = v (sauf registres a open bus partiel, voir read_inner); end_cycle(); v
fn write(addr,v): begin_cycle(); advance(access_clocks(..)); mdr = v; write_inner(addr, v); end_cycle()
fn idle():       begin_cycle(); advance(6); end_cycle()
begin_cycle: (1) rafraichissement DRAM (3.3 de 02): si !refreshed_this_line et (master - line_start) >= DRAM_REFRESH_HCLOCK: advance(40); refreshed_this_line = true
             (2) si pending_hdma_init ou pending_hdma_run: executer HDMA (voir section 5), puis effacer les drapeaux
end_cycle:   si pending_dma != 0: executer le DMA general (section 4) puis pending_dma = 0
```
(Le DMA part donc apres le cycle qui suit l'ecriture de MDMAEN: en pratique apres la lecture de l'opcode suivant, comme la spec 03 section 3.1.)
Les lignes d'interruption pour le CPU: `nmi_pending()` = front NMI detecte par `Timing` (consomme); `irq_asserted()` = `mmio.irq_line`.

### 3.4 Avance du temps par le bus
`Bus::read(addr)`: `t = access_clocks(addr)`; applique refresh si necessaire; **le temps passe en deux parties**: les 6/8/12 clocks sont decoupes ainsi: lecture de la valeur a `master + (t - 4)`... `UNKNOWN - to confirm` le point d'echantillonnage exact dans le cycle. Valeur de depart simple: lecture/ecriture effectuee a la **fin** du cycle (apres avoir fait avancer `master` de `t` clocks et appele `catch_up`). Les effets de bord PPU/MMIO sont donc vus a l'instant `master_end`. Un ecart de quelques clocks peut etre corrige plus tard par E03-T (tuning) sans changer l'architecture.

## Tests
Tous les tests sont prefixes par `e03_29_`.

- `e03_29_idle_time` : `Bus::idle(&mut bus)` -> master==6 et `ppu.dot()==2` (dots 0 et 1 executes) ; un 2eme idle -> master==12, `ppu.dot()==3`.
- `e03_29_read_costs` : `Bus::read(&mut bus, 0x008000)==0xA9` (ROM `mk(&[0xA9])`) -> master==8, mdr==0xA9 ; ensuite `read(0x002100)` -> master==14 ; `read(0x004016)` -> 26 ; `read(0x000000)` -> 34.
- `e03_29_write_costs_and_mdr` : `Bus::write(&mut bus, 0x000010, 0x44)` -> `wram.read(0x10)==0x44`, mdr==0x44, master==8 ; `Bus::write(&mut bus, 0x002100, 0x80)` -> master==14.
- `e03_29_memsel_fast` : `bus.memsel=true`: `Bus::read(&mut bus, 0x808000)` -> master==6 ; `Bus::read(&mut bus, 0x008000)` -> +8.
- `e03_29_addr_masked` : `Bus::read(&mut bus, 0x01008000)` se comporte comme `0x008000` (masque 24 bits).
- `e03_29_line_boundary` : `bus.advance(1360)`: `ppu.v()==0` et `ppu.dot()==339` (le dot 339 commence a 1360, il n'est pas encore execute) ; `bus.advance(1)` de plus : `ppu.v()==1` et `ppu.dot()==0` (le dot 339 est execute des que master > 1360). Sur un autre bus neuf: `advance(1364)` d'un coup donne aussi (1,0).
- `e03_29_vblank_flag_strict` : `bus.advance(306_904)`: `take_vblank_flag()==false` (le dot (225,1) commence a 306904, il n'est pas encore execute) ; `bus.advance(1)`: `take_vblank_flag()==true` puis false ; `vblank_count()==1` et `mmio.rdnmi_flag==true`.
- `e03_29_nmi_pending_consumed` : `bus.mmio.nmitimen=0x80`; `advance(306_904)`: `Bus::nmi_pending(&mut bus)==false` ; `advance(1)`: `nmi_pending()==true` ; 2eme appel: false.
- `e03_29_irq_level` : `bus.mmio.irq_line=true`: `Bus::irq_asserted(&mut bus)==true` deux fois de suite (niveau, non consomme) ; `irq_line=false` -> false.
- `e03_29_frame_length` : `bus.advance(357_368)`: `ppu.v()==0`, `ppu.dot()==0`, `ppu.field()==true`, `vblank_count()==1`.
- `e03_29_time_is_monotonic` : 60 appels `Bus::read(&mut bus, 0x008000)`: master==480 exactement (480 < 538: aucun rafraichissement DRAM meme apres E03-30) ; `ppu.v()==0`, `ppu.dot()==120`.
