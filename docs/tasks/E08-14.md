## Specification
Ajoute a `run <ROM>` : `--save-state <FICHIER>` (apres l'execution des `--frames` frames, ecrit `Snes::save_state()` dans le fichier ; erreur d'ecriture -> stderr `cannot write <chemin>: <err>`, code 2) et `--load-state <FICHIER>` (lu AVANT d'executer les frames, juste apres `Snes::new_with` : fichier illisible -> stderr `cannot read <chemin>: <err>`, code 2 ; `load_state` en erreur -> stderr `cannot load state: <StateError>`, code 2). Les deux options sont refusees (code 2, stderr `--save-state needs a ROM`) avec `--test-pattern`. Les sorties (`--hash`, `--state-hash`, `--debug`) viennent apres.

## 6. CLI (`puce16-cli`)

```
puce16-cli run <rom> [--frames N] [--region ntsc|pal] [--hash] [--trace FILE]
                     [--dump-ppm FILE] [--save-state FILE] [--load-state FILE]
puce16-cli suite <manifest.toml> [--update-baseline]
puce16-cli cpu-test <dossier_json_65816> [--filter NN]     # SingleStepTests
puce16-cli spc-test <dossier_json_spc700> [--filter NN]
```

Codes de sortie: 0 = OK, 1 = echec de test, 2 = erreur d'usage/fichier.
Tout echec imprime `DebugSnapshot` (PC/A/X/Y/S/D/DB/P, H/V, master).

## Tests
Tous les tests sont prefixes par `e08_14_`.

- `e08_14_save_then_load_matches` : ROM `tiny_rom()` (voir E03-44) dans un dossier temporaire : `run ROM --frames 3 --save-state S` (code 0, fichier S de plus de 1 Mo) ; `run ROM --frames 2 --load-state S --state-hash` donne le meme `state_hash` que `run ROM --frames 5 --state-hash` (3+2 frames).
- `e08_14_missing_state_file` : `--load-state /nonexistent/s` -> code 2, stderr contient `cannot read`.
- `e08_14_bad_state_file` : fichier de 10 octets aleatoires en `--load-state` -> code 2, stderr contient `cannot load state`.
- `e08_14_unwritable_save` : `--save-state /nonexistent/dir/s` -> code 2, stderr contient `cannot write`.
- `e08_14_pattern_refused` : `run --test-pattern --save-state S` -> code 2, stderr contient `needs a ROM`.
