## Specification
0. REGLE DE SORTIE: ne jamais afficher la sortie complete de l'oracle (elle peut faire des milliers de lignes). Toujours rediriger vers un fichier, puis lire seulement le debut:
   `cargo run -q -p puce16-cli -- cpu-test tests/oracle/65816 --filter 61,63,65,67,69,6D,6F,71,72,73,75,77,79,7D,7F > target/oracle_out.txt 2>&1` puis lire les 40 premieres lignes de `target/oracle_out.txt` (outil de lecture de fichier avec limite, ou `python -c "print(''.join(open('target/oracle_out.txt').readlines()[:40]))"`).
   La derniere ligne du fichier est `files: N ok: K failed: F`.
1. Lancer (avec redirection, regle 0): `cargo run -q -p puce16-cli -- cpu-test tests/oracle/65816 --filter 61,63,65,67,69,6D,6F,71,72,73,75,77,79,7D,7F`
2. Si `failed: 0`: aller a l'etape 5.
3. Sinon travailler UN OPCODE A LA FOIS: prendre le premier `FAIL` du fichier, relancer SEULEMENT cet opcode (`cargo run -q -p puce16-cli -- cpu-test tests/oracle/65816 --filter <UN_SEUL_OPCODE_HEX>`, toujours redirige vers le fichier), lire le premier diff (champ ou cycle fautif), corriger dans les fichiers autorises. Ne pas modifier addr/ (modes valides depuis E02-17): si un echec vient clairement d'un mode, poser une question `bug`.
4. Apres chaque correction, relancer le groupe complet (etape 1) et recommencer. Maximum 6 opcodes corriges dans cette tache: au-dela, ecrire `docs/qa/inbox/E02-26d-Q1.md` (type `bug`, liste des opcodes restants) et bloquer la tache.
   ADC DECIMAL 16 BITS: la version actuelle de `adc_decimal_n` est fausse (elle additionne en binaire puis corrige les chiffres). Lire `specs/data/bcd_reference.md` et recopier TELLE QUELLE la fonction `adc_decimal_n` dans `alu/adc.rs` (l'appel 8 bits passe `nibbles = 2`). Ne pas ecrire de variante. Si l'oracle contredit ENCORE cette reference, ecrire une question `spec` avec le premier test en echec (A, m, C, D attendus/obtenus).
5. Le fichier `tests/e02_26d_oracle_regressions.rs` contient TOUJOURS la fonction de test `e02_26d_oracle_clean_or_regressions` (elle verifie `Cpu::new().p == 0x34`), plus un test par bug corrige (nom `e02_26d_<instruction>_<cas>`).
6. Fin: `failed: 0` pour le groupe.
