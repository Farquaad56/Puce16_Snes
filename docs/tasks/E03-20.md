# E03-20 - dma/mod.rs: run_general sens B -> A et cas WRAM <-> $2180
Epopee: E03 | Type: code | Dependances: E03-19 | Taille estimee: ~100 lignes

## Contexte
Ajoute le sens B->A (bit 7 de DMAP) et la regle "WRAM <-> $2180 est ignore": quand l'adresse A est en WRAM et que le registre B vise $2180 (reg 0x80),
le transfert n'a aucun effet (rien n'est lu/ecrit cote B ou A, WMADD n'avance pas) mais le temps passe et les compteurs avancent. Detail `UNKNOWN - to confirm` (spec 03 section 3). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Modifie la boucle d'octet de `run_general` (dans l'ordre, pour chaque octet, APRES `bus.elapse(8)`):
```
regB = bbad.wrapping_add(offs[i % offs.len()])
wram_skip = regB == 0x80 && is_wram_addr(A)
if dmap & 0x80 == 0 {                       // A -> B
    if !wram_skip { v = bus.a_read(A); bus.b_write(regB, v); }
} else {                                    // B -> A
    if !wram_skip { v = bus.b_read(regB); bus.a_write(A, v); }
}
a1t = step_a(a1t, step); i += 1
```
(Dans le cas `wram_skip` en A->B on ne lit meme pas l'A-bus.) Les tests utilisent `FakeBus` (voir E03-19).

## 3. DMA general (MDMAEN $420B)

Ecriture non nulle: les canaux dont le bit est a 1 s'executent dans l'ordre 0..7. Le CPU est arrete pendant toute la duree.

Pour chaque canal actif, tant que le compteur n'est pas 0:
1. Lire un octet (source selon direction), ecrire a destination.
   - Direction A->B: lire A-bus `(A1Bn:A1Tn)`, ecrire B-bus `$2100 + ...`.
   - Direction B->A: lire B-bus, ecrire A-bus.
2. Passer a l'octet suivant du pattern (offset B suivant, cyclique sur la longueur du pattern).
3. Ajuster A1Tn (16 bits, la banque ne change jamais): mode 0: +1; mode 2: -1; modes 1 et 3: inchange.
4. Decrementer DASn (16 bits). A 0 -> fin du canal. Le transfert s'arrete meme au milieu d'un pattern.

Apres le canal: DASn = 0, A1Tn = adresse apres l'avance (wrap 16 bits dans la banque). Compteur initial 0 = 65536 octets.

Restrictions:
- L'adresse A-bus ne peut pas viser $2100-$21FF, $4000-$41FF, $4200-$421F, $4300-$437F (banques 00-3F/80-BF): ces acces sont ignores (lecture = open bus; ecriture = rien). `UNKNOWN - to confirm` le detail: defaut = lecture open bus (`mdr`), ecriture ignoree.
- DMA WRAM->$2180 : la lecture A-bus en WRAM n'a pas d'effet utile (rien n'est ecrit, adresse WMADD non incrementee). DMA $2180->WRAM: ecrit open bus; WMADD non incremente. (wiki)
- BBADn = $00 sur certaines revisions de CPU: ne pas emuler la panne; documenter seulement.
- DMA ne peut pas copier WRAM -> WRAM.

### 3.1 Timing DMA (cycle-accurate, valeurs par defaut)
- L'ecriture de MDMAEN fixe un drapeau "DMA en attente". Le DMA demarre **apres la lecture de l'opcode de l'instruction suivante** (le CPU ne se fait pas interrompre au milieu d'un cycle).
- Au demarrage: temps maitre aligne sur le multiple de 8 clocks suivant (`master_phase`; `UNKNOWN - to confirm` l'origine: defaut = origine de la ligne 0 de la frame), puis **8 clocks de surcout**.
- Par canal actif: **8 clocks** de surcout de canal.
- Par octet transfere: **8 clocks**.
- A la fin: **le CPU reprend apres un alignement sur son prochain cycle** (6/8/12 clocks selon l'adresse du cycle suivant): `UNKNOWN - to confirm`; defaut: pas de realignement supplementaire.
- HDMA peut interrompre un DMA general: le DMA est mis en pause pendant l'execution de HDMA (voir 4).
- Les composants PPU/APU/timers avancent normalement pendant le DMA (via `catch_up`). Le CPU ne s'execute pas.

## Tests
Tous les tests sont prefixes par `e03_20_`.

- `e03_20_b_to_a` : dmap=0x80, bbad=0x39, a1b=0x7E, a1t=0x3000, das=2: `a_writes()==[(0x7E3000,1),(0x7E3001,2)]` ; `count_b_reads()==2` ; `a1t==0x3002` ; `das==0`.
- `e03_20_b_to_a_p1` : dmap=0x81, bbad=0x39, das=4: les `BRead` visent les regs 0x39,0x3A,0x39,0x3A ; valeurs ecrites en A: 1,2,3,4.
- `e03_20_b_to_a_decrement` : dmap=0x90, a1t=0x3001, das=2: ecritures A a 0x7E3001 puis 0x7E3000.
- `e03_20_wram_skip_a_to_b` : dmap=0x00, bbad=0x80, a1b=0x7E, a1t=0x1000, das=3: AUCUN `BWrite` et AUCUN `ARead` ; `a1t==0x1003` ; `bus.master==40` (le temps passe quand meme).
- `e03_20_wram_skip_mirror` : meme test avec a1b=0x00, a1t=0x0100 (miroir WRAM) et avec a1b=0x01, a1t=0x1000 (das=3, reste < 0x2000): aucun BWrite.
- `e03_20_rom_not_skipped` : bbad=0x80, a1b=0xC0, a1t=0x8000 (ROM): les `BWrite(0x80, ..)` ont lieu (3 pour das=3).
- `e03_20_wram_skip_b_to_a` : dmap=0x80, bbad=0x80, a1b=0x7E, das=2: aucun `BRead`, aucun `AWrite` ; temps consomme ; `a1t` avance de 2.
- `e03_20_skip_per_transfer_reg` : dmap=0x01 (P1), bbad=0x7F, a1b=0x7E, das=4: les transferts vers reg 0x80 (offsets 1) sont ignores, ceux vers 0x7F ont lieu: `b_writes()` contient exactement 2 ecritures, toutes a reg 0x7F ; `a1t` avance de 4.
- `e03_20_a_to_b_regression` : dmap=0x00, bbad=0x18, a1b=0x7E, a1t=0x1000, das=3 : meme resultat que E03-19 `p0_basic`.
