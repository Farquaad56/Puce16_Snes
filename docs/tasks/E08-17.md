## Specification
Ajoute dans `audio.rs`:
```rust
pub const SRC_RATE: u32 = 32_040;
pub struct Playback { rs: Resampler, pending: std::collections::VecDeque<[f32; 2]>, last: [f32; 2], scratch: Vec<[i16; 2]> }
impl Playback {
    pub fn new(device_rate: u32) -> Playback;       // Resampler::new(SRC_RATE, device_rate), last = [0,0]
    /// Remplit `out` (entrelace, `channels` canaux). volume 0.0..=1.0.
    pub fn render(&mut self, ring: &mut AudioRing, volume: f32, muted: bool, channels: usize, out: &mut [f32]);
}
```
`render`: `frames = out.len() / channels` ; tant que `pending.len() < frames` : lire dans l'anneau au plus `(frames - pending.len()) * SRC_RATE / device_rate + 16` trames (min 16) dans `scratch` ; si 0 trame lue : sous-alimentation -> pousser `last` dans `pending` jusqu'a `frames` et arreter ; sinon convertir (`x as f32 / 32768.0`), `rs.process`, ajouter a `pending`. Ensuite, pour chacune des `frames` trames retirees de `pending` : `last = trame` ; `l, r` = trame * volume (0 si `muted`) ; 1 canal -> `(l + r) / 2` ; 2 canaux -> `l, r` ; plus de 2 -> `l, r` puis des zeros. Si `channels == 0` ou `out` vide : ne rien faire.

## 5. Audio (`cpal`)

- Le core produit des echantillons stereo `[i16; 2]` a ~32 040 Hz (`Snes::take_audio`). Le thread audio consomme un anneau (`Vec<[i16;2]>` circulaire, capacite 8192 trames).
- Re-echantillonnage vers la frequence du peripherique par interpolation sinc fenetree (Hann), 16 points, en `f32` (autorise ici). Volume 0..100 % applique en sortie. Muet = silence.
- Latence cible 60 ms (anneau ~ 2000 trames pleines). Sous-alimentation: repeter le dernier echantillon ; sur-alimentation (anneau > `RING_WAIT_ABOVE` = 3072 trames, ~96 ms; constante reglable): le thread d'emulation attend par pas de 1 ms, au plus 100 ms par frame (c'est l'horloge de synchronisation).
- Pas de peripherique audio: l'emulation continue avec le minuteur (message dans la barre d'etat).

## Tests
Tous les tests sont prefixes par `e08_17_`.

- `e08_17_constant_stereo` : anneau rempli de 4000 trames `[16384,16384]`, `Playback::new(48000)`, `render(vol 1.0, !muted, 2, out[512*2])` : apres les 16 premieres trames, toutes les valeurs sont a moins de 0.01 de 0.5.
- `e08_17_volume_scales` : meme avec volume 0.5 -> valeurs proches de 0.25 (apres warmup).
- `e08_17_muted_is_silent` : meme avec `muted=true` -> toutes les valeurs exactement 0.0 ; l'anneau a quand meme ete consomme (`len()` a diminue).
- `e08_17_mono_downmix` : anneau `[16384, -16384]` constant, 1 canal : valeurs proches de 0.0 (moyenne) apres warmup ; avec `[16384, 0]` -> proches de 0.25.
- `e08_17_six_channels` : anneau `[16384,16384]`, `channels=6`: pour chaque trame, indices 0 et 1 proches de 0.5 (apres warmup) et indices 2..6 exactement 0.0.
- `e08_17_underrun_repeats_last` : anneau avec 100 trames `[16384,16384]`, `Playback::new(32040)`, `render` de 600 trames stereo : les dernieres 50 trames valent exactement la derniere valeur produite avant la sous-alimentation (aucun saut a 0).
- `e08_17_empty_ring_start_is_silent` : anneau vide, `render` -> toutes les valeurs 0.0 (last initial = 0).
- `e08_17_consumption_rate` : `Playback::new(48000)`, anneau de 8000 trames : un `render` de 4800 trames consomme entre 3 200 et 3 260 trames de l'anneau.
- `e08_17_zero_channels_noop` : `render(.., channels=0, out)` ne panique pas et ne touche pas a l'anneau.
