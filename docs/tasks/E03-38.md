## Specification
Vecteur IRQ -> 0x8100 (`set_vector("irq", 0x8100)`). Handler `HANDLER_IRQ` a l'offset 0x100: `AD 11 42  EE 03 01  40` = LDA $4211 (acquitte) ; INC $0103 ; RTI.
- `PROG_H` (mode 1, HTIME=100): `78 18 FB  9C 03 01  A9 64  8D 07 42  9C 08 42  A9 10  8D 00 42  58  80 FE`.
- `PROG_V` (mode 2, VTIME=100): `78 18 FB  9C 03 01  A9 64  8D 09 42  9C 0A 42  A9 20  8D 00 42  58  80 FE`.
- `PROG_HV` (mode 3, HTIME=50, VTIME=100): `78 18 FB  9C 03 01  A9 32  8D 07 42  9C 08 42  A9 64  8D 09 42  9C 0A 42  A9 30  8D 00 42  58  80 FE`.
- `PROG_V_MASKED` = `PROG_V` avec `58` (CLI) remplace par `EA` (NOP): l'IRQ reste masque. Chaque fichier de test commence par `mod common; #[path = "common/prog.rs"] mod prog;` (et `#[path = "common/fake_dma_bus.rs"]` n'est pas utile ici), puis `use puce16_core::snes::Snes; use prog::build_rom;`. Helper de test: `fn snes(rom: Vec<u8>) -> Snes { Snes::new(&rom, None).ok().unwrap() }`. Les programmes sont du code machine 65816 assemble A LA MAIN (octets donnes); l'adresse CPU de l'octet i du programme est 0x8000 + i. `settle(&mut s)` = `for _ in 0..12 { s.step_instruction(); }` (laisse le temps au CPU de prendre une interruption apres `run_frame`).

### 6.3 IRQ timer (H/V)
- Condition evaluee **a chaque dot** (en pratique: a chaque avance de H):
  - mode 1 (V=0,H=1): vrai quand `H == HTIME` (a chaque ligne);
  - mode 2 (V=1,H=0): vrai quand `V == VTIME` et `H == 0`;
  - mode 3: `V == VTIME` et `H == HTIME`.
- Quand la condition passe de faux a vrai: TIMEUP.7 = 1 (flag) et la ligne IRQ du CPU = 1 (maintenue jusqu'a lecture de $4211 ou jusqu'a ce que NMITIMEN V/H = 00; ecrire NMITIMEN avec V/H=00 efface le flag et la ligne).
- Decalage H reel (IRQ declenche ~ quelques dots apres H==HTIME): `IRQ_H_DELAY` defaut 4 clocks? `UNKNOWN - to confirm`.
- HTIME > 339 ou VTIME > derniere ligne: ne se declenche jamais.
- V=0 H=0 (modes 2,3): decale d'un dot sur certaines revisions: ignorer en v1.

## Tests
Tous les tests sont prefixes par `e03_38_`.

- `e03_38_irq_h_every_line` : PROG_H + handler + vecteur irq: un `run_frame()` (jusqu'au VBlank, ligne 225): `peek_wram(0x103)` est entre 224 et 225 inclus (un IRQ par ligne 0..=224).
- `e03_38_irq_v_once_per_frame` : PROG_V: pour k = 1..=3: `run_frame()` puis `peek_wram(0x103)==k` (IRQ a la ligne 100, bien avant le VBlank).
- `e03_38_irq_hv_once_per_frame` : PROG_HV: pour k = 1..=3: `run_frame()` puis `peek_wram(0x103)==k`.
- `e03_38_irq_masked_by_i` : PROG_V_MASKED: 2 frames: `peek_wram(0x103)==0` (le niveau IRQ reste a 1 mais I=1).
- `e03_38_irq_not_before_line_100` : PROG_V: `run_master(1364*99)` (sans atteindre la ligne 100): `peek_wram(0x103)==0` ; puis `run_master(1364*3)`: `peek_wram(0x103)==1`.
- `e03_38_irq_position` : PROG_V: au retour de `run_master(1364*100 + 400)` l'IRQ de la ligne 100 a deja eu lieu: `peek_wram(0x103)==1` ; `debug().v==100`.
- `e03_38_irq_ack_prevents_retrigger` : PROG_V: apres la 1re frame, `peek_wram(0x103)==1` exactement (pas de re-declenchement sur la meme ligne tant que le handler acquitte).
- `e03_38_irq_without_ack_loops` : handler SANS acquittement (`EE 03 01  40`, sans le `AD 11 42`) avec PROG_V : le niveau IRQ reste vrai, le CPU reprend l'IRQ des le retour du handler : apres `run_master(1364*103)`, `peek_wram(0x103) > 10` (boucle d'IRQ). (Preuve que l'IRQ est un NIVEAU.)
