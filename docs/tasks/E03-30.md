Le CPU est arrete 40 clocks par ligne a hclock >= 538 (`UNKNOWN - to confirm`, constante `DRAM_REFRESH_HCLOCK`). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Dans `begin_cycle`: `if self.timing.refresh_due(self.master) { self.timing.mark_refreshed(); self.advance(DRAM_REFRESH_CLOCKS); }` avec `use crate::consts::DRAM_REFRESH_CLOCKS` (=40).
IMPORTANT: marquer AVANT d'avancer: `advance` peut franchir la fin de ligne, et `on_dot` (dot 0) remet alors le drapeau a faux; marquer apres l'avance annulerait ce reset.
 Dans les tests: `mod common; use common::*;` puis `fn mk(code: &[u8]) -> SysBus { SysBus::new(Cart::from_bytes(&make_rom(code, Map::LoRom)).unwrap(), Region::Ntsc) }` (imports: `puce16_core::bus::SysBus`, `puce16_core::cart::Cart`, `puce16_core::Region`).

### 3.3 Rafraichissement DRAM
Le CPU est arrete 40 clocks par ligne: quand un cycle CPU commencerait a `hclock >= DRAM_REFRESH_HCLOCK` et que le refresh de la ligne n'a pas eu lieu, on insere 40 clocks (le cycle est decale). Les autres composants (PPU, APU, DMA HDMA) continuent. `UNKNOWN - to confirm` position exacte (538 par defaut) et alignement.

### 2.1 Cycle CPU (impl Bus pour SysBus)
```
fn read(addr):   begin_cycle(); advance(access_clocks(addr, memsel)); v = read_inner(addr); mdr = v (sauf registres a open bus partiel, voir read_inner); end_cycle(); v
fn write(addr,v): begin_cycle(); advance(access_clocks(..)); mdr = v; write_inner(addr, v); end_cycle()
fn idle():       begin_cycle(); advance(6); end_cycle()
begin_cycle: (1) rafraichissement DRAM (3.3 de 02): si !refreshed_this_line et (master - line_start) >= DRAM_REFRESH_HCLOCK: advance(40); refreshed_this_line = true
             (2) si pending_hdma_init ou pending_hdma_run: executer HDMA (voir section 5), puis effacer les drapeaux
end_cycle:   si pending_dma != 0: executer le DMA general (section 4) puis pending_dma = 0
```
(Le DMA part donc apres le cycle qui suit l'ecriture de MDMAEN: en pratique apres la lecture de l'opcode suivant, comme la spec 03 section 3.1.)
Les lignes d'interruption pour le CPU: `nmi_pending()` = front NMI detecte par `Timing` (consomme); `irq_asserted()` = `mmio.irq_line`.

## Tests
Tous les tests sont prefixes par `e03_30_`.

- `e03_30_refresh_once_per_line` : `bus.advance(536)` ; `Bus::idle` (hclock 536 < 538: pas de refresh) -> master==542 ; 2eme `idle` : refresh (hclock 542 >= 538): +40 +6 -> master==588 ; 3eme `idle` -> 594 (une seule fois).
- `e03_30_refresh_next_line` : apres le test precedent: `bus.advance(1364 + 538 - bus.master)` (master==1902) ; `Bus::idle` -> refresh a nouveau: master==1902+40+6==1948.
- `e03_30_no_refresh_early` : sur la ligne 0 depuis master 0: 80 `idle` (480 clocks) -> master==480 exactement.
- `e03_30_refresh_crossing_line` : bus neuf, aucun cycle encore: `bus.advance(1360)` (hclock 1360 sur la ligne 0, refresh de la ligne 0 non consomme) ; `Bus::idle` : refresh (+40 -> 1400, franchit la fin de ligne 1364) puis +6 -> master==1406 ; `ppu.v()==1`. Le refresh a ete marque AVANT l'avance donc `on_dot` (dot 0 de la ligne 1) a remis le drapeau a faux : `bus.timing.refresh_due(bus.master)` est FAUX car hclock vaut 42 (<538), et apres `bus.advance(538 - 42)` (hclock 538) il est VRAI.
- `e03_30_read_triggers_refresh` : `bus.advance(540)` ; `Bus::read(&mut bus, 0x008000)` -> master==540+40+8==588.
- `e03_30_hundred_reads_with_refresh` : 100 lectures ROM depuis master 0: master==840 (les 68 premieres lectures finissent a 544 ; la 69eme commence a 544 >= 538 -> +40 ; au total 800 + 40) ; `ppu.v()==0`.
