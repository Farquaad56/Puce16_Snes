# E03-46 - Desktop: emu_thread LoadRom, Reset reel, Event::Error
Epopee: E03 | Type: code | Dependances: E03-45 | Taille estimee: ~140 lignes

## Contexte
Le thread d'emulation sait maintenant remplacer son `Snes` par un `Snes` reel (commande `LoadRom`). Une erreur de chargement ou une panique d'emulation est rapportee par `Event::Error` sans tuer le thread.
Comme un variant est ajoute a `Event`, `app.rs` doit rester compilable (traite `Event::Error`). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Modifie `emu_thread.rs` (en gardant le comportement de E01-09):
- `Command` gagne `LoadRom(Vec<u8>, String)` (octets, nom affiche). `Event` gagne `Error(String)`.
- `LoadRom(bytes, name)`: `Snes::new(&bytes, None)`. `Ok(s)`: remplace le `Snes` ; re-applique les derniers `SetJoypad` recus (le thread garde `joy: [u16;2]`) ; `frame_no` repart de 0 ; `paused = false` ; envoie `Event::Status(format!("Loaded {} ({:?}, {:?})", name, info.map, info.region))` avec `info = snes.cart_info().unwrap()`. `Err(e)`: envoie `Event::Error(format!("cannot load {}: {}", name, <message>))` ou `<message>` = "ROM too small" / "no valid ROM header found" / "unsupported coprocessor: <n>" ; l'ancien `Snes` est conserve et l'etat de pause inchange.
- `Reset` appelle desormais `snes.reset()` (motif ou reel) puis remet `frame_no` a 0.
- Chaque `run_frame()` est protege par `std::panic::catch_unwind(AssertUnwindSafe(..))` : en cas de panique, envoyer `Event::Error("emulator panic: <message>")`, passer en pause, et ne plus appeler `run_frame` tant que l'utilisateur n'a pas fait `Reset` ou `LoadRom`.
Dans `app.rs`: ajouter le bras `Event::Error(e) => self.status = format!("ERROR: {}", e)` (match exhaustif). Aucune autre modification de l'UI dans cette tache.
ROM minimale pour les tests (LoROM, 32 Kio, boucle infinie): `fn tiny_rom() -> Vec<u8> { let mut r = vec![0u8; 0x8000]; r[0] = 0x80; r[1] = 0xFE; r[0x7FFC] = 0x00; r[0x7FFD] = 0x80; r }` (BRA -2 a 0x8000, vecteur RESET 0x8000; l'unique candidat d'en-tete est LoROM). Elle reste en mode emulation. `Event` n'implemente pas `PartialEq` : utilise `matches!`.

## 7. Architecture desktop

- Thread d'emulation (`emu_thread.rs`) possede `Snes` ; thread UI (egui) envoie des `Command` (`std::sync::mpsc`): `LoadRom(Vec<u8>, path)`, `Reset`, `Pause(bool)`, `FrameAdvance`, `SetJoypad(port, u16)`, `SaveState(slot)`, `LoadState(slot)`, `SetFastForward(bool)`, `RequestDebug(bool)`, `Quit`.
- Le thread d'emulation publie `Event` : `Frame(Arc<FrameData>)` (largeur, hauteur, pixels), `Status(String)`, `Debug(Box<DebugData>)` (seulement si demande), `SramDirty`, `Error(String)`.
- Boucle: tant que non en pause: `run_frame()` ; pousser l'audio ; publier la frame ; attendre selon la synchro. Une frame est publiee par frame emulee (la UI affiche la plus recente).
- Aucun etat d'emulation n'est partage par verrou avec la UI: tout passe par canaux.

## Tests
Tous les tests sont prefixes par `e03_46_`.

- `e03_46_load_ok_status` : `spawn_test_pattern(Ntsc, true)` ; envoie `LoadRom(tiny_rom(), "tiny.sfc".into())` : on recoit (timeout 2 s) un `Event::Status` contenant `Loaded tiny.sfc` et `LoRom`.
- `e03_46_load_ok_black_frame` : suite: `FrameAdvance` -> `Event::Frame` avec `frame_no==1`, `width==256`, `height==224` et le pixel (0,0) == 0xFF000000 (le motif de test avait un pixel colore).
- `e03_46_load_resumes_running` : `spawn_test_pattern(Ntsc, true)` (en pause), `LoadRom(tiny_rom(), ..)` : au moins 2 `Event::Frame` sont recus sans envoyer `FrameAdvance` (le chargement leve la pause).
- `e03_46_load_error_keeps_old` : `LoadRom(vec![0u8;10], "bad.sfc".into())` : `Event::Error` contenant `cannot load bad.sfc` et `ROM too small` ; puis `FrameAdvance` produit toujours une frame (le motif de test d'avant continue).
- `e03_46_reset_real` : apres `LoadRom` valide et deux `FrameAdvance` (frame_no 1 puis 2) : `Reset` puis `FrameAdvance` donne `frame_no==1`.
- `e03_46_joypad_survives_load` : `SetJoypad(0, 0x8000)` AVANT `LoadRom`: le chargement ne plante pas (pas de verification visuelle: la ROM minimale ne lit pas la manette).
- `e03_46_quit_after_load` : `quit()` apres `LoadRom` retourne en < 1 s sans panique.
