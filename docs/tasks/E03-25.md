### 6.4 Auto-read joypad
- Si NMITIMEN.0 = 1: au debut du VBlank (V = vblank_start), a partir de `H >= 32.5 dots` (defaut: clock 130 = ligne V, hclock 130; `UNKNOWN - to confirm` entre H=32.5 et 95.5), l'auto-read dure **4224 master clocks**; pendant ce temps HVBJOY.0 = 1.
- Au debut: equivalent a JOYOUT=1 puis 0 (latch). Puis 16 lectures de $4016 et $4017: JOY1 (bits D0 du port 1) , JOY2 (bits D0 du port 2), JOY3 (bits D1 port 1), JOY4 (bits D1 port 2); le 1er bit lu = bit 15.
- Defaut v1: les registres JOYn sont mis a jour **a la fin** des 4224 clocks (pendant l'operation, ils conservent l'ancienne valeur). `UNKNOWN - to confirm`.
- Les manettes standard (voir joypad ci-dessous) renvoient apres 16 bits: 1.

## 5. HDMA: declenchement
- `pending_hdma_init`: `Timing` renvoie `hdma_init` a (v == 0, dot == HDMA_INIT_DOT) si `mmio.hdmaen != 0` (valeur au moment du declenchement).
- `pending_hdma_run`: `hdma_run` a (v in 0..=vis_last, dot == HDMA_RUN_DOT) si `mmio.hdmaen != 0`.
- Execution dans `begin_cycle`: init: `dma.hdma_init(self, mmio.hdmaen)`; run: `dma.hdma_run_line(self, mmio.hdmaen)`. Surcout: `bus.elapse(18)` (une fois par appel) + 8 par canal actif + 8 par octet (spec 03 4.3), appliques par le moteur HDMA.
- Un canal HDMA actif est un canal dont le bit est dans `hdmaen` et dont `done == false`.

## 8. Algorithme de `Timing::on_dot` (position = (ppu.v(), ppu.dot()) APRES le step, `t` = debut de ce dot)
Dans cet ordre:
1. `dot == 0`: `line_start = t`; `refreshed_this_line = false`. Si de plus `v == 0`: `out.frame_end = true`; `mmio.rdnmi_flag = false` (fin du VBlank).
2. `v == ppu.vblank_start() && dot == NMI_FLAG_DOT`: `mmio.rdnmi_flag = true`; `out.vblank_start = true`.
3. Ligne NMI: `line = mmio.rdnmi_flag && (mmio.nmitimen & 0x80 != 0)`; si `line && !nmi_line_prev`: `nmi_edge = true`; `nmi_line_prev = line`.
4. IRQ H/V: `mode = (mmio.nmitimen >> 4) & 3`; si `mode != 0`: mode 1: `dot == htime + IRQ_H_OFFSET_DOTS`; mode 2: `v == vtime && dot == IRQ_H_OFFSET_DOTS`; mode 3: `v == vtime && dot == htime + IRQ_H_OFFSET_DOTS` ; `htime > 339` ou `vtime > derniere ligne` : jamais. Si vrai: `mmio.timeup_flag = true; mmio.irq_line = true`.
5. Auto-read: si `nmitimen & 1 != 0 && v == vblank_start && dot == AUTOREAD_START_DOT`: `autoread_end = Some(t + AUTOREAD_CLOCKS)`. Puis, si `autoread_end == Some(e)` et `t >= e`: `mmio.joy = joy.autoread_values()`; `autoread_end = None`.
6. HDMA: `mmio.hdmaen != 0`: `v == 0 && dot == HDMA_INIT_DOT` -> `out.hdma_init`; `v <= vis_last && dot == HDMA_RUN_DOT` -> `out.hdma_run`.
`mmio.read` de `$4210` efface `rdnmi_flag` ; de `$4211` efface `timeup_flag` ET `irq_line` ; `mmio.write(NMITIMEN)` avec bits V/H = 00 efface `timeup_flag` et `irq_line`.

## Tests
Tous les tests sont prefixes par `e03_25_`.

- `e03_25_autoread_updates_at_end` : `Rig::new(Ntsc)`; `mmio.nmitimen=1`; `joy.set_buttons(0,0x8001)`, `joy.set_buttons(1,0x0F00)`. `run_until(225,33)`: `mmio.joy==[0;4]` et `timing.autoread_busy(rig.t)==true`. Noter `t0=rig.t`. Continuer pas a pas jusqu'au 1er step apres lequel `mmio.joy[0]!=0` : `dt = rig.t - t0` verifie `4224 <= dt && dt < 4229` ; alors `mmio.joy==[0x8001,0x0F00,0,0]`, `autoread_busy(rig.t)==false`.
- `e03_25_autoread_busy_window` : avec nmitimen=1: `autoread_busy(t0 - 1)==false` (t0 = debut en (225,33)), `autoread_busy(t0)==true`, `autoread_busy(t0+4223)==true` ; apres le step qui met `mmio.joy` a jour: `autoread_busy(rig.t)==false`.
- `e03_25_shift_reset_after_autoread` : apres la mise a jour, `rig.joy.read_port(0)==1` (registre a 0xFFFF).
- `e03_25_autoread_disabled` : nmitimen=0: `run_until(230,0)` puis 2000 steps : `mmio.joy==[0;4]` et `autoread_busy` toujours faux.
- `e03_25_autoread_once_per_frame` : nmitimen=1, apres la mise a jour, changer `joy.set_buttons(0,0x0001)`: `mmio.joy` ne change plus avant la frame suivante ; sur la frame suivante, il prend 0x0001.
- `e03_25_hdma_off` : hdmaen=0: sur une frame, aucun `hdma_init`/`hdma_run`.
- `e03_25_hdma_init_once` : hdmaen=1: sur une frame (a partir de la position (0,0)): exactement un `hdma_init`, et c'est le step qui arrive en (0,3).
- `e03_25_hdma_run_count` : hdmaen=1, NTSC: 225 `hdma_run` par frame (v=0..=224, dot 276) ; avec `ppu.write(0x33,0x04)` (overscan): 240.
- `e03_25_hdma_run_position` : le 1er `hdma_run` arrive en (0,276) ; il n'y en a pas pour v>=225.
- `e03_25_hash_includes_autoread` : le hash de `Timing` differe pendant l'auto-read (apres (225,33)) et apres.
