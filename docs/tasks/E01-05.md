## Specification
Dans `ppu/output.rs` (conserve `FrameView<'a>` existant):
- `pub struct FrameBuf { pub pixels: Vec<u32> /* FB_WIDTH*FB_HEIGHT */, pub view_w: usize, pub view_h: usize }` ; `FrameBuf::new()` remplit de `0xFF000000`, view_w=256, view_h=224.
- `pub fn set(&mut self, col: usize, row: usize, argb: u32)` (ignore hors tampon) ; `pub fn get(&self, col, row) -> u32`.
- `pub fn set_view(&mut self, w: usize, h: usize)` (w dans {256,512}, h <= 478; sinon panic avec message).
- Le tampon interne est TOUJOURS large de `FB_WIDTH` (512) colonnes (stride 512). `pub fn compact(&self) -> Vec<u32>` copie la zone utile `view_w x view_h` depuis le coin haut-gauche (colonnes `0..view_w`, lignes `0..view_h`) vers un `Vec` de stride `view_w`. (Les frames 256 colonnes sont ecrites par le PPU dans les colonnes 0..255.)
- `pub fn pixel_double(src: &[u32], w: usize, h: usize) -> Vec<u32>` (fonction libre) : duplique chaque pixel horizontalement (`w` -> `2*w` colonnes), utilisee quand la frame est hi-res mais la ligne ne l'est pas.
- `pub fn make_view(w: usize, h: usize, pixels: &[u32]) -> FrameView<'_>` : construit la vue (panique si `pixels.len() != w*h`).
- `pub fn hash(&self, h: &mut crate::hash::Fnv64)` : ecrit `view_w`, `view_h` (u32) puis les pixels compacts (u32 little-endian, ligne par ligne).

## 6. Sortie: framebuffer

- Tampon interne fixe: `[u32; 512 * 478]`, pixel XRGB8888 avec octet haut `0xFF`: `0xFF000000 | r8 << 16 | g8 << 8 | b8`.
- Conversion finale d'un canal 5 bits `c5` (apres math et luminosite): `c5b = c5 * brightness / 15` (division entiere; brightness 0..15), puis `c8 = (c5b << 3) | (c5b >> 2)` (D-010). `forced_blank` -> `0xFF000000` (noir).
- Rangee de sortie: `row = if frame_interlaced { 2 * r + field_as_u8 } else { r }`. Les rangees de l'autre field gardent leur contenu precedent (image entrelacee complete = 448 ou 478 lignes).
- Colonne: mode 256: `x` (largeur utile 256). Mode hi-res (SETINI.3 ou BG mode 5/6, voir 05b section 12): colonnes `2x` (sous-ecran) et `2x+1` (ecran principal) dans le tampon 512.
- Si la ligne n'est pas hi-res mais que la frame l'est (`frame_hires` = au moins une ligne hi-res dans la frame courante), chaque pixel est duplique sur `2x`, `2x+1` a l'export.
- `FrameView` (spec 01_ARCHITECTURE section 5) est calcule au debut de VBlank (`v == vblank_start`): `width = if frame_hires {512} else {256}`, `height = (vis_last) * (if frame_interlaced {2} else {1})`, avec `frame_interlaced = interlace` lu a ce moment. `pixels` = copie compacte de la zone utile (stride = width). `Ppu::frame()` retourne la derniere frame complete.
- Les lignes non visibles ou ligne 0: non ecrites.

## Tests
Tous les tests sont prefixes par `e01_05_`.

- `e01_05_new_black` : `FrameBuf::new()`: 512*478 pixels egaux a 0xFF000000, `view_w==256`, `view_h==224`.
- `e01_05_set_get` : set(3,2,0xFF112233) puis get(3,2)==0xFF112233 ; set hors tampon (600,0) ne panique pas.
- `e01_05_compact_256` : avec view 256x2, set(0,0,A), set(255,0,B), set(0,1,C), set(255,1,D): compact() == [A, ..., B, C, ..., D] de longueur 512, compact()[255]==B, compact()[256]==C.
- `e01_05_pixel_double` : src = 256 pixels 0xFF000000|i (w=256,h=1): `pixel_double(&src,256,1)` a 512 elements et [2*i]==[2*i+1]==0xFF000000|i.
- `e01_05_make_view` : `make_view(2,2,&[1,2,3,4])` a width 2, height 2, pixels == [1,2,3,4] ; avec 3 pixels -> panique (`#[should_panic]`).
- `e01_05_hash_changes` : deux FrameBuf identiques ont le meme hash ; apres set(0,0,1) le hash differe.
