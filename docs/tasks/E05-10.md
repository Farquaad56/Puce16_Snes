# E05-10 - ppu/obj.rs: tailles, decodage d'un sprite et liste des 32 sprites d'une rangee
Epopee: E05 | Type: code | Dependances: E05-09 | Taille estimee: ~140 lignes

## Contexte
Debut des sprites (spec 05b section 6). Cette tache fait l'EVALUATION de la liste (quels sprites touchent la rangee `r`); la recuperation des pixels est en E05-11.
La rangee `r = v - 1` est la rangee de sortie (0 = premiere ligne visible). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'. Aides de test (a recopier dans le fichier de test): `fn put_vram(p: &mut Ppu, addr: u16, w: u16) { p.write(0x15,0x80); p.write(0x16,(addr & 0xFF) as u8); p.write(0x17,(addr >> 8) as u8); p.write(0x18,(w & 0xFF) as u8); p.write(0x19,(w >> 8) as u8); }` ; `fn put_cgram(p: &mut Ppu, i: u8, w: u16) { p.write(0x21,i); p.write(0x22,(w & 0xFF) as u8); p.write(0x22,(w >> 8) as u8); }`. Un `Ppu::new(Region::Ntsc)` neuf est en forced blank: toutes ces ecritures sont autorisees. Chaque test construit SA scene sur un `Ppu` neuf. Aides OAM (a recopier): `fn load_oam(p: &mut Ppu, img: &[u8; 544]) { p.write(0x02,0); p.write(0x03,0); for b in img.iter() { p.write(0x04,*b); } }` ; `fn spr(img: &mut [u8; 544], i: usize, x: i16, y: u8, tile: u8, attr: u8, large: bool) { img[i*4] = (x & 0xFF) as u8; img[i*4+1] = y; img[i*4+2] = tile; img[i*4+3] = attr; let sh = (i % 4) * 2; let hb = 512 + i / 4; img[hb] &= !(3u8 << sh); let x8 = ((x >> 8) & 1) as u8; img[hb] |= (x8 | if large { 2 } else { 0 }) << sh; }`. Une image OAM neuve est `[0u8; 544]`: ATTENTION, un sprite a zero a x = 0, y = 0, 8x8: il est visible aux rangees 1..=8. Pour sortir les sprites inutilises de la zone visible, utilise `fn hide_all(img: &mut [u8; 544]) { for i in 0..128 { spr(img, i, -200, 0, 0, 0, false); } }` (x = -200 : hors ecran pour toutes les tailles, donc jamais dans la liste, et different de -256 qui compte toujours); puis place les sprites voulus. Les regles d'attribut sont : `attr = V H PP CCC t` (bit 7 = V flip, bit 6 = H flip, bits 5-4 = priorite, bits 3-1 = palette, bit 0 = bit de table de noms).

## Specification
Dans `ppu/obj.rs`:
```rust
pub fn obj_dims(obj_size: u8, large: bool) -> (u8, u8);       // (largeur, hauteur) en pixels ; obj_size 0..=7 (> 7: comme 7)
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub struct Sprite { pub x: i16, pub y: u8, pub tile: u8, pub tbit: bool, pub pal: u8, pub prio: u8, pub hflip: bool, pub vflip: bool, pub large: bool }
impl Ppu {
    pub fn sprite(&self, i: usize) -> Sprite;                           // decode le sprite i (0..128) depuis l'OAM
    pub fn sprite_list(&self, r: u16) -> (Vec<u8>, bool);               // (indices dans l'ordre d'evaluation, depassement de 32)
}
```
`obj_dims(size, large)` (petit / grand) : 0 -> 8x8 / 16x16 ; 1 -> 8x8 / 32x32 ; 2 -> 8x8 / 64x64 ; 3 -> 16x16 / 32x32 ; 4 -> 16x16 / 64x64 ; 5 -> 32x32 / 64x64 ; 6 -> 16x32 / 32x64 ; 7 -> 16x32 / 32x32.
`sprite(i)` : octets de l'OAM basse `oam.byte(i*4 + k)` : k=0 X bits 7-0, k=1 Y, k=2 tuile, k=3 attribut `VHPP CCCt`. OAM haute : octet `512 + i/4`, bit `(i%4)*2` = X bit 8, bit `(i%4)*2 + 1` = grand. `x` = valeur 9 bits en signe : `x9 = lo | x8 << 8` ; `x = if x9 >= 256 { x9 - 512 } else { x9 }`. `tbit = attr & 1`, `pal = (attr >> 1) & 7`, `prio = (attr >> 4) & 3`, `hflip = attr & 0x40`, `vflip = attr & 0x80`.
`sprite_list(r)` (spec 6.2, taille lue avec `regs.obj_size`) :
```
first = if oam.rotation() { ((oam.internal() >> 2) & 0x7F) as usize } else { 0 }
list = [] ; overflow = false
pour k in 0..128 : i = (first + k) & 0x7F ; s = sprite(i) ; (w, h) = obj_dims(regs.obj_size, s.large)
    row = ((r as i32) - (s.y as i32) - 1) & 0xFF ; si row >= h : continuer
    si !(s.x == -256 || (s.x as i32) > -(w as i32)) : continuer
    si list.len() == 32 : overflow = true ; sortir de la boucle
    list.push(i)
```

### 6.1 Tables
OAM basse: octet `i*4+0` = X bits 7-0; `+1` = Y; `+2` = tuile bits 7-0; `+3` = `VHPP CCCt` (V flip, H flip, PP priorite 0..3, CCC palette 0..7, t = bit de table de noms / bit 8 de tuile).
OAM haute: octet `512 + i/4`, bits `(i%4)*2` = X bit 8, `(i%4)*2 + 1` = taille (grand si 1). `x = sign_extend_9(...)` -> -256..255.
Tailles (petit / grand) selon `obj_size`: 0: 8/16; 1: 8/32; 2: 8/64; 3: 16/32; 4: 16/64; 5: 32/64; 6: 16x32 / 32x64; 7: 16x32 / 32x32 (les autres sont carres: largeur = hauteur).

### 6.2 Evaluation de la liste (32 sprites max)
```
first = if obj_priority_rotation { (internal_oamadd >> 2) & 0x7F } else { 0 }
list = []
for k in 0..128:
    i = (first + k) & 0x7F
    row = (r - y - 1) & 0xFF            // le sprite apparait une rangee plus bas que Y: Y = 255 -> premiere rangee visible
    if row >= h: continue
    if !(x == -256 || x > -(w as i32)): continue    // bug materiel: x = -256 compte dans la limite
    if list.len() == 32 { range_over = true; break }
    list.push(i)
```

## Tests
Tous les tests sont prefixes par `e05_10_`.

- `e05_10_obj_dims_table` : `obj_dims(0,false)==(8,8)`, `(0,true)==(16,16)` ; `(1,false)==(8,8)`, `(1,true)==(32,32)` ; `(2,true)==(64,64)` ; `(3,false)==(16,16)`, `(3,true)==(32,32)` ; `(4,true)==(64,64)` ; `(5,false)==(32,32)`, `(5,true)==(64,64)` ; `(6,false)==(16,32)`, `(6,true)==(32,64)` ; `(7,false)==(16,32)`, `(7,true)==(32,32)`.
- `e05_10_decode_sprite` : `spr(&mut img,5,-1,0x12,0x34,0xE5,true)` puis `load_oam` : `p.sprite(5)==Sprite{x:-1,y:0x12,tile:0x34,tbit:true,pal:2,prio:2,hflip:true,vflip:true,large:true}`. Un autre sprite du meme octet haut (indice 4, 6, 7) n'est pas modifie : `p.sprite(4).large==false`.
- `e05_10_decode_x_range` : `spr(.., 0, 255, ..)` -> `sprite(0).x==255` ; `spr(.., 1, -256, ..)` -> `sprite(1).x==-256` ; `spr(.., 2, 0, ..)` -> 0 ; `spr(.., 3, -2, ..)` -> -2 ; `spr(.., 4, 100, .., large=true)` : `sprite(4).x==100`, large vrai.
- `e05_10_row_visibility_y255` : sprite 0 (x=10, y=255, 8x8) : `sprite_list(0)` contient 0 ; `sprite_list(7)` contient 0 ; `sprite_list(8)` ne contient pas 0 (rangee 8 >= hauteur 8). Les autres sprites sont cachees par `hide_all`.
- `e05_10_row_visibility_y0` : sprite 0 (x=10, y=0) : absent de `sprite_list(0)` ; present pour r = 1..=8 ; absent pour r = 9. Sprite (y=10) : present pour r = 11..=18 uniquement.
- `e05_10_large_height` : `write(0x01,0x00)` (taille 0), sprite 0 grand (16x16) y=255 : present pour r = 0..=15, absent pour r = 16.
- `e05_10_x_range_small` : sprites 8x8 sur la rangee r=1 (y=0) : x=-7 present ; x=-8 absent ; x=-9 absent ; x=-256 present ; x=255 present ; x=0 present.
- `e05_10_x_range_large` : sprite grand 16x16 : x=-15 present ; x=-16 absent.
- `e05_10_limit_32` : 33 sprites (indices 0..=32) identiques (x=10 + i, y=0, 8x8), les autres caches ; `sprite_list(1)` : liste de 32 indices `[0,1,...,31]` et overflow == true. Avec 32 sprites seulement (indices 0..=31) : liste de 32, overflow == false.
- `e05_10_invisible_do_not_count` : 40 sprites dont seuls les indices pairs touchent la rangee (les impairs ont y=100) : `sprite_list(1)` contient 20 indices pairs, overflow == false.
- `e05_10_rotation_first_sprite` : sprites 0 et 5 visibles (rangee 1), les autres caches. Sans rotation : `sprite_list(1).0==[0,5]`. Apres `load_oam` puis `write(0x02,10); write(0x03,0x80)` (OAMADD 10 -> internal 20 -> first = 5, rotation vrai) : `sprite_list(1).0==[5,0]`. Avec `write(0x02,12); write(0x03,0x80)` (internal 24 -> first = 6, l'ordre est 6..127 puis 0..5) : `[0,5]`.
