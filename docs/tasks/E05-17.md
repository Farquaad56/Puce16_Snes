# E05-17 - ppu/bg.rs: fonds hi-res des modes 5 et 6 (bg_pixel_hires)
Epopee: E05 | Type: code | Dependances: E05-16 | Taille estimee: ~140 lignes

## Contexte
Les modes 5 et 6 evaluent les fonds sur 512 colonnes (`hx` = 0..=511, deux colonnes par pixel de 256). Une entree de carte couvre 16 pixels hi-res de large (deux tuiles 8x8 cote a cote); la hauteur est 8 ou 16 selon BGMODE.
`UNKNOWN - to confirm`: parite des colonnes (`hx` impair = ecran principal), mosaique en hi-res, formule d'entrelacement `(v << 1) | field`, offset-per-tile du mode 6 (NON implemente ici: ne rien ajouter). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'. Aides de test (a recopier dans le fichier de test): `fn put_vram(p: &mut Ppu, addr: u16, w: u16) { p.write(0x15,0x80); p.write(0x16,(addr & 0xFF) as u8); p.write(0x17,(addr >> 8) as u8); p.write(0x18,(w & 0xFF) as u8); p.write(0x19,(w >> 8) as u8); }` ; `fn put_cgram(p: &mut Ppu, i: u8, w: u16) { p.write(0x21,i); p.write(0x22,(w & 0xFF) as u8); p.write(0x22,(w >> 8) as u8); }` ; `fn set_scroll(p: &mut Ppu, reg: u8, v: u16) { p.write(reg,(v & 0xFF) as u8); p.write(reg,(v >> 8) as u8); }`. ## Specification
Dans `ppu/bg.rs` :
```rust
impl Ppu {
    pub fn bg_pixel_hires(&self, n: usize, hx: usize, v: usize) -> Option<Pix>;
    pub fn sample_layers_hx(&self, x: usize, hx: usize, v: usize) -> [Option<Pix>; 5];
}
```
`bg_pixel_hires(n, hx, v)` (n = 0..=3) :
1. `mode = regs.bg_mode` ; si `mode != 5 && mode != 6` -> `None` ; `bpp = bpp(mode, n)` ; si `bpp == 0` -> `None`.
2. Mosaique (meme reglage que E05-07, active si `regs.mosaic_en >> n & 1 != 0`) : `x = hx >> 1` ; `(xm, vm) = mosaic_xy(regs.mosaic_size(), enabled, x, v)` ; `hxm = (xm << 1) | (hx & 1)`.
3. Entrelacement : `vm_il = if self.interlace { (vm << 1) | (self.field as usize) } else { vm }`.
4. `px = (hxm + ((scroll.hofs(n) as usize) << 1)) & 0x3FF` ; `py = (vm_il + scroll.vofs(n) as usize) & 0x3FF`.
5. `tall = regs.tile16[n]` ; `tx = px >> 4` ; `ty = if tall { py >> 4 } else { py >> 3 }` ; `entry = decode_entry(vram_word(map_entry_addr(regs.map_base[n], regs.map_x2[n], regs.map_y2[n], tx as u16, ty as u16)))`.
6. `xs = (((px >> 3) & 1) as u16) ^ (entry.hflip as u16)` ; `ys = if tall { (((py >> 3) & 1) as u16) ^ (entry.vflip as u16) } else { 0 }` ; `number = (entry.tile + xs + ys * 16) & 0x3FF` ; `fx = (px & 7) ^ (if entry.hflip { 7 } else { 0 })` ; `fy = (py & 7) ^ (if entry.vflip { 7 } else { 0 })`.
7. Meme lecture de tuile que `bg_pixel` (E05-05, `words = 16` pour 4 bpp, `8` pour 2 bpp, `tile_word = (chr_base[n] + number * words) & 0x7FFF`, `row = (tile_word + fy) & 0x7FFF`, `decode_row(..)[fx]`, indice 0 -> `None`) ; `rgb = cgram[bg_palette_index(mode, n, bpp, entry.pal, i)]` ; `Some(Pix { rgb, prio: entry.prio, obj_pal: 0 })`.
Modification de `Ppu::bg_pixel` (E05-05) : retourne `None` si `regs.bg_mode >= 5` (modes 5/6 : seul `bg_pixel_hires` est utilise ; mode 7 : voir E05-12/13).
`sample_layers_hx(x, hx, v)` = le contenu de `sample_layers` (E05-14) ou la couche BG `n` vaut `bg_pixel_hires(n, hx, v)` si `regs.bg_mode` est 5 ou 6, `bg_pixel(n, x, v)` sinon (mode 7 et OBJ inchanges ; une couche absente de `tm | ts` vaut `None`). `sample_layers(x, v)` devient `sample_layers_hx(x, 2 * x + 1, v)`.

## 12. Hi-res et pseudo hi-res
`hires_line = (mode == 5 || mode == 6 || hires_bit)`.
- **Pseudo hi-res** (SETINI bit3, modes autres que 5/6): colonne `2x+1` = ecran principal (calcul 11.4 normal), colonne `2x` = ecran secondaire `pick(Sub, x)` avec color math UNIQUEMENT si `!addend_subscreen` et couche autorisee (`layer_ok` calcule sur `sub.layer`) et `!prevent`: `blend(sub.rgb, fixed_color)`; sinon `sub.rgb` brut. `black` s'applique aux deux colonnes. (`UNKNOWN - to confirm`.)
- **Modes 5 et 6**: les fonds sont evalues sur 512 colonnes: `bg_pixel_hires(n, hx, v)` avec `hx = 2x + 1` pour l'ecran principal et `hx = 2x` pour le secondaire. Les sprites sont a 256 colonnes (meme pixel pour les deux). Tuile BG: 16 px de large (carte), BGMODE choisit 16x8 ou 16x16. Position: `px = hx + (hofs[n] << 1)`; entree de carte `(px >> 4, py >> 3 ou >> 4)`; demi-tuile gauche/droite: `xs = ((px >> 3) & 1) ^ H`, numero `T + xs (+ ys*16 si tuile 16 haute)`; pixel `fx = (px & 7) ^ (H?7:0)`. Memes regles de priorite/palette/couleur que 7. Entrelacement (SETINI bit0): `py = vm_il + vofs[n]` avec `vm_il = (v << 1) | field` (sinon `v`) `UNKNOWN - to confirm`. OPT mode 6: `UNKNOWN`, a faire en dernier.
Ecriture dans le framebuffer: voir 05 section 6.

## 2. Modes BG: profondeur de bits par couche et tables de priorite

`BPP[mode][bg]` (0 = couche non rendue):
| Mode | BG1 | BG2 | BG3 | BG4 | Remarque |
|---|---|---|---|---|---|
| 0 | 2 | 2 | 2 | 2 | base CGRAM BGn = (n-1)*32 |
| 1 | 4 | 4 | 2 | 0 | |
| 2 | 4 | 4 | 0 | 0 | BG3 = donnees offset-per-tile (non affichee) |
| 3 | 8 | 4 | 0 | 0 | BG1 couleur directe possible |
| 4 | 8 | 2 | 0 | 0 | BG3 = OPT (un seul mot) |
| 5 | 4 | 2 | 0 | 0 | hi-res force, tuiles 16 px de large |
| 6 | 4 | 0 | 0 | 0 | hi-res force, BG3 = OPT |
| 7 | 8 | (EXTBG 7 bits) | 0 | 0 | voir section 8 |

Ordre de priorite, de l'AVANT vers l'ARRIERE. Notation: `Sp` = sprites de priorite p (0..3); `nH`/`nL` = BG n avec bit de priorite de tuile 1 / 0; en mode 7: `1` = BG1 (une seule priorite), EXTBG: `2H`/`2L` = bit 7 de l'indice.
```
Mode 0:  S3 1H 2H S2 1L 2L S1 3H 4H S0 3L 4L
Mode 1 (BGMODE bit3 = 0): S3 1H 2H S2 1L 2L S1 3H S0 3L
Mode 1 (BGMODE bit3 = 1): 3H S3 1H 2H S2 1L 2L S1 S0 3L
Mode 2,3,4,5: S3 1H S2 2H S1 1L S0 2L
Mode 6:  S3 1H S2 S1 1L S0
Mode 7:  S3 S2 S1 1 S0
Mode 7 + EXTBG: S3 S2 2H S1 1 S0 2L
```
Implementation: `const PRIORITY: [&[(u8 /*couche*/, u8 /*niveau*/)]; ...]` (niveau = priorite 0..3 pour OBJ, 0/1 pour BG; mode 6: BG1 H/L; mode 7: BG1 niveau 0 ou "tous"). Le fond (backdrop) vient toujours en dernier.
Pour une couche BG non rendue (BPP = 0), ou dont le bit TM/TS est a 0, l'entree est ignoree.
