# E06-37 - Snes: le S-CPU voit le handshake de l'IPL (jalon audio A1)

## Contexte
Premier test de bout en bout du SPC700 dans la console: un vrai programme 65816 attend `$AA` en `$2140` et `$BB` en `$2141`, puis allume l'ecran en rouge. L'image est rouge SI ET SEULEMENT SI l'APU a repondu. Programme (LoRom, comme E04-15). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. ## Specification
Programme `PROG_APU` (a 0x8000, 41 octets) :
`78 18 FB` SEI ; CLC ; XCE
`AD 40 21` LDA $2140 ; `C9 AA` CMP #$AA ; `D0 F9` BNE (retour au LDA $2140)
`AD 41 21` LDA $2141 ; `C9 BB` CMP #$BB ; `D0 F2` BNE (retour au LDA $2140)
`A9 00 8D 21 21` ; `A9 1F 8D 22 21` ; `A9 00 8D 22 21` (couleur 0 = rouge) ; `A9 0F 8D 00 21` (ecran allume) ; `80 FE` (boucle).
Soit: `78 18 FB AD 40 21 C9 AA D0 F9 AD 41 21 C9 BB D0 F2 A9 00 8D 21 21 A9 1F 8D 22 21 A9 00 8D 22 21 A9 0F 8D 00 21 80 FE`.
Utilise le meme montage que `tests/e04_15_snes_video.rs` (module `common`, `build_rom(&[(0, PROG)], &[])`, `Snes::new(&rom, None)`).

## Tests
Tous les tests sont prefixes par `e06_37_`.

- `e06_37_handshake_turns_screen_red` : `Snes::new` sur `PROG_APU` ; `run_frame()` 3 fois : `frame().width==256`, `frame().height==224`, tous les 57344 pixels == 0xFFFF0000 (rouge : l'APU a repondu).
- `e06_37_first_frame_still_black` : apres UN seul `run_frame()` (~357 000 clocks maitres mais le SMP n'a pas encore fini d'effacer sa RAM selon le timing) : si l'image est deja rouge le test reste valide ; ce test verifie seulement que `frame()` est soit tout noir (0xFF000000) soit tout rouge (aucun pixel d'une autre couleur).
- `e06_37_determinism` : deux `Snes` identiques apres 3 frames ont le meme `state_hash()`.
- `e06_37_reset_restarts` : apres 3 frames rouges, `reset()` puis 3 frames : image rouge de nouveau (le handshake est refait).
