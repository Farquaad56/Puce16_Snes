## Specification
Dans `emu_thread.rs` (le module est deja declare dans lib.rs; les tests importent `puce16_desktop::emu_thread::*`):
```rust
pub enum Command { Pause(bool), FrameAdvance, SetJoypad(usize, u16), Reset, SetFastForward(bool), Quit }   // LoadRom/SaveState/... viendront plus tard
pub struct FrameData { pub width: usize, pub height: usize, pub pixels: Vec<u32>, pub frame_no: u64 }
pub enum Event { Frame(std::sync::Arc<FrameData>), Status(String) }
pub struct EmuHandle { pub tx: std::sync::mpsc::Sender<Command>, pub rx: std::sync::mpsc::Receiver<Event>, join: Option<std::thread::JoinHandle<()>> }
pub fn spawn_test_pattern(region: puce16_core::Region, start_paused: bool) -> EmuHandle;
impl EmuHandle { pub fn quit(self); }   // envoie Quit et join
```
Comportement:
- le thread cree `Snes::new_test_pattern(region)` et boucle: traite TOUTES les commandes en attente (`try_recv`); si non pause: `run_frame()`, envoie `Event::Frame` (copie de `frame()` + `frame_count`), puis attend ~16 ms (`thread::sleep`; cadence exacte non requise ici). Si pause: dort 5 ms.
- `FrameAdvance` en pause: execute exactement une frame et l'envoie. `Pause(false)` reprend. `SetJoypad(p, b)` appelle `set_joypad`. `Reset`: recree le `Snes` (frame_no repart a 1 au prochain run). `Quit` termine le thread.
- Le canal d'evenements est borne par la consommation de la UI (utilise `mpsc::channel` non borne mais n'envoie pas plus d'une frame par frame emulee).

## 7. Architecture desktop

- Thread d'emulation (`emu_thread.rs`) possede `Snes` ; thread UI (egui) envoie des `Command` (`std::sync::mpsc`): `LoadRom(Vec<u8>, path)`, `Reset`, `Pause(bool)`, `FrameAdvance`, `SetJoypad(port, u16)`, `SaveState(slot)`, `LoadState(slot)`, `SetFastForward(bool)`, `RequestDebug(bool)`, `Quit`.
- Le thread d'emulation publie `Event` : `Frame(Arc<FrameData>)` (largeur, hauteur, pixels), `Status(String)`, `Debug(Box<DebugData>)` (seulement si demande), `SramDirty`, `Error(String)`.
- Boucle: tant que non en pause: `run_frame()` ; pousser l'audio ; publier la frame ; attendre selon la synchro. Une frame est publiee par frame emulee (la UI affiche la plus recente).
- Aucun etat d'emulation n'est partage par verrou avec la UI: tout passe par canaux.

## Tests
Tous les tests sont prefixes par `e01_09_`.

- `e01_09_start_paused_no_frame` : `spawn_test_pattern(Ntsc, true)`: apres 100 ms `rx.try_recv()` est vide ; puis `FrameAdvance` -> on recoit un `Event::Frame` avec `frame_no==1` (timeout 2 s).
- `e01_09_frame_advance_twice` : deux `FrameAdvance` en pause -> `frame_no` 1 puis 2 (ordre garanti).
- `e01_09_run_free` : `spawn_test_pattern(Ntsc,false)`: on recoit au moins 3 `Event::Frame` en < 2 s, `frame_no` strictement croissant.
- `e01_09_joypad_visible` : en pause: `SetJoypad(0,0x8000)` puis `FrameAdvance` -> le pixel (0,0) de la frame recue vaut 0xFFFFFFFF.
- `e01_09_quit_joins` : `quit()` retourne en < 1 s sans panique.
