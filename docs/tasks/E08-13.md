# E08-13 - Tests d'integration des save states sur des scenarios (NMI, DMA, HDMA, PPU, APU)
Epopee: E08 | Type: code | Dependances: E08-12 | Taille estimee: ~140 lignes

## Contexte
Prouve que sauver puis recharger au milieu d'une execution ne change RIEN au futur: pour chaque scenario, `A` (sans sauvegarde) et `B` (sauve a la frame K, recharge dans une console neuve, continue) donnent le meme `state_hash` et les memes pixels/audio a chaque frame. Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Fichier de test : Chaque fichier de test commence par `mod common; #[path = "common/prog.rs"] mod prog;` (et `#[path = "common/fake_dma_bus.rs"]` n'est pas utile ici), puis `use puce16_core::snes::Snes; use prog::build_rom;`. Helper de test: `fn snes(rom: Vec<u8>) -> Snes { Snes::new(&rom, None).ok().unwrap() }`. Les programmes sont du code machine 65816 assemble A LA MAIN (octets donnes); l'adresse CPU de l'octet i du programme est 0x8000 + i. `settle(&mut s)` = `for _ in 0..12 { s.step_instruction(); }` (laisse le temps au CPU de prendre une interruption apres `run_frame`). Fonction `fn compare(rom: &[u8], k: u64, n: u64)`: A = `Snes::new` + `k + n` frames (enregistrer le `state_hash`, les pixels de `frame()` et l'audio de `take_audio` a chaque frame) ; B = `Snes::new`, `k` frames, `blob = save_state()` ; C = `Snes::new` puis `C.load_state(&blob)` puis `n` frames. A chaque frame apres K: `state_hash`, pixels de `frame()` et audio de C egaux a ceux de A.
Scenarios (les programmes sont COPIES des tests d'integration existants du meme depot, fichiers `tests/e03_37_nmi.rs`, `e03_39_*.rs`, `e03_40_*.rs`, `e04_15_snes_video.rs`, `e05_16_*.rs`, `e06_37_snes_handshake.rs`; recopier les octets, ne pas les reecrire de memoire):
1. NMI: `PROG_A` + `HANDLER_INC0100` a l'offset 0x100 + vecteur `nmi` 0x8100 (E03-37).
2. DMA general ROM -> WRAM par `$2180`: le programme du premier test de E03-39.
3. HDMA vers `$2180`, table directe: le programme du premier test de E03-40.
4. PPU: la scene du premier test de E05-16 (mode 1, BG1, couleurs) ou, a defaut, le programme rouge de E04-15.
5. APU: `PROG_APU` de E06-37.
6. DMA long: le programme de E03-39 dans lequel la taille du transfert (`DAS`, deux octets) est mise a `0x0000` (= 65536 octets).
7. PAL: scenario 4 avec `Snes::new(&rom, Some(Region::Pal))`.

## Tests
Tous les tests sont prefixes par `e08_13_`.

- `e08_13_nmi_counter` : scenario 1, K=3, N=5.
- `e08_13_dma_general` : scenario 2, K=2, N=3.
- `e08_13_hdma_table` : scenario 3, K=2, N=3.
- `e08_13_ppu_scene_mode1` : scenario 4, K=2, N=3, comparer aussi la couleur du pixel (0,0) a la fin.
- `e08_13_apu_handshake_red` : scenario 5, K=1 puis K=3 (avant et apres l'apparition du rouge).
- `e08_13_long_dma` : scenario 6, K=1, N=3 puis K=2, N=3 (tester au moins un K qui tombe pendant le DMA si le temps du DMA depasse une frame).
- `e08_13_pal_console` : scenario 4 en PAL, K=2, N=3.
