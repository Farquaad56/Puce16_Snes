## Specification
Fichier `tests/e07_10_suite.rs` du crate `puce16-cli` (lancer le binaire par `env!("CARGO_BIN_EXE_puce16-cli")` avec `std::process::Command`). Aides a recopier: `tiny_rom()` et `wram_rom()` ci-dessous ; `fn setup(dir: &Path) ` qui ecrit `dir/tiny.sfc`, `dir/wram.sfc` et un `manifest.toml` ; chemins ABSOLUS dans le TOML (utiliser `dir.display()` avec des `/`). ROM minimale pour les tests (LoROM, 32 Kio, boucle infinie): `fn tiny_rom() -> Vec<u8> { let mut r = vec![0u8; 0x8000]; r[0] = 0x80; r[1] = 0xFE; r[0x7FFC] = 0x00; r[0x7FFD] = 0x80; r }` (BRA -2 a 0x8000, vecteur RESET 0x8000; l'unique candidat d'en-tete est LoROM). Elle reste en mode emulation. Programme d'ecriture WRAM (a mettre en tete d'une copie de `tiny_rom()`, octets 0..10): `78 18 FB A9 42 8D 10 00 80 FE` = SEI ; CLC ; XCE ; LDA #$42 ; STA $0010 ; BRA -2 (`fn wram_rom() -> Vec<u8> { let mut r = tiny_rom(); r[..10].copy_from_slice(&[0x78,0x18,0xFB,0xA9,0x42,0x8D,0x10,0x00,0x80,0xFE]); r }`).
Manifeste de base (`<D>` = dossier temporaire):
```toml
[[rom]]
name = "tiny_hash"
path = "<D>/tiny.sfc"
frames = 3
epic = "E04"
[[rom]]
name = "wram_ram"
path = "<D>/wram.sfc"
frames = 2
epic = "E03"
check = "ram"
expect_ram = [ { addr = 0x7E0010, value = 0x42 } ]
[[rom]]
name = "tiny_ports"
path = "<D>/tiny.sfc"
frames = 3
epic = "E06"
check = "ports"
expect_ports = [0xAA, 0xBB, 0, 0]
[[rom]]
name = "absent_game"
path = "<D>/nothere.sfc"
frames = 1
epic = "E07"
optional = true
```


## Tests
Tous les tests sont prefixes par `e07_10_`.

- `e07_10_first_run_reports_new` : `suite <D>/manifest.toml` (pas de baseline.json) : stdout contient `NEW tiny_hash frame_hash=0x`, `PASS wram_ram`, `PASS tiny_ports`, `SKIP absent_game: file missing` et la ligne `suite: 2 pass, 0 fail, 1 skip, 1 new` ; code de sortie 0.
- `e07_10_update_then_pass` : `suite <manifest> --update-baseline tiny_hash` : stdout `baseline updated: tiny_hash`, code 0, `<D>/baseline.json` existe et contient `"tiny_hash"` et `"frames": 3` ; relancer `suite <manifest>` : stdout contient `PASS tiny_hash`, code 0.
- `e07_10_hash_mismatch_fails` : apres `update_then_pass`, modifier `baseline.json` (remplacer la valeur de `state_hash` par `0x0000000000000000`) : `suite` -> stdout contient `FAIL tiny_hash:` et `state_hash`, code 1.
- `e07_10_ram_mismatch_fails` : changer `value = 0x42` en `0x43` dans le manifeste : stdout contient `FAIL wram_ram: ram 0x7E0010: expected 0x43 got 0x42`, code 1.
- `e07_10_max_epic_filters` : `--max-epic E03` : seule `wram_ram` est executee : stdout contient `PASS wram_ram` et ne contient pas `tiny_hash` ni `tiny_ports`.
- `e07_10_bad_max_epic` : `--max-epic X1` -> code 2 et stderr contient `bad --max-epic`.
- `e07_10_missing_required_rom_fails` : retirer `optional = true` de `absent_game` : stdout contient `FAIL absent_game: file missing`, code 1.
- `e07_10_unknown_update_target` : `--update-baseline nope` -> code 2 et stderr contient `unknown rom: nope`.
- `e07_10_dump_ppm` : `--dump-ppm <D>/out` : le fichier `<D>/out/tiny_hash.ppm` existe, commence par `P6\n256 224\n255\n` et a la taille 15 + 256*224*3.
- `e07_10_invalid_manifest` : manifeste `[[rom\n` -> code 2 et stderr contient `invalid manifest`.
- `e07_10_deterministic_output` : deux executions successives de `suite` (avec baseline a jour) produisent exactement la meme sortie standard.
