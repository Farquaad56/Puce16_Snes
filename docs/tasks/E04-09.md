## Contexte
Lecture des registres $2134-$2136 (MPY), $2138 (OAMDATAREAD), $2139/$213A (VMDATAxREAD), $213B (CGDATAREAD) et gestion de l'open bus interne du PPU (`ppu1_mdr`, `ppu2_mdr`).

## Specification
Dans `ppu/mod.rs`: ajoute au `Ppu` les champs `ppu1_mdr: u8`, `ppu2_mdr: u8` (0 au power-on) et les accesseurs `pub fn ppu1_mdr(&self) -> u8`, `pub fn ppu2_mdr(&self) -> u8`.
`Ppu::read(reg, cpu_mdr, wrio7) -> u8`:
- `0x34 | 0x35 | 0x36` (MPYL, MPYM, MPYH): `val = ((m7.mpy_bits() >> (8 * (reg - 0x34))) & 0xFF) as u8` ; `ppu1_mdr = val` ; renvoie `val`.
- `0x38`: `val = oam.read(self.oam_ok())` ; `ppu1_mdr = val`.
- `0x39`: `val = vram.read_low(self.vram_ok())` ; `ppu1_mdr = val`. `0x3A`: `vram.read_high(self.vram_ok())` ; `ppu1_mdr = val`.
- `0x3B`: `val = cgram.read(self.ppu2_mdr)` ; `ppu2_mdr = val`.
- tout le reste (`0x00..=0x33`, `0x37`, `0x3C..=0x3F`, et reg > 0x3F): renvoie `cpu_mdr` (open bus CPU) sans modifier le Ppu. (E04-10 complete `0x37` et `0x3C..=0x3F`.)
`hash_into`: AJOUTE a la fin: `ppu1_mdr`, `ppu2_mdr` (u8).

## 4. Registres PPU en lecture ($2134-$213F)

`Ppu::read(reg, cpu_mdr, wrio7) -> u8`. `ppu1_mdr` et `ppu2_mdr` = derniere valeur retournee par un registre PPU1 / PPU2 respectivement.

| Reg | Nom | Valeur retournee | Mise a jour open bus |
|---|---|---|---|
| $2134 | MPYL | `mpy & 0xFF` | `ppu1_mdr = valeur` |
| $2135 | MPYM | `(mpy >> 8) & 0xFF` | `ppu1_mdr` |
| $2136 | MPYH | `(mpy >> 16) & 0xFF` | `ppu1_mdr` |
| $2137 | SLHV | si `wrio7`: verrouille les compteurs (4.1). Retourne `cpu_mdr`. | aucune |
| $2138 | OAMDATAREAD | voir 2.1 | `ppu1_mdr` |
| $2139 | VMDATALREAD | voir 2.3 | `ppu1_mdr` |
| $213A | VMDATAHREAD | voir 2.3 | `ppu1_mdr` |
| $213B | CGDATAREAD | voir 2.4 | `ppu2_mdr` |
| $213C | OPHCT | voir 4.1 | `ppu2_mdr` |
| $213D | OPVCT | voir 4.1 | `ppu2_mdr` |
| $213E | STAT77 | `(range_over<<7) | (time_over<<6) | (ppu1_mdr & 0x10) | 0x01` (bit7 = T: plus de 32 sprites sur une ligne = `range_over`; bit6 = R: plus de 34 tranches = `time_over`; bit5 master/slave = 0; version PPU1 = 1) | `ppu1_mdr` |
| $213F | STAT78 | `(field<<7) | (counter_latched<<6) | (ppu2_mdr & 0x20) | (is_pal<<4) | 0x03` ; puis `counter_latched = false; ophct_byte = 0; opvct_byte = 0` | `ppu2_mdr` |

`mpy = (m7a as i16 as i32) * ((m7b_last_byte as i8) as i32)` (24 bits signe, calcule a la lecture).
Lecture de $2100-$2133 et de $2137: retourne `cpu_mdr` (open bus CPU).

### 4.1 Verrou des compteurs H/V
- Verrouillage (`latch_counters`): `latch_h = dot_counter_now()`, `latch_v = v`, `counter_latched = true`. `dot_counter_now()` = `self.dot` (0..339, ou 0..340 sur ligne longue); decalage `HV_LATCH_DOT_OFFSET` dans consts.rs, defaut 0 (`UNKNOWN - to confirm`).
- Declencheurs: lecture de $2137 si `wrio7`; `wrio_write(old, new)` quand le bit 7 passe de 1 a 0 (front descendant) [spec 02: WRIO.7 = /EXTLATCH].
- OPHCT ($213C): `ophct_byte == 0` -> retourne `latch_h & 0xFF`; sinon retourne `(latch_h >> 8) & 1 | (ppu2_mdr & 0xFE)`. Puis `ophct_byte ^= 1`.
- OPVCT ($213D): idem avec `latch_v` et `opvct_byte`.
- Avant tout verrouillage, `latch_h = latch_v = 0`.

## Tests
Tous les tests sont prefixes par `e04_09_`.

- `e04_09_mpy_bytes` : `write(0x1B,0x00); write(0x1B,0x01)` (a=256) ; `write(0x1C,0xFF)` -> `read(0x34,0,false)==0x00`, `read(0x35,0,false)==0xFF`, `read(0x36,0,false)==0xFF` (produit -256 = 0xFFFF00) ; `ppu1_mdr()==0xFF`.
- `e04_09_mpy_negative_small` : a=-1 (`write(0x1B,0xFF)` deux fois), `write(0x1C,0x7F)` -> `read(0x34,..)==0x81`, `read(0x35,..)==0xFF`, `read(0x36,..)==0xFF` (-127 = 0xFFFF81).
- `e04_09_mpy_positive` : a=0x0100 (ecritures 0x00 puis 0x01 sur 0x1B), `write(0x1C,0x7F)` -> `read(0x34,..)==0x00`, `read(0x35,..)==0x7F`, `read(0x36,..)==0x00`.
- `e04_09_oam_read` : forced blank : `write(0x02,0); write(0x03,0)`, quatre ecritures `write(0x04, 0x11/0x22/0x33/0x44)` ; `write(0x02,0)` (adresse 0) : `read(0x38,0,false)` renvoie 0x11, 0x22, 0x33, 0x44 successivement ; `ppu1_mdr()==0x44`. Display on a (0,0) : `read(0x38,0x99,false)==0` (bloque, adresse incrementee).
- `e04_09_vram_read_sequence` : forced blank : `write(0x15,0x80); write(0x16,0x10); write(0x17,0x00)` ; deux mots ecrits: `write(0x18,0xCD); write(0x19,0xAB); write(0x18,0x34); write(0x19,0x12)` (mots 0x10 = 0xABCD, 0x11 = 0x1234) ; `write(0x16,0x10)` (re-adresse, prefetch) : `read(0x39)==0xCD` (vmadd inchange), `read(0x3A)==0xAB`, `read(0x3A)==0xAB` (meme mot, rechargement avant increment), `read(0x39)==0x34` (latch = 0x1234, aucun changement), `read(0x3A)==0x12`. `ppu1_mdr()==0x12`.
- `e04_09_vram_read_blocked` : display on (`write(0x00,0x0F)`) a (0,0), VMAIN 0x00 : `read(0x39,0x77,false)==0` (bloque) et `vram_unit().vmadd()==1`.
- `e04_09_cgram_read_bit7_open_bus` : `write(0x21,5); write(0x22,0xBC); write(0x22,0x7A)` ; `write(0x21,5)` : `read(0x3B,0,false)==0xBC` (ppu2_mdr==0xBC), puis `read(0x3B,0,false)==0xFA` (0x7A | (0xBC & 0x80)). Ensuite mot 6 = 0 : `read(0x3B,..)==0x00`, `read(0x3B,..)==0x00` (bit 7 de ppu2_mdr est 0).
- `e04_09_mdr_independent` : `ppu1_mdr()` n'est pas modifie par `read(0x3B,..)` et `ppu2_mdr()` n'est pas modifie par `read(0x34,..)`, `read(0x38,..)`, `read(0x39,..)`.
- `e04_09_open_bus_cpu` : `read(0x05,0xAB,false)==0xAB` ; `read(0x00,0x12,true)==0x12` ; `read(0x37,0xCD,false)==0xCD` ; `read(0x40,0x55,false)==0x55` ; ces appels ne changent pas le hash.
- `e04_09_hash` : hash differe apres `read(0x34,..)` quand le produit est non nul (ppu1_mdr change de 0), et differe apres `read(0x3B,..)` (toggle/addr et ppu2_mdr).
