## Specification
1. `files.rs`: `pub fn cheat_path(rom: &Path) -> PathBuf` (meme dossier et meme nom que la ROM, extension remplacee par `cht`, comme `srm_path` le fait pour `srm`); `pub fn load_cheat_entries(path: &Path) -> Result<Vec<CheatEntry>, String>` (fichier absent -> `Ok(vec![])`; erreur de lecture ou de syntaxe -> `Err(message en francais avec le numero de ligne)`); `pub fn save_cheat_entries(path: &Path, entries: &[CheatEntry]) -> Result<(), String>` (utilise `format_cheat_file` et `write_atomic`).
2. `emu_thread.rs`: nouvelle variante `Command::SetCheats(Vec<ParCode>)`. Le thread console garde une variable `cheats: Vec<ParCode>`: a la reception, `cheats = codes; snes.set_cheats(&cheats)`. Partout ou la console est recreee ou remplacee (rechargement de ROM, `reload_console`, chargement d'etat si `Snes` est reconstruit), reappliquer `snes.set_cheats(&cheats)` sur la nouvelle console, SAUF au chargement d'une nouvelle ROM par `Command::LoadRom` ou la liste est videe (`cheats.clear()`) puis reappliquee vide (la fenetre de triches renverra les codes du nouveau `.cht`).
3. Pas d'interface ici (tache suivante). Si `Command` est utilise dans un `match` exhaustif ailleurs, ajouter la branche manquante.

## 7. Desktop

- Fichier de triches d'une ROM: meme dossier et meme nom que la ROM avec l'extension `.cht` (comme `.srm`).
- Au chargement d'une ROM: lecture du `.cht` (absent = liste vide), envoi des codes actifs a la console par `Command::SetCheats(Vec<ParCode>)`. La console garde la liste apres un `Reset` et un rechargement de la console.
- Menu `Triches` (grise sans ROM), sans fenetre de gestion: en haut, une case a cocher par triche (son nom; un survol affiche ses codes); cocher/decocher agit tout de suite et le menu RESTE ouvert (on peut activer plusieurs triches de suite). Sous un separateur: `Ajouter une triche...`, un sous-menu `Supprimer` (une entree par triche) et `Tout desactiver`. Sans triche, le menu affiche une ligne grisee `Aucune triche pour ce jeu`.
- `Ajouter une triche...` ouvre une petite fenetre avec UN champ principal `Code(s)` (multiligne: on peut coller plusieurs codes separes par espaces, virgules ou retours a la ligne) et un champ facultatif `Nom` (vide = le premier code sert de nom). L'erreur s'affiche en direct sous le champ (code fautif nomme) et le bouton `Ajouter` est grise tant que le texte est invalide. La touche Entree valide, Echap ferme. A la validation la triche est ajoutee ACTIVE, la fenetre se ferme.
- Chaque modification (case, ajout, suppression, tout desactiver) renvoie les codes actifs a la console et reecrit le `.cht` (ecriture atomique).

## Tests
Tous les tests sont prefixes par `e10_05_`.

- `e10_05_cheat_path_replaces_extension` : cheat_path("C:/jeux/smw.sfc") se termine par smw.cht dans le meme dossier; cheat_path("/x/y.z.smc") donne /x/y.z.cht; un nom sans extension recoit .cht
- `e10_05_load_missing_file_is_empty` : load_cheat_entries sur un chemin inexistant = Ok(vec![])
- `e10_05_save_then_load_roundtrip` : dossier temporaire unique (std::env::temp_dir + nom unique): save_cheat_entries de 2 entrees puis load_cheat_entries = les memes entrees; le fichier commence par "# Puce16 cheats"
- `e10_05_load_bad_file_reports_line` : fichier contenant "+ A = 7E0DBE05\nfaux" -> Err dont le message contient "2"
- `e10_05_emu_thread_applies_cheats_after_reset` : demarrer le thread console avec une ROM synthetique (programme E6 00 80 FC, voir e03_46_emu_load.rs pour le style), envoyer SetCheats([7E000042]), Reset, attendre une image, lire la WRAM par les donnees de debug (ou une image publiee): la valeur 0x42 est presente; si lire la WRAM par le thread n'est pas possible, tester la fonction pure extraite qui rejoue la liste apres reload
