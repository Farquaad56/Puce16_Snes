## Specification
ROM avec SRAM de 8 Kio: `build_rom_with(blocks, vectors, 3, 0x02)`. Programme `PROG_BUS` (offset 0):
```
78 18 FB
AF 00 00 70        LDA $700000       (SRAM)
8D 45 01           STA $0145
A9 5A              LDA #$5A
8F 00 00 70        STA $700000
AD 00 50           LDA $5000         (open bus)
8D 40 01           STA $0140
AD 00 43           LDA $4300         (DMAP0 power-on)
8D 41 01           STA $0141
AD FF 1F           LDA $1FFF         (WRAM power-on)
8D 42 01           STA $0142
AD 10 42           LDA $4210         (RDNMI, flag faux)
8D 43 01           STA $0143
AD 13 42           LDA $4213         (RDIO power-on)
8D 44 01           STA $0144
80 FE
``` Chaque fichier de test commence par `mod common; #[path = "common/prog.rs"] mod prog;` (et `#[path = "common/fake_dma_bus.rs"]` n'est pas utile ici), puis `use puce16_core::snes::Snes; use prog::build_rom;`. Helper de test: `fn snes(rom: Vec<u8>) -> Snes { Snes::new(&rom, None).ok().unwrap() }`. Les programmes sont du code machine 65816 assemble A LA MAIN (octets donnes); l'adresse CPU de l'octet i du programme est 0x8000 + i. `settle(&mut s)` = `for _ in 0..12 { s.step_instruction(); }` (laisse le temps au CPU de prendre une interruption apres `run_frame`).

## 4. Open bus
- `mdr: u8` = derniere valeur vue sur le bus de donnees (mise a jour a chaque lecture ET ecriture CPU, et a chaque octet DMA lu cote A-bus... voir 03_DMA.md).
- Lecture d'une adresse non mappee: retourne `mdr`. Lecture d'un registre partiellement defini (ex: RDNMI bits 6-4, HVBJOY bits 5-1, TIMEUP bits 6-0, JOYSER bits 7-2): les bits non definis valent les bits correspondants de `mdr`.
- JOYSER1 ($4017): bits 4-2 = 1 toujours; bits 7-5 = mdr.
- PPU: les lectures PPU1 ($2134-$2137? voir 05_PPU.md) utilisent un open bus PPU separe (ppu1_mdr / ppu2_mdr). Defaut v1: ppu1_mdr = derniere valeur lue d'un registre PPU1 ($2134-$2136, $2138-$213A, $213E), ppu2_mdr = derniere valeur lue de PPU2 ($213B-$213D, $213F). `UNKNOWN - to confirm` si necessaire pour les ROM de test.

### 4.1 LoROM (banques de 32 Kio)
- Banques `$00-$7D` et `$80-$FF`, `addr >= $8000`: `rom_offset = ((bank & 0x7F) << 15) | (addr & 0x7FFF)`.
- Banques `$40-$7D` et `$C0-$FF`, `addr < $8000`: miroir de la moitie haute: meme formule (`addr & 0x7FFF`), sauf SRAM.
- SRAM (si taille > 0): banques `$70-$7D` et `$F0-$FF`, `addr < $8000`: `sram_off = (((bank & 0x0F) << 15) | addr) % sram_len` (`UNKNOWN - to confirm`: les variantes sont nombreuses, ce defaut couvre la plupart des jeux <= 2 Mio).
- Banques `$00-$3F`/`$80-$BF`, `addr < $8000`: systeme, pas la cartouche.

## Tests
Tous les tests sont prefixes par `e03_43_`.

- `e03_43_sram_written` : `run_frame()` : `sram().unwrap()[0]==0x5A`.
- `e03_43_sram_preloaded` : `load_sram(&[0x77])` AVANT `run_frame()` : `peek_wram(0x145)==0x77` (lu par LDA long) puis `sram().unwrap()[0]==0x5A` (reecrit).
- `e03_43_open_bus_value` : `peek_wram(0x140)==0x50` (LDA $5000 renvoie la derniere valeur vue sur le bus = l'octet haut de l'operande).
- `e03_43_dma_power_on` : `peek_wram(0x141)==0xFF` ($4300 vaut 0xFF au power-on).
- `e03_43_wram_power_on` : `peek_wram(0x142)==0x55`.
- `e03_43_rdnmi_partial_open_bus` : `peek_wram(0x143)==0x42` ((0x42 & 0x70) | 0x02, flag faux).
- `e03_43_rdio_power_on` : `peek_wram(0x144)==0xFF`.
- `e03_43_no_sram_rom` : meme programme avec `build_rom` (sans SRAM, chipset 0): `sram()==None` ; `peek_wram(0x145)` vaut l'open bus: l'ecriture SRAM est ignoree; `LDA $700000` lit le MIROIR ROM de LoROM (banque 0x70, adresse < 0x8000 -> offset 0 de la ROM = premier octet du programme, SEI = 0x78): `peek_wram(0x145)==0x78`.
