## Specification
`PROG_MATH` (10 NOP = 10 octets `EA` aux deux endroits marques):
```
78 18 FB
A9 07 8D 02 42     WRMPYA = 7
A9 09 8D 03 42     WRMPYB = 9         (lance 7*9)
EA x10
AD 16 42 8D 30 01  $0130 = RDMPYL
AD 17 42 8D 31 01  $0131 = RDMPYH
A9 34 8D 04 42     WRDIVL = $34
A9 12 8D 05 42     WRDIVH = $12       (dividende $1234)
A9 07 8D 06 42     WRDIVB = 7         (lance $1234 / 7)
EA x10
AD 14 42 8D 32 01  $0132 = RDDIVL
AD 15 42 8D 33 01  $0133 = RDDIVH
AD 16 42 8D 34 01  $0134 = RDMPYL (reste)
80 FE
```
`PROG_MATH_EARLY` = lecture immediate: `78 18 FB  A9 07 8D 02 42  A9 09 8D 03 42  AD 16 42 8D 30 01  80 FE` (la lecture de $4216 se termine 30 clocks apres l'ecriture de $4203, < 48). Helper de test: `fn snes(rom: Vec<u8>) -> Snes { Snes::new(&rom, None).ok().unwrap() }`. Les programmes sont du code machine 65816 assemble A LA MAIN (octets donnes); l'adresse CPU de l'octet i du programme est 0x8000 + i. `settle(&mut s)` = `for _ in 0..12 { s.step_instruction(); }` (laisse le temps au CPU de prendre une interruption apres `run_frame`).

### 6.1 Multiplication / division (unite math du 5A22)
- WRMPYB: `rdmpy = wrmpya * wrmpyb` (16 bits). Au power-on la valeur de RDMPY/RDDIV est `UNKNOWN - to confirm` (defaut 0).
- Valeurs intermediaires: une lecture avant la fin retourne un resultat partiel. Defaut v1: le resultat complet est visible a partir de `MUL_DONE = start + 8 * 6 = 48` clocks apres l'ecriture de WRMPYB (division: `start + 16 * 6 = 96`); avant, les registres gardent l'ancienne valeur. `UNKNOWN - to confirm` -> E03-T tuning.
- WRDIVB: si diviseur != 0: `rddiv = wrdiv / div ; rdmpy = wrdiv % div`. Diviseur == 0: `rddiv = 0xFFFF ; rdmpy = wrdiv`.
- Ecrire WRMPYB pendant une division/multiplication en cours: `UNKNOWN - to confirm` (defaut: nouvelle operation ecrase l'ancienne).

## Tests
Tous les tests sont prefixes par `e03_42_`.

- `e03_42_multiplication` : `run_frame()` sur PROG_MATH : `peek_wram(0x130)==0x3F` et `peek_wram(0x131)==0x00` (7*9 = 63).
- `e03_42_division` : `peek_wram(0x132)==0x99`, `peek_wram(0x133)==0x02` (quotient $0299 = 665), `peek_wram(0x134)==0x05` (reste 5).
- `e03_42_early_read_returns_old` : PROG_MATH_EARLY: `run_frame()` : `peek_wram(0x130)==0x00` (ancienne valeur de RDMPYL au power-on).
- `e03_42_determinism_same_rom` : deux `Snes` sur PROG_MATH: meme `state_hash` apres 2 frames.
- `e03_42_determinism_input_changes_hash` : deux `Snes` identiques, l'un avec `set_joypad(0, 0x8000)` : hash differents apres 1 frame.
- `e03_42_determinism_chunked_runs` : deux `Snes` identiques: `run_master(50_000)` x3 de chaque cote puis `run_frame()` : meme hash ; la partition identique est requise (le test ne compare PAS des partitions differentes).
- `e03_42_frames_do_not_change_results` : apres 3 `run_frame()`, `peek_wram(0x130..0x135)` valent toujours `[0x3F,0x00,0x99,0x02,0x05]` : le programme boucle sur BRA, il ne re-execute pas le calcul, les valeurs sont stables.
