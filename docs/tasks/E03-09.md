# E03-09 - ppu/mod.rs: registres $2100 et $2133 (minimal), read, hash
Epopee: E03 | Type: code | Dependances: E03-08 | Taille estimee: ~100 lignes

## Contexte
Seuls INIDISP (bit 7: forced blank) et SETINI (bit 0: interlace, bit 2: overscan) sont necessaires au timing. Le reste des registres est ecrit en E04.
La lecture d'un registre PPU renvoie pour l'instant `cpu_mdr` (open bus). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Ajoute a `impl Ppu`:
```rust
pub fn write(&mut self, reg: u8, v: u8);                         // reg = adresse - 0x2100
pub fn read(&mut self, reg: u8, cpu_mdr: u8, wrio7: bool) -> u8;   // E03: renvoie cpu_mdr
pub fn wrio_write(&mut self, old: u8, new: u8);                  // E03: ne fait rien
pub fn forced_blank(&self) -> bool;  pub fn interlace(&self) -> bool;  pub fn overscan(&self) -> bool;
pub fn hash_into(&self, h: &mut crate::hash::Fnv64);             // region (u8), v, dot (u16), field, interlace, overscan, forced_blank (u8 chacun)
```
`write`: `0x00` -> `forced_blank = v & 0x80 != 0` ; `0x33` -> `interlace = v & 1 != 0 ; overscan = v & 4 != 0` ; tout autre `reg` -> ignore. L'ecriture ne change PAS `v`, `dot`, `field`.

### 5.2 Frame
```
last_line = (if PAL {311} else {261}) + (if interlace && !field {1} else {0})   // UNKNOWN - to confirm quel field
```
A la fin de la derniere ligne: `v = 0`, **`field ^= 1` a chaque frame, interlace ou non** (le vrai materiel bascule toujours; STAT78 bit7 expose cette valeur).
`vis_last = if overscan {239} else {224}`. Lignes visibles: `v in 1..=vis_last`; ligne de sortie `r = v - 1`. V=0 est cachee (noire).

## Tests
Tous les tests sont prefixes par `e03_09_`.

- `e03_09_inidisp` : `Ppu::new`: forced_blank()==true ; `write(0x00,0x0F)` -> false ; `write(0x00,0x8F)` -> true.
- `e03_09_setini_flags` : `write(0x33,0x05)`: interlace()==true, overscan()==true, vblank_start()==240 ; `write(0x33,0x00)` -> false/false, vblank_start()==225 ; `write(0x33,0x04)` -> overscan seul.
- `e03_09_ignored_regs` : `write(0x01,0xFF)`, `write(0x2F,0xFF)`, `write(0x34,0xFF)` ne changent ni `forced_blank` ni interlace/overscan (verifie par hash identique avant/apres).
- `e03_09_read_open_bus` : `read(0x37,0xAB,true)==0xAB` ; `read(0x3F,0x12,false)==0x12`.
- `e03_09_interlace_ntsc_frames` : NTSC, `write(0x33,0x01)` avant le debut: frame 0 (field false): last_line()==262, somme des dot_clocks sur 263*340 steps == 358732 ; ensuite v()==0, field()==true ; frame 1 (field true): last_line()==261, somme sur 262*340 steps == 357368 (pas de ligne courte en entrelace).
- `e03_09_interlace_pal_frames` : PAL, `write(0x33,0x01)`: frame 0: last_line()==312, somme sur 313*340 steps == 426932 ; frame 1 (field true): last_line()==311, somme sur 312*340 + 1 steps (la ligne 311 a 341 dots) == 425572.
- `e03_09_overscan_vblank_event` : NTSC, `write(0x33,0x04)`: apres 240*340 steps v()==240, le step suivant renvoie VBLANK_START ; `in_vblank()` faux a v==239 et vrai a v==240.
- `e03_09_hash` : deux `Ppu::new(Ntsc)` ont le meme hash (`Fnv64`) ; apres un `step_dot` les hash different ; `Ppu::new(Ntsc)` et `Ppu::new(Pal)` different.
