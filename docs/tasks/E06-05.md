## Specification
1. `spc700/mod.rs`: `pub mod table; pub mod addr; pub mod testbus; mod alu; mod mov; mod incdec; mod word; mod bits; mod flow; mod misc;` puis les constantes `F_*` (valeurs de la section 2), le trait `SmpBus`, la struct `Spc700` (derive `Clone, Debug`; champs publics `a x y sp pc psw halted`, champs prives `cyc: u32`, `taken: bool`), et TOUTES les methodes du tableau de la section 2 (`new`, `rd`, `wr`, `idle`, `fetch8`, `fetch16`, `dp`, `rd16`, `flag`, `set_flag`, `set_nz`, `ya`, `set_ya`, `push8`, `pull8`, `branch`, `step`, `reset`). `impl Default for Spc700`.
2. `step` exactement comme la section 3 (dispatch `mov::exec(self,bus,op) || alu::exec(..) || incdec::exec(..) || word::exec(..) || bits::exec(..) || flow::exec(..) || misc::exec(..)`; sinon `panic!("unimplemented opcode {:02X} ({})", op, table::NAME[op as usize])`; completion par `idle`; renvoie `max(cyc, target)`).
3. Chaque fichier de famille (`alu mov incdec word bits flow misc`) contient exactement:
```rust
use super::{SmpBus, Spc700};
pub(super) fn exec<B: SmpBus>(_cpu: &mut Spc700, _bus: &mut B, _op: u8) -> bool { false }
```
4. `addr.rs` et `testbus.rs`: un commentaire `// filled by a later task` suffit.
5. `halted`: `step` fait un `idle`, ne change pas `pc`, renvoie 1.

## 2. Contrat
```rust
pub const F_C: u8 = 0x01; pub const F_Z: u8 = 0x02; pub const F_I: u8 = 0x04; pub const F_H: u8 = 0x08;
pub const F_B: u8 = 0x10; pub const F_P: u8 = 0x20; pub const F_V: u8 = 0x40; pub const F_N: u8 = 0x80;
pub trait SmpBus { fn read(&mut self, addr: u16) -> u8; fn write(&mut self, addr: u16, v: u8); fn idle(&mut self); }
#[derive(Clone, Debug)]
pub struct Spc700 { pub a: u8, pub x: u8, pub y: u8, pub sp: u8, pub pc: u16, pub psw: u8, pub halted: bool, cyc: u32, taken: bool }
```
Methodes (toutes generiques `B: SmpBus`, definies dans `mod.rs`; seules elles touchent le bus):
| Methode | Effet |
|---|---|
| `new()` | a=x=y=0, sp=0, pc=0, psw=0x02, halted=false |
| `rd(bus, addr) -> u8` / `wr(bus, addr, v)` / `idle(bus)` | un acces bus; `cyc += 1` |
| `fetch8(bus) -> u8` / `fetch16(bus) -> u16` | lit a `pc`, `pc += 1` (16 bits: octet bas d'abord) |
| `dp(&self) -> u16` | `0x0100` si flag P sinon `0x0000` |
| `rd16(bus, lo_addr, hi_addr) -> u16` | lit `lo_addr` puis `hi_addr` (bas, haut) |
| `flag(f) -> bool`, `set_flag(f, on)`, `set_nz(v: u8)` | N = bit 7, Z = (v == 0) |
| `ya(&self) -> u16`, `set_ya(&mut self, v: u16)` | `(y << 8) \| a` |
| `push8(bus, v)` / `pull8(bus) -> u8` | pile `0x0100 \| sp`; push: ecrit puis `sp -= 1`; pull: `sp += 1` puis lit |
| `branch(bus, rel: u8)` | `pc = pc.wrapping_add(rel as i8 as i16 as u16)`; `taken = true` (le cycle supplementaire est ajoute par `step`) |
| `step(bus) -> u32` | voir section 3 |
| `reset(bus)` | `pc = rd16(0xFFFE, 0xFFFF)`; a=x=y=0; sp=0; psw=0x02; halted=false |
`Spc700::cyc` compte les acces du step courant. Les fonctions d'ALU pures/flags sont dans `alu.rs`: `Spc700::adc_op(&mut self, a, b) -> u8`, `sbc_op`, `cmp_op(a, b)` (met N,Z,C), `or_op/and_op/eor_op(a, b) -> u8` (met N,Z).

## 3. Dispatch et cycles
```
step(bus): if halted { idle; return 1 }
  cyc = 0; taken = false; op = fetch8(bus)
  exec = mov::exec(op) || alu::exec(op) || incdec::exec(op) || word::exec(op) || bits::exec(op) || flow::exec(op) || misc::exec(op)   // chaque exec(cpu,bus,op) -> bool (true = opcode traite)
  si aucun: panic!("unimplemented opcode {:02X} ({})", op, NAME[op])
  target = CYCLES[op] + (if taken { BRANCH_EXTRA[op] } else { 0 })
  tant que cyc < target { idle(bus) }     // les cycles non modelises sont des cycles factices
  return max(cyc, target)                // si une famille fait plus d'acces que le TSV, c'est le nombre REEL qui est renvoye
```
Consequence: dans une famille on n'emet QUE les acces utiles (lectures/ecritures reelles, dont les lectures factices de destination decrites en 07 section 6.1); `step` complete avec des `idle`. Si une instruction fait plus d'acces que `CYCLES[op]`, le nombre renvoye est le nombre reel et l'ORACLE le signale (comparaison du nombre de cycles): c'est alors soit un bug de la famille, soit une erreur du TSV (`UNKNOWN - to confirm`, ex. `MOVW dp,YA` : TSV 4 cycles mais 5 acces decrits en 07 section 6.1) a trancher par une question `spec` (Claude corrige le TSV).

## 1. Registres du coeur
`A, X, Y: u8`, `SP: u8` (pile en page 1: adresse `$0100 | SP`), `PC: u16`, `YA` = `(Y<<8)|A` (16 bits).
`PSW` = `N V P B H I Z C` (bits 7..0). Le flag `P` choisit la page directe: `dp_base = if P {0x0100} else {0x0000}`. `I` n'a aucun effet (pas d'interruption sur le SPC700 de la SNES). `B` est mis par BRK.
Reset: `PC = lecture 16 bits de $FFFE/$FFFF` (= `$FFC0` via l'IPL), `A=X=Y=0`, `SP=0`, `PSW=$02` (`UNKNOWN - to confirm`: l'IPL fixe SP=$EF lui-meme).

## Tests
Tous les tests sont prefixes par `e06_05_`.

- `e06_05_new_defaults` : `Spc700::new()`: a=x=y=sp=0, pc=0, psw==0x02, halted==false.
- `e06_05_fetch_order_and_wrap` : Bus local au test (`struct TB { ram: Vec<u8> }` 65536 octets implementant `SmpBus`, idle = ne rien faire) : pc=0x0300, octets [0x34,0x12] : fetch16 -> 0x1234 (bas d'abord), pc==0x0302 ; pc=0xFFFF : fetch8 lit l'octet en 0xFFFF et pc==0x0000.
- `e06_05_push_pull` : sp=0xEF: push8(0xAB) ecrit ram[0x01EF]==0xAB et sp==0xEE ; pull8 renvoie 0xAB et sp==0xEF. sp=0x00: push8 ecrit en 0x0100 puis sp==0xFF (wrap).
- `e06_05_dp_base` : psw=0x00 -> dp()==0x0000 ; psw=F_P -> dp()==0x0100.
- `e06_05_flags_and_nz` : set_flag(F_C,true) -> psw==0x03 ; set_flag(F_C,false) -> 0x02 ; set_nz(0x80): N=1,Z=0 ; set_nz(0): Z=1,N=0 ; set_nz(0x7F): N=0,Z=0 ; flag(F_Z) reflete le bit.
- `e06_05_ya_pair` : y=0x12, a=0x34: ya()==0x1234 ; set_ya(0xABCD): y==0xAB, a==0xCD.
- `e06_05_rd16_order` : ram[0x10]=0x34, ram[0x11]=0x12: rd16(bus,0x10,0x11)==0x1234 ; rd16(bus,0xFF,0x00) avec ram[0xFF]=0x78, ram[0x00]=0x56 -> 0x5678.
- `e06_05_branch_forward_backward` : pc=0x0210: branch(bus,0x05) -> pc==0x0215 ; branch(bus,0xFB) (-5) depuis 0x0215 -> 0x0210 ; pc=0x0000, branch(0xFF) -> 0xFFFF.
- `e06_05_reset_vector` : ram[0xFFFE]=0xC0, ram[0xFFFF]=0xFF (bus local): reset(bus) -> pc==0xFFC0, a=x=y=0, sp==0, psw==0x02, halted==false.
- `e06_05_halted_step` : halted=true: step renvoie 1 et pc inchange.
- `e06_05_unimplemented_panics` : `#[should_panic(expected = "unimplemented opcode 00")]`: bus local avec ram[0x0200]=0x00 (NOP pas encore implemente a ce stade), pc=0x0200, step.
