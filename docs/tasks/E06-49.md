## Specification
1. Dans `apu/mod.rs` ajoute (sans autre changement): `pub fn debug_dsp_read(&mut self, reg: u8) -> u8 { self.io.dsp.read(reg) }`.
2. Dans `tests/e06_49_dsp_integration.rs` (API publique seulement):
```rust
fn setup(apu: &mut Apu, kon: u8, flg: u8) {
    apu.debug_poke(0x0200, &[0x00, 0x03, 0x00, 0x03]);                       // repertoire: debut = boucle = 0x0300
    apu.debug_poke(0x0300, &[0xC3, 0x77, 0x77, 0x77, 0x77, 0x77, 0x77, 0x77, 0x77]);   // bloc BRR: shift 12, filtre 0, boucle + fin, nibbles 7 -> 28672
    apu.debug_poke(0x0400, &[0x2F, 0xFE]);                                   // BRA -2 (boucle infinie)
    apu.debug_set_pc(0x0400);
    for (r, v) in [(0x5D,0x02),(0x04,0x00),(0x02,0x00),(0x03,0x10),(0x05,0x00),(0x07,0x7F),(0x00,0x7F),(0x01,0x7F),(0x0C,0x7F),(0x1C,0x7F),(0x6C,flg)] { apu.debug_dsp_write(r, v); }
    apu.debug_dsp_write(0x4C, kon);
}
```
(DIR=0x02, SRCN=0, PITCH=0x1000, ADSR1=0 donc GAIN direct 0x7F -> env 2032, volumes 0x7F.) Duree de reference: `apu.step_to(1_000_000)` (environ 1492 echantillons).
3. Programme SMP (test `smp_program_drives_dsp`): meme donnees en RAM et PAS de `debug_dsp_write`; a la place le programme a 0x0400 est la concatenation de, pour chaque paire (r, v) de la liste ci-dessus avec `KON=0x01` en dernier: `8F r F2` puis `8F v F3` (MOV $F2,#r ; MOV $F3,#v), suivie de `2F FE`.

## Tests
Tous les tests sont prefixes par `e06_49_`.

- `e06_49_constant_tone` : `setup(kon=1, flg=0x20)` ; `step_to(1_000_000)` ; `v = take_audio()` : `v.len()` pair et entre 2*1440 et 2*1520 ; pour tout `i >= 2*40` : `27000 <= v[i] && v[i] <= 29000` ; pour tout couple : `v[2k] == v[2k+1]`.
- `e06_49_silence_without_key_on` : `setup(kon=0, flg=0x20)` : toutes les valeurs sont 0.
- `e06_49_mute_flag` : `setup(kon=1, flg=0x60)` : toutes les valeurs sont 0.
- `e06_49_endx_set_by_loop` : `setup(kon=1, flg=0x20)`, `step_to(1_000_000)` : `debug_dsp_read(0x7C) & 1 == 1`.
- `e06_49_start_delay` : `setup(kon=1, flg=0x20)` ; `step_to(1_000_000)` : les 6 premieres paires sont exactement `[0,0]` (1 echantillon avant la premiere scrutation + delai de key-on de 5) et la paire d'indice 6 (7eme) est non nulle.
- `e06_49_deterministic` : deux `Apu` avec le meme `setup` et le meme `step_to` ont le meme `take_audio()` et le meme hash (`hash_into` dans un `Fnv64`).
- `e06_49_step_to_split_invariant` : A: `step_to(1_000_000)` ; B: `step_to(400_000)` puis `step_to(1_000_000)` ; `take_audio()` de B (concatene des deux prises) == celui de A.
- `e06_49_smp_program_drives_dsp` : voir (3) : audio non nul apres `step_to(1_000_000)` et `v[v.len()-2] >= 27000 && v[v.len()-2] <= 29000` ; `debug_dsp_read(0x6C)==0x20`.
