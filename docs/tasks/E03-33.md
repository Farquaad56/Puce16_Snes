## Specification
Dans `begin_cycle`, APRES le bloc de rafraichissement de E03-30:
```rust
if self.pending_hdma_init || self.pending_hdma_run {
    let (init, run) = (self.pending_hdma_init, self.pending_hdma_run);
    self.pending_hdma_init = false; self.pending_hdma_run = false;
    let m = self.mmio.hdmaen;
    let mut d = std::mem::take(&mut self.dma);
    if init { d.hdma_init(self, m); }
    if run  { d.hdma_run_line(self, m); }
    self.dma = d;
}
```
(L'avance du temps faite par HDMA peut redeclencher des flags; ils seront traites au cycle suivant.) ## 5. HDMA: declenchement
- `pending_hdma_init`: `Timing` renvoie `hdma_init` a (v == 0, dot == HDMA_INIT_DOT) si `mmio.hdmaen != 0` (valeur au moment du declenchement).
- `pending_hdma_run`: `hdma_run` a (v in 0..=vis_last, dot == HDMA_RUN_DOT) si `mmio.hdmaen != 0`.
- Execution dans `begin_cycle`: init: `dma.hdma_init(self, mmio.hdmaen)`; run: `dma.hdma_run_line(self, mmio.hdmaen)`. Surcout: `bus.elapse(18)` (une fois par appel) + 8 par canal actif + 8 par octet (spec 03 4.3), appliques par le moteur HDMA.
- Un canal HDMA actif est un canal dont le bit est dans `hdmaen` et dont `done == false`.

### 2.1 Cycle CPU (impl Bus pour SysBus)
```
fn read(addr):   begin_cycle(); advance(access_clocks(addr, memsel)); v = read_inner(addr); mdr = v (sauf registres a open bus partiel, voir read_inner); end_cycle(); v
fn write(addr,v): begin_cycle(); advance(access_clocks(..)); mdr = v; write_inner(addr, v); end_cycle()
fn idle():       begin_cycle(); advance(6); end_cycle()
begin_cycle: (1) rafraichissement DRAM (3.3 de 02): si !refreshed_this_line et (master - line_start) >= DRAM_REFRESH_HCLOCK: advance(40); refreshed_this_line = true
             (2) si pending_hdma_init ou pending_hdma_run: executer HDMA (voir section 5), puis effacer les drapeaux
end_cycle:   si pending_dma != 0: executer le DMA general (section 4) puis pending_dma = 0
```
(Le DMA part donc apres le cycle qui suit l'ecriture de MDMAEN: en pratique apres la lecture de l'opcode suivant, comme la spec 03 section 3.1.)
Les lignes d'interruption pour le CPU: `nmi_pending()` = front NMI detecte par `Timing` (consomme); `irq_asserted()` = `mmio.irq_line`.

## Tests
Tous les tests sont prefixes par `e03_33_`.

- `e03_33_init_after_dot3` : ROM de test avec table a 0x8300 = [0x01, 0xA1, 0x00] (vec de 0x310 octets). `bus.write_inner(0x00420C,0x01)` (hdmaen=1) ; WMADD=0x300 (`write_inner` 0x2181/0x2182) ; canal 0: dmap=0x00, bbad=0x80, a1t=0x8300, a1b=0 (via `bus.dma.write`). `bus.advance(20)` (position (0,5)): `hdma_state(0)` encore `(0xFFFF,0,false,true)` (rien n'a ete execute: HDMA ne part qu'en debut de cycle). `Bus::idle`: `bus.dma.hdma_state(0)==(0x8301, 1, true, false)` et `bus.master==20+26+6==52`.
- `e03_33_run_line_writes` : suite: `bus.advance(1101 - bus.master)` (master==1101, position (0,276), flag run pose) puis `Bus::idle` : d'abord le rafraichissement de la ligne 0 (hclock 1101 >= 538, jamais consomme: +40 -> 1141), puis HDMA run (18+8+8 = 34 -> 1175), puis le cycle idle (+6) : `bus.master==1181` ; `wram.read(0x300)==0xA1`, `wram.addr==0x301`, `hdma_state(0).3==true` (l'octet suivant 0x00 termine la table).
- `e03_33_done_channel_no_more` : ensuite on avance jusqu'apres le dot 276 de la ligne 1 (`bus.advance(1364 + 1101 - bus.master)`) puis `Bus::idle` : rien n'est ecrit (`wram.addr` toujours 0x301, `hdma_state(0).3` toujours vrai) : le flag run est consomme mais aucun canal n'est actif, donc aucun surcout HDMA (master n'augmente que du refresh 40 + idle 6).
- `e03_33_hdmaen_zero` : sans `write_inner(0x00420C,..)`: sur une frame entiere (`advance(357_368)` en plusieurs `idle`), jamais d'ecriture WRAM par HDMA.
- `e03_33_init_each_frame` : avec hdmaen=1: a la frame suivante (apres `advance` jusqu'a (1 frame + 5 dots)) et un `idle`, le canal est re-initialise (`hdma_state(0).3==false`).
- `e03_33_mark_refreshed_skips_refresh` : meme scenario que `run_line_writes` mais avec `bus.timing.mark_refreshed()` appele juste avant le `idle` : `bus.master==1101+34+6==1141` (pas de rafraichissement).
