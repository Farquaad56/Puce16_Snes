# E04-15 - snes.rs: le Snes reel affiche la sortie du PPU (jalon video V1)
Epopee: E04 | Type: code | Dependances: E04-14 | Taille estimee: ~100 lignes

## Contexte
Le variant `Real` de `Snes` cesse d'avoir son propre tampon noir: `frame()` renvoie `sys.ppu.frame()`. Premier test de bout en bout ou du vrai code 65816 ecrit un registre PPU et ou l'image change.
Les champs `fb` et `compact` du variant `Real` (E03-34) deviennent inutiles et sont supprimes. Le variant `Pattern` ne change pas. Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Dans `snes.rs`:
- `Snes::frame(&self)` pour `Inner::Real { sys, .. }`: `sys.ppu.frame()`.
- Retire `fb` et `compact` de `Inner::Real` (et de `new_with`/`reset`); le variant `Pattern` garde les siens.
Les tests existants (E03-34/35, `frame_view_real`: image noire 256x224) doivent rester verts sans modification.
Programmes de test (LoRom, a mettre dans le test; `HDR` habituel: `mod common; #[path = "common/prog.rs"] mod prog;`, `Snes::new(&build_rom(&[(0, PROG)], &[]), None)`):
- `PROG_RED` = `78 18 FB  A9 00 8D 21 21  A9 1F 8D 22 21  A9 00 8D 22 21  A9 0F 8D 00 21  80 FE` : SEI ; CLC ; XCE ; LDA #$00 ; STA $2121 (CGADD=0) ; LDA #$1F ; STA $2122 ; LDA #$00 ; STA $2122 (couleur 0 = 0x001F, rouge) ; LDA #$0F ; STA $2100 (display on, luminosite 15) ; BRA -2. (25 octets.)
- `PROG_BLUE` = `78 18 FB  A9 00 8D 21 21  A9 00 8D 22 21  A9 7C 8D 22 21  A9 0F 8D 00 21  80 FE` (couleur 0 = 0x7C00, bleu).
- `PROG_DARK` = `78 18 FB  A9 00 8D 21 21  A9 1F 8D 22 21  A9 00 8D 22 21  A9 08 8D 00 21  80 FE` (rouge, luminosite 8).

## 5. API publique de `puce16-core` (stable, ne pas changer sans question)

## Tests
Tous les tests sont prefixes par `e04_15_`.

- `e04_15_red_frame` : `Snes::new` sur PROG_RED ; `run_frame()` deux fois : `frame().width==256`, `frame().height==224`, tous les 57344 pixels == 0xFFFF0000.
- `e04_15_blue_frame` : idem avec PROG_BLUE : tous les pixels == 0xFF0000FF.
- `e04_15_dark_frame` : idem avec PROG_DARK : tous les pixels == 0xFF840000 (luminosite 8).
- `e04_15_black_before_display` : ROM `[0x78,0x18,0xFB,0x80,0xFE]` (jamais d'ecriture PPU) : apres `run_frame()` tous les pixels == 0xFF000000 (forced blank).
- `e04_15_first_frame_complete` : PROG_RED : apres le PREMIER `run_frame()` seulement, tous les pixels sont deja 0xFFFF0000 (le programme finit sa configuration pendant la ligne 0, avant la premiere ligne visible).
- `e04_15_determinism` : deux `Snes` PROG_RED identiques : meme `state_hash` apres 2 frames ; un `Snes` PROG_BLUE a un hash different.
- `e04_15_pattern_unchanged` : `Snes::new_test_pattern(Ntsc)` : apres `run_frame()` le pixel (0,0) vaut toujours 0xFF010040.
- `e04_15_reset_clears_picture` : PROG_RED, 2 frames ; `reset()` puis `run_frame()` une fois : l'image est rouge a nouveau (le programme se re-execute) et `frame_count()==1`.
