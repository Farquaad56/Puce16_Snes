# E08-21 - emu_thread: SRAM (chargement, sauvegarde toutes les 5 s, a la fermeture)
Epopee: E08 | Type: code | Dependances: E08-20 | Taille estimee: ~140 lignes

## Contexte
La SRAM de la cartouche est lue a l'ouverture de la ROM et ecrite sur disque quand elle change (D-017). Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Dans `emu_thread.rs`:
- `Command` gagne `SetRomPath(std::path::PathBuf)` (envoye par l'UI juste AVANT `LoadRom`) et `FlushSram`. `Event` gagne `SramSaved(std::path::PathBuf)`.
- `pub const SRAM_SAVE_INTERVAL: Duration = Duration::from_secs(5);`
- Pure et testable: `pub struct SramSync { last_saved: Option<Vec<u8>>, last_check: Instant }` avec `pub fn new(now: Instant) -> SramSync`, `pub fn reset(&mut self, now: Instant, current: Option<&[u8]>)` (memorise `current` comme deja sauve), `pub fn due(&mut self, now: Instant) -> bool` (vrai si `now - last_check >= SRAM_SAVE_INTERVAL` ; dans ce cas `last_check = now`), `pub fn changed(&self, sram: &[u8]) -> bool` (vrai si different de `last_saved` ou si `last_saved` est None), `pub fn mark_saved(&mut self, sram: &[u8])`.
- Dans le thread: apres un `LoadRom` reussi, si `rom_path` est connu et que `snes.sram()` est `Some` : si `srm_path(rom_path)` existe, `snes.load_sram(&octets)` (lecture ratee -> `Event::Error`, on continue) ; `sync.reset(..)`. Avant de remplacer le `Snes` (nouveau `LoadRom`), a `Quit` et sur `FlushSram` : sauvegarder si `changed`. Pendant l'execution: a chaque frame `if sync.due(now) && sram changed` -> `write_atomic(srm_path, sram)` puis `mark_saved` et `Event::SramSaved(path)`. Pas de SRAM (`None`) -> aucun fichier. Echec d'ecriture -> `Event::Error`.
- Dans `app.rs`: `open_path` envoie `Command::SetRomPath(path)` avant `Command::LoadRom`; la barre d'etat affiche `SRAM saved` sur `Event::SramSaved`. Aide de test (a recopier): `fn sram_rom(code: &[u8]) -> Vec<u8> { let mut r = vec![0u8; 0x8000]; r[..code.len()].copy_from_slice(code); r[0x7FC0..0x7FC0 + 21].copy_from_slice(b"PUCE16 TEST          "); r[0x7FD5] = 0x20; r[0x7FD6] = 0x02; r[0x7FD7] = 0x05; r[0x7FD8] = 0x03; r[0x7FD9] = 0x01; r[0x7FDA] = 0x33; r[0x7FFC] = 0x00; r[0x7FFD] = 0x80; r[0x7FDC] = 0xFF; r[0x7FDD] = 0xFF; r[0x7FDE] = 0x00; r[0x7FDF] = 0x00; let sum: u32 = r.iter().map(|&b| b as u32).sum(); let c = (sum & 0xFFFF) as u16; r[0x7FDE] = c as u8; r[0x7FDF] = (c >> 8) as u8; let n = !c; r[0x7FDC] = n as u8; r[0x7FDD] = (n >> 8) as u8; r }` (LoROM 32 Kio avec 8 Kio de SRAM, chipset 0x02, vecteur RESET 0x8000; si `Snes::new` la refuse, corrige l'en-tete d'apres spec 04). Programmes (code a 0x8000): `PROG_W` = `78 18 FB A9 5A 8F 00 00 70 80 FE` (SEI CLC XCE LDA #$5A STA $700000 BRA -2) ; `PROG_R` = `78 18 FB AF 00 00 70 1A 8F 01 00 70 80 FE` (LDA $700000 ; INC A ; STA $700001 ; BRA -2). Dossier temporaire de test: `let dir = std::env::temp_dir().join(format!("puce16_<id>_{}", std::process::id()))` cree puis supprime a la fin du test.

## 6. Fichiers

- Ouverture: `rfd` (filtres `.sfc`, `.smc`, `.swc`, `.fig`, `.zip`). Un `.zip` (crate `zip`) : prendre la premiere entree dont l'extension est une des quatre precedentes.
- **SRAM**: `<dossier de la ROM>/<nom sans extension>.srm`, octets bruts de `Snes::sram()`. Chargee a l'ouverture de la ROM (`load_sram`) ; sauvee toutes les 5 s si le contenu a change, a la fermeture de la ROM et a la sortie ; ecriture atomique (ecrire `.srm.tmp` puis renommer). Pas de SRAM (`None`) -> aucun fichier.
- **Save states**: `<dossier de la ROM>/<nom>.<slot>.p16s`, slot 0..9. Contenu: en-tete `b"P16S"` + `u16` version du conteneur (1) + `u64` hash FNV-64 des octets de la ROM tels que charges (apres extraction d'un `.zip`, avant toute normalisation du core) + `u8` region, puis le blob `Snes::save_state()`. Au chargement: refuser (message) si magie, version ou hash ROM different.
- **Config**: `config.json` dans `%APPDATA%\Puce16\` (Windows) ; a defaut `$HOME/.config/puce16/`. JSON: `scale, ratio, filter, volume, muted, fullscreen, keymap, pad_map, recent_roms (max 8), last_dir, block_opposite_dirs`. Fichier absent ou invalide -> valeurs par defaut (jamais de plantage).
- Capture d'ecran F2: `<nom>_<n>.ppm` dans le dossier de la ROM (n = premier numero libre).

## Tests
Tous les tests sont prefixes par `e08_21_`.

- `e08_21_sync_due` : `SramSync::new(t0)` : `due(t0 + 4s)` faux ; `due(t0 + 5s)` vrai ; ensuite `due(t0 + 6s)` faux (le dernier controle est a t0+5s) ; `due(t0 + 10s)` vrai.
- `e08_21_sync_changed` : `changed(&[1])` vrai (rien de sauve) ; apres `mark_saved(&[1])` : faux ; `changed(&[2])` vrai ; `reset(now, Some(&[7]))` puis `changed(&[7])` faux.
- `e08_21_flush_writes_file` : dossier temporaire, ROM `sram_rom(PROG_W)` ecrite dans `dir/game.sfc` ; `spawn_with_audio(Ntsc,true,None)` ; `SetRomPath(dir/game.sfc)` ; `LoadRom(rom, "game.sfc")` ; attendre 300 ms (le programme ecrit 0x5A en SRAM) ; `FlushSram` : `Event::SramSaved` recu (timeout 2 s) ; `dir/game.srm` existe, taille 8192, octet 0 == 0x5A.
- `e08_21_sram_loaded_on_open` : suite du test precedent : nouveau thread, ROM `sram_rom(PROG_R)` au meme chemin `game.sfc` ; apres `LoadRom` + 300 ms + `FlushSram` : `game.srm` octet 0 == 0x5A (conserve du fichier) et octet 1 == 0x5B (le programme a lu 0x5A et ecrit +1) : preuve du chargement.
- `e08_21_quit_flushes` : meme montage que `flush_writes_file` mais sans `FlushSram` : `quit()` du handle produit le fichier `.srm`.
- `e08_21_no_sram_no_file` : ROM `tiny_rom()` : apres `LoadRom` + `FlushSram` + `quit`, aucun fichier `.srm` n'existe dans le dossier.
- `e08_21_unchanged_not_rewritten` : apres un premier `FlushSram` (fichier ecrit), supprimer le fichier a la main, `FlushSram` de nouveau (SRAM inchangee) : le fichier n'est PAS recree.
