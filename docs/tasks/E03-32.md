# E03-32 - bus/cycle.rs: execution du DMA general (apres le cycle suivant MDMAEN)
Epopee: E03 | Type: code | Dependances: E03-31 | Taille estimee: ~70 lignes

## Contexte
Le DMA demarre APRES le cycle qui suit l'ecriture de MDMAEN (en pratique apres la lecture de l'opcode suivant, spec 03 section 3.1).
`write_inner` a deja pose `pending_dma = v` et `dma_wait = true`. Execution strictement sequentielle (D-020): cette tache suppose que toutes les precedentes sont terminees. Ne modifie QUE les fichiers de 'Write only in'.

## Specification
Dans `end_cycle`:
```rust
if self.pending_dma != 0 {
    if self.dma_wait { self.dma_wait = false; }                 // cycle de l'ecriture MDMAEN: on arme seulement
    else {
        let m = self.pending_dma; self.pending_dma = 0;
        let mut d = std::mem::take(&mut self.dma);
        d.run_general(self, m);                                 // utilise l'impl DmaBus de SysBus
        self.dma = d;
    }
}
```
Pendant `run_general`, `self.dma` est un `Dma::default()` temporaire: c'est voulu (le moteur travaille sur `d`). Les ecritures CPU ne peuvent pas avoir lieu pendant ce temps. Dans les tests: `mod common; use common::*;` puis `fn mk(code: &[u8]) -> SysBus { SysBus::new(Cart::from_bytes(&make_rom(code, Map::LoRom)).unwrap(), Region::Ntsc) }` (imports: `puce16_core::bus::SysBus`, `puce16_core::cart::Cart`, `puce16_core::Region`).

### 2.1 Cycle CPU (impl Bus pour SysBus)
```
fn read(addr):   begin_cycle(); advance(access_clocks(addr, memsel)); v = read_inner(addr); mdr = v (sauf registres a open bus partiel, voir read_inner); end_cycle(); v
fn write(addr,v): begin_cycle(); advance(access_clocks(..)); mdr = v; write_inner(addr, v); end_cycle()
fn idle():       begin_cycle(); advance(6); end_cycle()
begin_cycle: (1) rafraichissement DRAM (3.3 de 02): si !refreshed_this_line et (master - line_start) >= DRAM_REFRESH_HCLOCK: advance(40); refreshed_this_line = true
```

## 4. DMA general: temps (decisions provisoires, spec 03 section 3.1)
`run_general(bus, mask)`: `bus.elapse(align8)` ou `align8` amene `master` au multiple de 8 clocks suivant (`(8 - master % 8) % 8`); `bus.elapse(8)` surcout de depart; par canal actif (bit de `mask`, ordre 0..7): `bus.elapse(8)`; par octet transfere: `bus.elapse(8)` PUIS la copie.
Un canal dont `das == 0` au depart transfere 65536 octets. Apres le canal `das = 0`, `a1t` avance selon le mode.

## Tests
Tous les tests sont prefixes par `e03_32_`.

- `e03_32_dma_after_next_cycle` : ROM: `mk(...)` dont le code est l'identite d'octets: construis la ROM par `make_rom(&data_block, LoRom)` avec data_block[0x200..0x204]=[0x11,0x22,0x33,0x44] (vec de 0x210 octets, donnees a l'offset 0x200 -> adresse 0x8200). `bus.write_inner(0x002181,0x00)`, `0x002182 <- 0x02` (WMADD=0x200). Canal 0 via `bus.dma.write`: 0x4300<-0x00, 0x4301<-0x80, 0x4302<-0x00, 0x4303<-0x82, 0x4304<-0x00, 0x4305<-0x04, 0x4306<-0x00. `Bus::write(&mut bus, 0x00420B, 0x01)` : master==6, `bus.pending_dma()==1`, `wram.read(0x200)==0x55` (rien copie encore).
- `e03_32_dma_runs_on_next_cycle` : suite: `Bus::read(&mut bus, 0x008000)`: apres cet appel `pending_dma()==0`, `wram.read(0x200..0x204)==[0x11,0x22,0x33,0x44]`, `wram.addr==0x204`, `dma.ch[0].das==0`, `dma.ch[0].a1t==0x8204`, et `bus.master==64` (6 + 8 -> 14 ; alignement +2 -> 16 ; +8 depart -> 24 ; +8 canal -> 32 ; 4 octets x 8 -> 64). `ppu.dot()==16`.
- `e03_32_dma_regs_restored` : apres le DMA, `bus.dma` est bien le vrai objet (`bus.dma.ch[0].dmap==0x00` ecrit par le test, `bus.dma.ch[3].dmap==0xFF`).
- `e03_32_mdmaen_zero` : `Bus::write(&mut bus, 0x00420B, 0x00)` puis une lecture : aucun transfert, master==6+8.
- `e03_32_two_channels_order` : mask 0x06 (canaux 1 et 2) : les canaux s'executent dans l'ordre 1 puis 2 : canal 1 copie 2 octets vers WMADD=0x300, canal 2 copie 2 octets (WMADD continue) ; WRAM[0x300..0x304] = les 4 octets dans l'ordre.
- `e03_32_no_double_run` : apres le DMA, une 2eme lecture ne relance rien: `master` n'augmente que de 8.
- `e03_32_write_then_idle` : meme sequence avec `Bus::idle` comme cycle suivant : le DMA part aussi apres l'idle (end_cycle de l'idle).
- `e03_32_rewrite_before_start` : deux ecritures MDMAEN successives (0x01 puis 0x02) avant le 1er cycle suivant: seul le canal 1 (valeur 0x02) s'execute ; mais `dma_wait` est re-arme par la 2eme ecriture : le DMA part apres le cycle suivant la 2eme.
