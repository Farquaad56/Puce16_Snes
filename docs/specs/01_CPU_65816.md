# SPEC 01 - CPU 65C816 (Ricoh 5A22 cote coeur)

Source: connaissance 65816 + wiki SNESdev. **Oracle de validation: SingleStepTests/65816 (JSON, cycles de bus).**
Quand ce document et les tests JSON divergent, les tests JSON gagnent: poser une question (02_QA_PROTOCOL.md), ne pas "arranger".

## 1. Registres

| Reg | Taille | Note |
|---|---|---|
| A (C) | 16 | Accumulateur; l'octet haut (B) est conserve meme si M=1 |
| X, Y | 16 | Si flag X=1: octet haut = 0 (force a chaque passage en X=1) |
| S | 16 | Mode emulation: octet haut = $01 |
| D | 16 | Direct page |
| DB (DBR) | 8 | Banque de donnees |
| PB (PBR) | 8 | Banque de programme |
| PC | 16 | Dans la banque PB (le PC ne traverse pas la banque: wrap 16 bits) |
| P | 8 | `N V M X D I Z C` (bit7..bit0) |
| E | 1 | Mode emulation (echange avec C par XCE) |

Flags: N=bit7 V=bit6 M=bit5 (acc 8 bits si 1) X=bit4 (index 8 bits si 1) D=bit3 (decimal) I=bit2 (IRQ off) Z=bit1 C=bit0.
En mode emulation: M=1 et X=1 forces; dans l'octet P pousse sur la pile, bit5=1 et bit4 = B (1 pour BRK/COP, 0 pour IRQ/NMI).

Etat apres RESET: E=1, M=1, X=1, D(decimal)=0, I=1, S=$01xx (valeur exacte de l'octet bas: UNKNOWN - to confirm, les tests ROM
n'en dependent pas), DB=$00, PB=$00, D(direct)=$0000, PC = mot lu en $00:FFFC. Les valeurs de A/X/Y au power-on: UNKNOWN - to confirm
(utiliser 0 par defaut, et un test ne doit pas en dependre).

## 2. Modele de cycle (obligatoire)

Chaque instruction est une suite de **cycles de bus**. Types: `R(addr)` lecture, `W(addr,val)` ecriture, `IO` cycle interne.
Chaque cycle est emis par `bus.read/write/idle` qui avance l'horloge maitre (6/8/12 clocks, voir 02_BUS_TIMING.md).
Le nombre et l'ORDRE des cycles doivent correspondre exactement aux tests JSON (adresse + valeur de chaque cycle).

Notation: `PC` = PB:PC; `pc++` apres chaque lecture d'octet de programme. `DL` = octet bas de D. `d16` = M=0 (acc 16 bits) ou X=0 pour l'index.
`W16(addr)` = ecriture octet bas a addr puis octet haut a addr+1 (sauf RMW: haut d'abord, voir 3.3).

## 3. Cycles par mode d'adressage

Les cycles ci-dessous sont **apres** le cycle 1 (fetch de l'opcode) sauf indication. Total = nombre de cycles de l'instruction.

### 3.1 Calcul d'adresse (partie commune)

| Mode | Cycles (apres opcode) | Notes |
|---|---|---|
| imm | `R(pc++)` [+ `R(pc++)` octet haut si 16 bits] | total 2 (+1) |
| acc / implied | `IO` | total 2 |
| d | `R(pc++)=dl`; [`IO` si DL!=0]; adresse = D + dl (bank 0) | |
| d,x / d,y | `R(pc++)`; [`IO` si DL!=0]; `IO`; adresse = D + dl + idx | wrap: voir 4 |
| a | `R(pc++)=aal`; `R(pc++)=aah`; adresse = DB:aah:aal | |
| a,x / a,y | `R(pc++)`; `R(pc++)`; [`IO`: toujours pour ecriture/RMW; pour lecture seulement si franchissement de page OU index 16 bits (X=0)]; adresse = DB:a + idx (carry vers la banque) | |
| al | `R(pc++)`x3 (aal, aah, bank) | |
| al,x | `R(pc++)`x3; adresse = bank:a + X (24 bits) | pas de cycle supplementaire |
| (d) | `R(pc++)`; [`IO` DL]; `R(D+dl)`=lo; `R(D+dl+1)`=hi; adresse = DB:ptr | |
| [d] | idem + `R(D+dl+2)`=bank; adresse = bank:ptr | |
| (d,x) | `R(pc++)`; [`IO` DL]; `IO`; ptr lu en D+dl+X (lo, hi); adresse = DB:ptr | |
| (d),y | `R(pc++)`; [`IO` DL]; ptr lu (lo, hi); [`IO`: toujours ecriture; lecture si page franchie OU X=0]; adresse = DB:ptr + Y | |
| [d],y | `R(pc++)`; [`IO` DL]; ptr 24 bits lu; adresse = bank:ptr + Y (pas de cycle sup.) | |
| d,s | `R(pc++)=sr`; `IO`; adresse = S + sr (bank 0) | |
| (d,s),y | `R(pc++)=sr`; `IO`; ptr lu en S+sr (lo, hi); `IO`; adresse = DB:ptr + Y | |

### 3.2 Acces donnee

- Lecture: apres le calcul d'adresse, `R(addr)` octet bas, puis `R(addr+1)` octet haut si 16 bits.
- Ecriture: `W(addr, lo)` puis `W(addr+1, hi)` si 16 bits.
- L'adresse +1 d'une donnee 16 bits traverse les banques (24 bits) pour les modes a/al/a,x/al,x/a,y/(d)/[d]/(d),y ...;
  pour les modes direct page (d, d,x, d,y) l'octet haut est a (D + offset + 1) avec les regles de wrap de la section 4.
  `UNKNOWN - to confirm` cas par cas: laisser les tests JSON trancher.

### 3.3 Instructions lecture-modification-ecriture (ASL LSR ROL ROR INC DEC TSB TRB sur memoire)

`R(addr)`=lo; [`R(addr+1)`=hi si 16 bits]; `IO` (cycle de modification); [`W(addr+1)`=hi' si 16 bits]; `W(addr)`=lo'.
**En 16 bits l'ecriture se fait octet HAUT d'abord, puis octet bas.** (Les JSON le confirment: a verifier au premier test.)
Les formes accumulateur (ASL A ...) sont implied: `IO` seul.

Totaux utiles (8 bits): `LDA #`=2, `LDA d`=3(+DL), `LDA a`=4, `LDA al`=5, `LDA d,x`=4(+DL), `LDA a,x`=4(+1 si page), `LDA (d)`=5(+DL),
`LDA (d),y`=5(+DL,+1 page), `LDA [d]`=6(+DL), `LDA (d,x)`=6(+DL), `LDA d,s`=4, `LDA (d,s),y`=7, `STA a,x`=5, `STA (d),y`=6, `ASL a`=6, `ASL a,x`=7, `ASL d`=5(+DL). +1 par octet supplementaire en 16 bits (+2 pour les RMW).

## 4. Regles de wrap de la direct page

- Mode natif (E=0), ou E=1 avec DL != 0: adresse direct = (D + dl [+ idx]) & $FFFF en banque 0 (wrap sur 64 KiB de la banque 0).
- E=1 et DL == 0: les modes **d,x d,y (d) (d,x) (d),y** et la lecture des pointeurs `(d)`... bouclent **dans la page** D (l'octet haut de l'adresse reste = D.h).
  Les modes `[d]` et `[d],y` NE bouclent PAS en page (ils sont "nouveaux" instructions) mais bouclent dans la banque 0.
- La pile en mode emulation: les instructions "anciennes" (PHA PLA PHP PLP JSR RTS RTI BRK interruptions emu ...) font boucler S dans la page 1 ($0100-$01FF).
  Les instructions "nouvelles" (PEA PEI PER PHD PLD PHB PLB PHK JSL RTL JSR (a,x) et modes d,s / (d,s),y) traitent S comme 16 bits et ne bouclent pas en page 1 en emulation;
  apres l'instruction, S.h est reforce a $01 si E=1. `UNKNOWN - to confirm` instruction par instruction: tests JSON = oracle.

### 5.1 Taille des operandes
- `#` immediat: 1 octet si M=1 (ou X=1 pour LDX LDY CPX CPY), 2 octets sinon.
- `imm8` (REP, SEP) et `wdm`, `brk`, `cop` (octet de signature): toujours 1 octet.
- Instructions utilisant M: ORA AND EOR ADC SBC CMP BIT LDA STA STZ + RMW memoire + PHA PLA + transferts vers A.
- Instructions utilisant X: LDX LDY STX STY CPX CPY INX INY DEX DEY PHX PHY PLX PLY.

### 5.2 Flags
- N/Z: mis par LDA/LDX/LDY, ADC SBC AND ORA EOR CMP CPX CPY, INC DEC (y compris INX INY DEX DEY), ASL LSR ROL ROR, PLA PLX PLY PLB PLD, transferts (TAX TAY TXA TYA TSX TXY TYX TCD TDC TCS? **TCS ne modifie aucun flag**; TSC et TDC mettent N/Z), XBA (N/Z sur l'octet bas de A apres echange).
- STA STX STY STZ, PHx, TXS, TCS, TSB/TRB (seul Z), BIT: BIT `#` ne modifie que Z; BIT mem modifie N=bit7 (ou bit15), V=bit6 (ou bit14), Z=(A & m)==0.
- TSB: Z=(A & m)==0; m = m | A. TRB: Z=(A & m)==0; m = m & ~A.
- CMP/CPX/CPY: calcul a - m en binaire: C = (a >= m), Z, N sur le resultat; V inchange.
- Flags de decalage: ASL C=bit sorti (7 ou 15); LSR C=bit0; ROL/ROR passent par C.
- CLC SEC CLI SEI CLD SED CLV: mettent/effacent le flag. REP: P &= ~imm; SEP: P |= imm (en E=1, M et X restent a 1; si X devient 1: X.h=Y.h=0).
- XCE: echange C et E. Apres: si E=1: M=X=1, X.h=Y.h=0, S.h=$01.
- PLP: si E=1, M=X=1 forces; si X devient 1: X.h=Y.h=0.
- TAX/TAY/etc: copie 16 bits si X=0 (ou M=0 pour TXA/TYA...) ; regle: la taille copiee = taille de la **destination**: TAX/TAY (dest X/Y) selon X; TXA/TYA (dest A) selon M; TSX selon X; TXS: en E=1 seulement octet bas (S.h=$01), en E=0 16 bits; TCS 16 bits (E=1: S.h=$01); TSC 16 bits; TCD/TDC 16 bits toujours; TXY/TYX selon X.
- XBA: echange octets de A (16 bits toujours), 3 cycles.
- Arithmetique decimale: voir 6.

## 6. ADC / SBC

Binaire (D=0): `r = A + m + C`; C = depassement; V = `~(A ^ m) & (A ^ r) & signbit`; N,Z sur r tronque.
SBC binaire: meme formule avec `m = ~m` (complement), i.e. `A + ~m + C`.

Decimal (D=1) - algorithme de reference de depart (a valider par les tests JSON; ne PAS modifier au hasard):

```
ADC 8 bits:
  r = (A & 0x0F) + (m & 0x0F) + C
  if r > 0x09: r += 0x06
  C = r > 0x0F
  r = (A & 0xF0) + (m & 0xF0) + (C << 4) + (r & 0x0F)
  V = (~(A ^ m) & (A ^ r) & 0x80) != 0
  if r > 0x9F: r += 0x60
  C = r > 0xFF ; A.l = r & 0xFF ; N,Z sur A.l
ADC 16 bits: meme principe sur 4 quartets (masques 0x000F,0x00F0,0x0F00,0xF000; seuils 0x0009,0x009F,0x09FF,0x9FFF; corrections 0x6,0x60,0x600,0x6000), V calcule avant la correction du dernier quartet.

SBC 8 bits (m' = m ^ 0xFF):
  r = (A & 0x0F) + (m' & 0x0F) + C
  if r <= 0x0F: r -= 0x06
  C = r > 0x0F
  r = (A & 0xF0) + (m' & 0xF0) + (C << 4) + (r & 0x0F)
  V = (~(A ^ m') & (A ^ r) & 0x80) != 0
  if r <= 0xFF: r -= 0x60
  C = r > 0xFF ; A.l = r & 0xFF ; N,Z sur A.l
SBC 16 bits: meme principe sur 4 quartets.
```

## 7. Controle de flux (cycles exacts, apres le cycle opcode)

| Instruction | Cycles |
|---|---|
| Bxx (rel) | `R(pc++)=off`; si pris: `IO`; en E=1 si franchissement de page (pc apres l'offset vs cible): `IO` supplementaire. Non pris: 2 total. Cible = pc(apres operande) + off signe (wrap 16 bits dans la banque). |
| BRA | idem, toujours pris |
| BRL | `R(pc++)`=lo; `R(pc++)`=hi; `IO`; PC += off16 (total 4) |
| JMP a | `R(pc++)`x2; PC=a (total 3) |
| JMP al (JML) | `R(pc++)`x3; PB=bank, PC=a (total 4) |
| JMP (a) | `R(pc++)`x2; `R(0:a)`=PCL; `R(0:a+1)`=PCH (a+1 wrap 16 bits en banque 0) (total 5) |
| JML [a] | + `R(0:a+2)`=PB (total 6) |
| JMP (a,x) | `R(pc++)`x2; `IO`; `R(PB:a+X)`=PCL; `R(PB:a+X+1)`=PCH (total 6; wrap dans PB) |
| JSR a | `R(pc++)`x2; `IO`; push PCH; push PCL; PC=a (total 6). PC pousse = adresse du DERNIER octet de l'instruction (PC-1). |
| JSR (a,x) | `R(pc++)`=aal; push PCH; push PCL; `R(pc++)`=aah; `IO`; `R(PB:a+X)`x2 (total 8) |
| JSL | `R(pc++)`x2 (aal,aah); push PB; `IO`; `R(pc++)`=bank; push PCH; push PCL (total 8); PB=bank |
| RTS | `IO`; `IO`; pull PCL; pull PCH; `IO`; PC = pulled + 1 (total 6) |
| RTL | `IO`; `IO`; pull PCL; PCH; PB (total 6); PC = pulled + 1 |
| RTI | `IO`; `IO`; pull P; pull PCL; pull PCH; [pull PB si E=0] (total 6 en E=1, 7 en E=0); PC non incremente |
| BRK / COP | `R(pc++)`=signature; [push PB si E=0]; push PCH; push PCL; push P; `R(vec)`lo; `R(vec+1)`hi (total 7 en E=1, 8 en E=0). Apres: I=1, D=0, PB=0. P pousse: B=1 en E=1. |
| WAI | `IO`; `IO` puis le CPU s'arrete jusqu'a une interruption (voir 8) |
| STP | `IO`; `IO` puis arret definitif jusqu'a RESET |
| WDM | `R(pc++)`=signature ignoree (total 2) |
| NOP | `IO` (total 2) |
| MVN/MVP | `R(pc++)`=dst bank; `R(pc++)`=src bank; DB=dst bank; `R(src:X)`; `W(dst:Y)`; `IO`; `IO`; X,Y += 1 (MVN) ou -= 1 (MVP) (si X=1 8 bits sinon 16); A -= 1 (16 bits toujours); si A != $FFFF: PC -= 3 (l'instruction recommence). Total 7 par octet. |

Vecteurs (bank $00): natif COP $FFE4, BRK $FFE6, ABORT $FFE8, NMI $FFEA, (reserve $FFEC), IRQ $FFEE;
emulation COP $FFF4, (reserve $FFF6), ABORT $FFF8, NMI $FFFA, RESET $FFFC, IRQ/BRK $FFFE.

## 8. Interruptions (NMI, IRQ, RESET)

Sequence materielle (hors BRK/COP): `R(pc)` (opcode fantome, ignore); `IO`; [push PB si E=0]; push PCH; push PCL; push P (B=0 en E=1); `R(vec)`lo; `R(vec+1)`hi (7 cycles E=1, 8 cycles E=0). Puis I=1, D=0, PB=0.
- IRQ est ignore si I=1. NMI jamais masquable.
- Echantillonnage: les lignes NMI/IRQ sont examinees a la **fin de l'instruction** (avant le fetch du prochain opcode, au dernier cycle de l'instruction courante). `UNKNOWN - to confirm` le decalage exact en master clocks entre l'evenement (VBlank, H/V match) et la prise en compte: tests ROM (specs/06_TEST_ROMS.md) trancheront. Valeur de depart: l'IRQ/NMI declenchee pendant le dernier cycle n'est prise qu'apres l'instruction suivante.
- NMI: detection de front montant de la ligne (RDNMI flag AND NMITIMEN bit7). Une ecriture qui active NMITIMEN.7 pendant que le flag RDNMI est deja a 1 genere un NMI (front).
- WAI: le CPU attend; si IRQ (I=1) se produit: reprend a l'instruction suivante sans prendre l'interruption; si I=0 ou NMI: prend l'interruption.
- RESET: lit $FFFC (E=1). Duree/alignement des premiers cycles: `UNKNOWN - to confirm` (voir 02_BUS_TIMING.md).
- ABORT: non utilise sur SNES (ligne non cablee); ne pas implementer.

## 9. Interface logicielle recommandee (pour decouper en taches)

```rust
pub struct Cpu { pub a: u16, pub x: u16, pub y: u16, pub s: u16, pub d: u16, pub db: u8, pub pb: u8, pub pc: u16, pub p: u8, pub e: bool, pub halted: bool /* STP */, pub waiting: bool /* WAI */ }
pub trait Bus { fn read(&mut self, addr: u32) -> u8; fn write(&mut self, addr: u32, v: u8); fn idle(&mut self); }
impl Cpu { pub fn step<B: Bus>(&mut self, bus: &mut B); }   // execute une instruction complete (ou une sequence d'interruption)
```
Le trait `Bus` de test enregistre `(addr, valeur, type)` de chaque cycle pour comparer aux JSON SingleStepTests.
Le Bus reel de `Snes` implemente ce trait en avancant l'horloge maitre (voir 02_BUS_TIMING.md).
